# 05 · 生产与端口系统

> 上一篇：[04-传送带系统](04-传送带系统.md) ｜ 下一篇：[06-建造与交互系统](06-建造与交互系统.md)

生产系统 = **MachineSystem（编排器）+ machine/ 纯函数 ops 层 + PortGeometry（几何单一事实源）**。设计原则（DD-011）：所有运行时状态都在 `BuildingComp`，ops 层无状态。

## 1. 全链路总览

```
传送带 → [IntakeOps 吸入] → 端口 → [BufferOps 槽位] → [ProductionOps 生产] → [BufferOps 槽位] → [OutputOps 注出] → 端口 → 传送带
                    └────────────── 仓库口整条链由 [DepotOps] 替代（无限源/无限汇）──────────────┘
```

每 Tick（20 TPS）MachineSystem 对每台设备按固定顺序执行（A8 §7）：

```
update(world, dt):
  beltAt = buildBeltCellIndex(world)         // 每 Tick 一份传送带格索引（共享给各 ops）
  for 每台 BuildingComp 设备:
    paused?  → releaseEnteringItems() 后跳过  // 唯一动作：放行已预约物品（否则卡死在半格深处）
    depot?   → updateDepot()                  // 仓库口分支（T2.12）
    常规设备: 1. updateInternal()   内部生产状态
              2. absorbBeltInputs() 输入物流（吸入不依赖配方）
              3. emitBeltOutputs()  输出物流
```

## 2. 生产状态机（updateInternal）

状态：`idle ↔ working ↔ blocked`（另有正交布尔 `paused`）。

| 阶段 | 逻辑 |
|---|---|
| working 计时 | `elapsed += 50ms`；`progress = min(elapsed / recipe.time, 1.0)` |
| 计时完成 → **原子结算** | `planRecipeInputs` 为 null（原料被外部调试钩子取走）→ `cancel` 清计时；`planOutputs` 为 null（输出槽满）→ `state='blocked'`，**原料不扣**，每 Tick 重试；两计划均成 → `settleProduction`（扣输入 + 落产物同 Tick 原子完成） |
| 续启 / 回 idle | 无计时器时 `findMatchingRecipe` → 命中即启动计时（**启动不扣原料**，A8 §3.1）+ `start` 事件；无可匹配 → idle |

事件（`ProductionEvent`）：`start / settle / blocked / cancel / input / output / depot-output / depot-input`，经 `machineSystem.onEvent` 转发 console，同时存入 `recentEvents` 环形缓冲（上限 400）供 `__game.productionLog()` 覆盘。

**暂停语义**：不推进计时（进度保留）、不吸入、不输出；唯一动作是放行已预约(entering)物品——预约时槽位已 +1，不放行会让物品永远卡在端口半格深处。

## 3. 端口几何 PortGeometry.ts（109 行）——单一事实来源

端口世界格/朝向的**唯一计算入口**（MachineSystem 吸入/出货、传送带创建吸附、堵塞分类、渲染高亮四处共用，T2.16 下沉至此防口径发散）：

| 导出 | 语义 |
|---|---|
| `inputPortCells(gx, gy, def, direction)` | `PortCell[]`：过滤 `def.ports` 中 `type==='input'`，每项 `{port, x, y, outward}` |
| `outputPortCells(...)` | 对称（`type==='output'`），在 OutputOps 中 |
| `rotatePort(port, footprint, direction)` | 端口格偏移旋转：90° → `{dx: h−1−dy, dy: dx}`，180° → 对角，270° → `{dx: dy, dy: w−1−dx}` |
| `portOutwardBase(port, footprint)` | 默认朝外方向按边缘判定：顶行（含单行占地）→ 270 朝上；底行 → 90；左列 → 180；右列 → 0 |
| `rotateDirection(base, direction)` | `(base + direction) % 360` |

### 端口类型

| 类型 | 处理模块 | 语义 |
|---|---|---|
| `input` | IntakeOps | 预约制吸入进 `bufferInput`，受轮询/槽位/类型/容量约束 |
| `output` | OutputOps | 从 `bufferOutput` 注入接收带，受轮询队列/相位窗口/一格一物品约束 |
| `liquid` | （Phase 3b） | 尚无几何路径；判定已预留：液体物品不作固体槽匹配、液体产物不占槽 |
| 仓库口（`depot: 'unload'/'load'`） | DepotOps | 端口仍标 output/input 类型，但走无限源/汇分支 |

### 连接判定（三处同口径）

- **输入** `findFeederBelt(world, beltAt, portCell)`：**只认端口朝向侧一格**（`端口格 + directionVector(outward)`）且段方向 === 逆朝向；侧向横穿不算连接（2026-09-02 用户拍板）。
- **输出** `findReceiverBelt(world, beltAt, portCell)`：4 邻扫描，段的**入口朝向**（`entryDir ?? direction`）指向端口格。

## 4. IntakeOps.ts（166 行）——带→设备吸入（预约制两阶段）

物品"进入设备"分两步（2026-08-17 选型）：

```
阶段1 预约: 物品走到门口 progress ≥ 0.5（供给格中心，PORT_ENTER_PROGRESS = BeltSystem.STOP_MAX）
           → tryAcceptItem 通过 → 输入槽 count+1（当场占用）+ 物品标记 entering=true（不移除）
阶段2 放行: BeltSystem 把 entering 物品推进到 1.5（端口格中心，PORT_RELEASE_PROGRESS = PORT_ENTER_DONE）
           → releaseArrivedItems() 移除，视觉消失在端口格中心
```

预约制防多端口争抢同一件物品；`entering` 物品不计入带上的阻挡。其他导出：`collectInputPortCells(world)`（全场输入口索引，含仓库存货口——它们是合法带终点，传送带预览吸附与吸入共用）、`buildBeltCellIndex(world)`（格→段实体索引）、`doorHeadItem(seg)`（门口非 entering 队首）。

## 5. 输入缓冲搬运（absorbBeltInputs，MachineSystem 内）

四段式：

1. **放行扫描**：全部输入口执行 `releaseArrivedItems`（与轮询指针解耦，被跳过的口也要放行）；
2. **先到排名戳记**：每口**第一次**有队首到门口 → `comp.inputArrivalRank[i] = simTick`（一次性；满载/类型不符也戳——"到门口即算先到"）；
3. **满载冻结检测**：全槽满只冻结新预约，不 early-return；
4. **预约轮询**：走访序 = `inputArrivalRank` 升序（**先到先得**；起点 = `inputPollIndex` 在该序中的位置）；每口至多预约 1 件，成功或跳过指针都前进；未满载时每 Tick 走访全部口（同 Tick 可多口齐吸）；补满即 break（冻结在排名序下一口，不重置）。

## 6. 输出物流（emitBeltOutputs，MachineSystem 内）

- **相位窗口全局闸门**：`BeltSystem.beltPhase > STOP_MAX(0.5)` 时直接 return 且不动队列——输出只在每 Tick 前半窗口进行（全局节奏，非端口故障）；
- **活跃队列轮转**（`outputPollQueue`）：按队列序走访——出货成功 → 移队尾（1→2→3→1…轮转）；失败（无接收带/满带）→ 移出队列进堵塞集；
- **堵塞恢复探测**：堵塞端口每 Tick 真实尝试出货，成功 → **追加队尾不插队**（A8 §4.2）；
- `tryEmitToBelt`：取第一个非空输出槽 → 目标段必须为**空**（一格一物品）→ 注入段首 `progress=0` → 扣槽。

## 7. ProductionOps.ts（169 行）——生产纯函数

| 导出 | 语义 |
|---|---|
| `findMatchingRecipe(recipes, slots, registry)` | 取列表序（CSV 顺序）第一条可匹配配方 |
| `planRecipeInputs(recipe, slots, registry)` | 逐原料组（`+` 和关系）在 `alternatives`（`/` 或关系）中按序找第一个可满足备选；`remaining[]` 跨组递减防同槽超扣；液体物品不作固体槽匹配 |
| `planOutputs(outputs, slots, capacity, registry)` | 固体产物先同类合堆、再空槽锁定；**液体产物跳过不占槽**；任一固体产物无处安放 → null（触发 blocked） |
| `settleProduction(comp, inPlan, outPlan)` | 原子结算：扣输入（扣到 0 解锁）→ 写输出槽 → 清计时器。不重复校验 |
| `isLiquidItem(itemId, registry)` | tags 含 `'liquid'` |

## 8. BufferOps.ts（70 行）——槽位原语

`createBufferSlots(n)`（n 个空槽）、`tryAcceptItem(slots, itemId, capacity)`（先同类合堆、再空槽锁定新类型、全不接受 → false 物品留带）、`consumeFromSlot(slot, n)`（扣到 0 自动解锁）、`formatBufferSlots`（调试格式化）。

## 9. DepotOps.ts（58 行）——仓库口（无限源/汇）

- `DEPOT_SOURCE_ITEM = 'originium_ore'`：取货口固定放出源矿（T2.15 弹窗后再改配置驱动）；
- `emitSourceToBelt(seg)`：`tryEmitToBelt` 的无槽位变体——凭空注入空段段首（无限源）；
- `tryAbsorbHeadItemSink(seg)`：`tryAbsorbHeadItem` 的无条件变体——到门口(0.5)即标 entering（无限汇，永不堵塞）。
- 状态恒 idle、无缓冲区、无配方、无轮询公平性（按定义序）。

## 10. PortStatusOps.ts（121 行）——端口状态只读判定

`portStatuses(world, handle, comp, def) → { input: PortStatus[], output: PortStatus[] }`，每项 `{port, x, y, connected, blocked}`：

- `connected` = 连接判定成立（findFeederBelt / findReceiverBelt 命中）；
- `blocked` = 已连接 && !paused && `seg.blocked === true`（与传送带链级堵塞同源）。

消费方：`PortHighlightRenderer`（连接黄 #FFEF00 / 堵塞红渐变）与调试钩子 `__game.portStatus()`——**渲染与断言共享同一判定**，防口径漂移。

## 11. LogisticsDebug.ts（50 行）——临时调试日志

`logisticsDebug` 单例（环形 400 条），在吸入/进门/冻结/恢复等跳变点记录，`__game.logisticsDebug(false)` 可关。问题定位后整模块退役（当前默认开启）。
