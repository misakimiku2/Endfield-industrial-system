## 1. 任务回顾

### 1.1 目标
实现从设备输出端或已有断头传送带发起的传送带绘制：基础创建、延长、删除，以及方向约束和防穿模检查。

### 1.2 范围（分两阶段）
- **阶段 1：基础创建与预览** — 按 `E` 进入/退出创建模式，高亮输出端口/断头末端，点击起点→移动鼠标显示蓝色预览路径（动量 L 形 + BFS 绕障）→点击目标空格落盘为黄色传送带，右键/ESC/E 退出
- **阶段 2：链管理与延长** — 每段独立 ECS Entity（`chainId`/`direction`/`isCorner`/`isTail`），从断头末端继续延长继承 `chainId`，方向约束（禁止反向、允许同向/90° 转弯），选中任意段高亮整链，`Delete` 删整链、`Shift+Delete` 删单段（下游重拆为断头链）

### 1.3 明确排除（后续任务）
- 截断已有传送带并创建分支、合并孤立传送带、物流桥作为合法交叉点、物品移动动画与 pointer 流动（T2.1）

## 3. 关键设计决策与实现细节

### 3.1 状态机设计（BeltCreationSystem）

```
idle ──E──→ hover ──左键点起点──→ preview ──左键添加中继锚点──→ preview（继续）
  ↑                                    │
  └───── 右键/ESC/E ───────────────────┘（不落盘直接退出）
```

- **hover 态**：扫描所有合法起点（设备输出端口 + 已有断头传送带末端），鼠标悬停时高亮
- **preview 态**：起点已选定，鼠标移动实时寻路生成预览路径，**左键点击 = 立即落盘当前预览段为真实实体**（多锚点交互：点一次创建一段，以新尾端为起点继续）
- **右键/ESC**：在 preview 态直接退出，**不落盘当前预览**（落盘仅由左键 addWaypoint 触发），符合文档 T2.0 入口规则

### 3.2 双层寻路策略（BeltPathfinding）

**核心思路**：先用「动量 L 形」启发式快速生成路径，若被阻挡则回退到 BFS 网格寻路绕障。

- **动量 L 形 (`calculateMomentumPath`)**：  
  - 有 `startingDirection` 时先沿该方向迈一步（模拟设备端口出口的物理方向约束）  
  - 再按 `verticalFirst` 决定先走竖直腿还是水平腿的 L 形  
  - 旧项目 `belt_direction_utils.dart` 直接移植，保证手感一致  
  - 路径恒含起点格（2026-09-02 修复：不传 `startingDirection` 时旧实现漏掉起点格，破坏「raw[0]=起点」调用方不变量；tail 首段转向启用该分支后暴露）  

- **BFS 兜底 (`findPathBFS`)**：  
  - 4 方向网格，节点记录 `incomingDir` 索引  
  - 非起点节点只允许「同方向、左转 90°、右转 90°」，**禁止 180° 反向**（传送带流向约束）  
  - 起点节点按 `firstStepDirection` / `allowedDirections` 约束首步  
  - 终点格被占用**不作为失败条件**（允许到达被占终点，整条染红由调用方 `checkPathValid` 判定）

- **阻挡判定 (`makeIsBlocked`)**：  
  - 已确认路径格 `fullPath` 阻挡（防自交）  
  - 设备占用格阻挡（`OccupancyMap.canPlace`）  
  - **起点格豁免仅限 port 起点**（端口格本身被设备占用但合法）；**tail 起点不豁免**——起点是原 chain 尾段（已存在的传送带），新路径绝不能穿回它（否则会在原传送带格上创建重叠段，这是 T2.0 重叠 bug 根因）

### 3.3 多锚点交互与落盘机制

**交互流程**：
1. hover 态点击起点 → 进入 preview，`anchors = [起点格]`，`lastAnchorDirection = 起点方向`
2. preview 态移动鼠标 → `refreshPreview()` 实时寻路（lastAnchor → mouseGrid）
3. preview 态左键 → `addWaypoint()`：
   - 取 `previewPath` 中尚未落盘的部分 `newCells`
   - `commitCells(newCells)` 立即创建真实实体（黄色带身 + pointer）
   - 记录锚点：`anchors.push(newCells 末端格)`
   - 更新 `lastAnchorDirection = 新尾段出方向`
   - 基于新锚点立即 `refreshPreview()` 继续延伸
4. 右键/ESC/E → `exitMode()` 清理预览，不落盘

**落盘实体化 (`commitCells`)**：
- 首次落盘确定 `chainId`：tail 起点继承原 `chainId` 并把原 tail `isTail=false`；port 起点新建 `chainId`
- **完整序列（已落盘 `fullPath` + 新段 `newCells`）统一计算方向/转角信息**，保证跨段转角正确
- 已落盘的旧尾格可能因新段而变成转角（直带末端转弯），需重算并更新其组件；tail 起点时 `fullPath` 前缀含原尾格（§3.11），原尾段的直段↔转角互转同样走此分支
- 新段末端标记 `isTail=true`（可继续延长）
- 新段 `segmentIndex` 接续原尾段连续递增（`committedBaseIndex`，§3.11）
- 占用表 `occupy` 每格写入 `'transport_belt'`

### 3.4 路径方向/转角数学（BeltPathGeometry）——三方单一事实来源

**设计原则**：预览、落盘、渲染**三方共用同一套纯函数**，保证「预览 ↔ 落盘 ↔ 渲染」像素级一致。

- `getCellTurnInfo(path, index, incomingDir?, outgoingDir?)`：按路径上下文判断直段/转角、入/出方向、CW/CCW
- `turnInfoFromDirections(incomingDir, outgoingDir)`：直接由方向对计算（预览/落盘已知方向对时用，避免索引推导歧义）
- `beltTextureRotation(dir)`：直段纹理旋转（Transport_Belt_Move.svg 默认朝下）
- `beltCornerTransform(entryDir, exitDir)`：转角变换——CW 按出口方向旋转；CCW = 出口方向反向旋转 + 水平镜像（移植自旧 Flutter `_drawSvgCellAtOrigin`）

**方向索引约定**（与旧项目一致）：`up=0, right=1, down=2, left=3`  
CCW 判定：`(outIdx - inIdx + 4) % 4 === 3`

### 3.5 矢量带身渲染（BeltVectorGeometry + BeltVectorRenderer）——方案 A

**背景**：位图 Sprite 缩小到 `zoom≈0.25` 时，GPU 双线性采样把纹理透明边距插值成半透明渐变，相邻格叠加 → 格子边界出现"接缝/灰线"。

**方案 A**：传送带带身改用 PixiJS **Graphics 矢量绘制**（与旧 Flutter `PictureInfo` 同构），任意缩放由 GPU 按当前变换矩阵重新光栅化，边缘精确、相邻格内容在格子边界连续 → **完全无缝**。

- `drawStraightBelt(g, cellSize, colors, dir?)`：灰壳全高矩形（宽 68.75%）+ 黄带全高矩形（宽 53.13%），居中；支持 `beltGradient`（创建模式终点黄→蓝沿带身方向线性渐变，`FillGradient textureSpace='global'`）
- `drawCornerBelt(g, cellSize, colors)`：四分之一圆环（灰壳外弧 r=14.2875、黄带外弧 r=12.9646、内弧 r=2.6458）+ 内角灰三角（r=3.96875），精确复刻 `Transport_Belt_rotate.svg` 的 `path5/circle5/circle6`；渐变沿黄带外弧（物品路径）分 40 扇环段 lerp
- `BeltVectorRenderer.update(deltaMS)`：每帧 diff 维护每段一个 Graphics（挂 `layer2Building`），形状只在 `segShapeKey`（方向/转角/镜像/选中/堵塞/创建终点）变化时重绘，**堵塞渐变进行中（0<blend<1）每帧重绘**实现黄→红平滑过渡

**染色优先级**：选中态（#B1B1B1/#FFF56A）> 堵塞态（黄 lerp 红 #B10000）> 创建终点态（黄→蓝 #80BEE9 沿带身渐变）> 素材原色

### 3.6 Pointer 流动动画（BeltPointerRenderer）

- 空载段（`items.length === 0`）显示黄色箭头循环流动；有物品段隐藏 pointer（`BeltItemRenderer` 渲染物品）
- 相位：`beltPhase = (elapsedMS / 2000 + phaseOffset) % 1`，**与物品同源**（`BeltSystem` 推进进度的 `beltPhase`），消除物品与箭头相位漂移
- 选中段隐藏 pointer（避免白边/斜杠干扰）
- 堵塞段箭头灰 `#828080` → 白 `#FFFFFF` 渐变（`deltaMS` 驱动，与带身堵塞渐变同步）

### 3.7 链管理与删除（BeltChainOps）

**核心难点**：单段删除后的「下游变断头链」用**空间连通性**判定上下游，**不依赖 `segmentIndex`**——后者在断头延长时会与原链索引碰撞（`BeltCreationSystem.trySelectStart` 把 `fullPath` 重置为 `[]`，新段 `segmentIndex` 从 0 重新计数）。用方向几何重建拓扑更鲁棒。

**拓扑端点定义**：
- `toCell   = cell + directionVector(出方向)`
- `fromCell = cell - directionVector(进入方向)`  
  进入方向 = 转角段 `entryDir`；直段 = 出方向（item 沿出方向流入）

**删除单段算法**：
1. 收集原链全集拓扑（含被删段，用于精确判定「原链头」）
2. 销毁被删段 + 释放占用
3. 原链头：`fromCell` 不在原链任何段 cell 中（无前驱；含被删段 cell 比较）
4. 剩余段按「无向连通性」（后继 `toCell` + 前驱 `fromCell` 都可走）分连通分量
5. 每个分量：找分量头（`fromCell` 不在分量内）→ 沿后继排序 → 含原链头的分量保留原 `chainId`，其余分配新 `chainId`（`chain-split-...`）→ 重写 `segmentIndex(0..n)`，末段 `isTail=true`

**边界处理**：
- 删头段 → 无分量含原头，全部重拆为新断头链
- 删尾段 → 上游保留原 `chainId`，末段置 `isTail`
- 链长 1 → 删空，无后续操作

### 3.8 T2.16 终点对接辅助（BeltDockOps + PortHighlightRenderer）

**用户实测痛点（2026-08-24）**：拖带到设备格整条染红、末段方向不指向端口时物品默默停在带尾——"连不上设备"无任何反馈。

**核心逻辑（端口重定向 `dockRedirect`，2026-09-02 三轮修订）**：
- **mouse 在输入端口格上** → 寻路目标**重定向**到该端口的朝向侧供给格（端口格 + outward 向量）+ 吸附末段方向 = 逆朝向指向端口。从任意方向拖到端口上（含从设备右侧横穿接近）都自动找最近路径经供给格接入：侧方进入供给格 → 末段 90° 拐向端口（转角），下方进入 → 直段。点击端口格 = 唯一对接触发手势。供给格被占/不可放置 → 路径终于供给格由 `checkPathValid` 染红（"接不上"反馈）。
- **零新段尾段转向（`commitTailResnap`）**：尾段已在供给格但方向不对（横着路过停在供给格），点击端口 → 已落盘尾段直接更新为指向端口（直↔转互转），即刻对接。
- ~~mouse 在供给格上 → 末段方向覆盖为指向端口~~ **（2026-09-02 移除——用户拍板：只有点击输入端口格本身才触发对接）**；~~路径终于端口格再截断~~ **（同日三轮修订移除——侧向接近恒红，改为目标重定向）**。`dockTargetAt`/`applyDockSnap`/`incomingDirOf` 一并退役。
- **吸附 180° 折返防御**（`applySnapToCells`）：末段自然方向与吸附方向相反时不覆盖——端口重定向下供给格上方恒为被占端口格，正常不可达，纯异常拓扑兜底。

**对接方向规则收紧（2026-09-02 二轮修订）**：用户拍板"接 (2,0) 只能经下方供给格 (2,1) 进入，不能从 (3,0) 侧向横穿连接"。三处同步收紧为**同一口径——供给格恒为端口朝向侧相邻格**：
- `PortCell` 新增 `outward` 朝外方向（`PortGeometry.inputPortCells` 计算，输入/输出口共用）；`portOutwardBase` 消解 h=1 顶/底边歧义：**输入口朝下（存货口供给带从下方指入）、输出口朝上（取货口/精炼炉带从上方接出）**——与 `PortMask` 端口面板视觉约定（输入画底边/输出画顶边）一致，旧四方向扫描掩盖了该歧义。
- `IntakeOps.findFeederBelt` 由四邻扫描改为**只认朝向侧供给格 + 段方向逆朝向指入**——侧向横穿的带不再被设备吸入。
- `BeltSystem` 真堵分类：链尾指向端口但非逆朝向（侧向横穿）视同断头红提示；`dockInfoOf` 确认绿只在末格为朝向侧供给格且指向端口时亮。

**高亮与带身残段（2026-09-02 四轮修订）**：
- **候选紫移除**：`dockInfoOf` 不再返回 targets（四邻"够得着"端口），只保留 confirmed "将连接"绿（用户拍板）——`PortHighlightRenderer` 对接态只剩红（起点反例）/绿（确认）。
- **端口内半格带身残段**（`drawStraightBeltStub`，双侧）：
  - **输入对接（进入侧半格）**：供给段（判定与 `findFeederBelt` 同口径）在端口格内画半格——物品 progress 1.0→1.5 走进设备期间有带身可骑，"连进端口/钻入设备"观感。
  - **输出接出（出口侧半格，同日补全）**：接收段（入口相邻格是输出端口且入口朝向 = 端口朝外方向——`findReceiverBelt` 的朝向侧对齐形态）在端口格内画半格——物品 progress=0 从端口格中心冒出，带身从设备下方接出（"钻出设备"观感）。
  - 已落盘由 `BeltVectorRenderer.updatePortStubs` 维护（按端口格 key diff，两类统一处理，染色跟随所属段选中/堵塞态，挂默认 zIndex=0 带身层、设备 zIndex=1 之下）；预览由 `BeltCreationSystem.drawPreview` 同步画预览色残段（输入=确认绿时画进入侧；输出=port 起点首段未落盘时画起点口出口侧，独立容器 zIndex=0.5 同在设备之下，首段落盘后交给已落盘残段避免重复）。
  - **配套修复**：whole 整图设备（仓库取货口/存货口）的 Sprite 此前未设 zIndex（默认 0，与带身同级）——同 zIndex 按插入序渲染，后创建的残段/物品画到了仓库设备**上方**（nineslice 设备 root 显式 zIndex=1 无此问题）。已在 `RenderSystem.createEntry` 对 BuildingComp 实体统一设 zIndex=1（2026-09-02 实测修复）。

**对接信息 (`dockInfoOf`)**：供 `PortHighlightRenderer` 渲染
- `targets`：预览末格四邻全部输入端口格（候选——"够得着"，紫 #C79BF2）
- `confirmed`：末段方向指向的那个端口格（落盘即对接成立——"将连接"，绿 #37D067）

**起点反例 (`getStartHintCell`)**：hover 态鼠标悬停的**输入端口格**（不是合法起点），`PortHighlightRenderer` 红色警示 + 文字提示"输入端口不能作为起点"，替代此前静默无效。

### 3.9 防穿模与重叠检查

- 创建前检查预览路径每个目标 Cell 是否被占用（`OccupancyMap.canPlace`）
- 被普通设备占用 / 地图边界外 → 创建失败，预览变红
- **传送带段之间不允许重叠**：同一 Cell 只能有一段传送带（T2.0 基础版）
- `checkPathValid` 关键判定：**起点格（`anchors[0]`）出现在非首格位置（`raw[1:]`）即判非法**——路径绕回起点会在原 chain / 建筑端口格上创建重叠段（T2.0 重叠 bug 根因）。BFS 即使把 startCell 当终点也会返回该路径（终点豁免占用），所以这里必须拒绝。

### 3.10 数据模型（BeltSegmentComp）

```typescript
interface BeltSegmentComp {
  chainId: string;              // 所属链 ID
  direction: Direction;         // 段朝向（直段=流向；转角段=出口方向）
  isCorner: boolean;            // 是否转角段
  entryDir?: Direction;         // 转角进入方向
  mirrorH?: boolean;            // CCW 转角需水平镜像
  isTail: boolean;              // 是否链末端（可继续延长）
  incomingDirection?: Direction;// 链首格继承的进入方向（仅首格）
  segmentIndex: number;         // 链内序号（0=链首）
  phaseOffset: number;          // pointer 相位偏移（随机 0~1，避免同步流动）
  items: BeltItem[];            // 物品队列（T2.1+）
  blocked?: boolean;            // 堵塞态（队首非 entering 物品被堵停 delta=0）
}

interface BeltItem {
  itemId: string;
  progress: number;      // 0.0~1.0（端口穿越扩展：输出注入 -0.5、预约进入 1.5）
  delta: number;         // 本 Tick progress 增量（渲染插值用：流动=+0.025、停止=0）
  entering?: boolean;    // T2.6 预约标记：已在门口(0.5)预约进设备
}
```

### 3.11 延长首段转向——原尾格直改（2026-09-02 修订）

**用户实测痛点**：断头延长时路径**先沿原方向强制顶一格**再走 L 形——尾在 (1,1) 方向 ↑、想往左接带，结果走出 `1,0 → 0,0 → 0,1` 的绕行，而不是直接 `1,1 → 0,1`。

**新行为**（仅 tail 起点**首段**；port 起点与多锚点后续段维持强制首步=端口朝向/上一段出方向）：

- **首步朝拖拽方向**：`refreshPreview` 对 tail 首段改传 `allowedDirections`（同向 + 两个 90° 侧转）而非 `startingDirection`——不再先顶一格，动量 L 形/BFS 首步直接对准目标
- **原尾格直段↔转角互转**：侧转时转角落在**原尾格**上（↑ 直段延长向左 → 原尾格变 ↑← 转角）；转角尾格沿进入轴延长则**转角拉直**。实现：`trySelectStart` 把原尾格登记为 `fullPath` 前缀首格（`committedHandles` 记其 handle），转角计算/落盘更新/阻挡判定全走既有链路（`commitCells` 旧尾格分支 + `updateSegment`）
- **禁止逆进入方向折返**：合法首步 = 排除 `reverse(entryDir)`（转角尾格以 `entryDir ?? direction` 为基准——只禁"朝物品来处"折返，垂直侧转合法）；动量 fallback 路径由 `checkPathValid` 兜底染红；正后方拖拽 BFS 自动绕行（同旧 180° 约束）
- **预览反馈——原尾格隐藏 + 预览接管（2026-09-02 二轮实测修订）**：首段预览期间原尾格实体**隐藏**（带身 `BeltVectorRenderer` + 箭头 `BeltPointerRenderer` 按格比对 `getHiddenTailCell()` 跳过渲染；经 RenderSystem 构造回调转发，Game.ts 接线），该格由预览渲染**接管**——避免"旧带身+预览"双层叠印。鼠标停在尾格上无新段时按已落盘实体当前形态画（单格序列推导会退化成 entry 直段，转角尾会画错）。首次落盘（形态定型）或退出创建模式即恢复显示，其后该格渲染与其它已落盘段一致
- **`segmentIndex` 接续**：新段从原尾段 `segmentIndex+1` 连续递增（`committedBaseIndex`），修正旧"从 0 重排"——`SelectionSystem` 链内排序与 `BeltPointerRenderer` v11 领头相位都按"链内连续位置"假设
- **配套 `BeltDockOps.incomingDirOf` 几何化**：吸附格进入方向改由前格位移推导（tail 首段侧转后首格进入方向 ≠ 链首继承方向，旧直取 `startDir` 会误判 180° 折返、错弃吸附）

**回归保障**：7 场景 esbuild 打包真模块模拟（用户示例/同向直延/斜拖/正后方绕行/转角尾×3/占用目标染红/port 首步不变）全部通过；`npx tsc --noEmit` 通过。

## 8. 给后续任务的提示（T2.1+ 依赖）

1. **物品移动逻辑在 `BeltSystem`**：每 Tick 推进 `progress += 0.025`（跨一格 40 Tick / 2 秒），到达段尾（`progress >= 1.0`）检查下游段/设备输入端口
2. **跨段传输**：下游段 `items.push({...progress: 0})`，上游段 `items.shift()`；下游满 → 上游 `blocked=true`，`delta=0`（pointer 也随之变色）
3. **端口吸入 (`IntakeOps.findFeederBelt`)**：末段须落在输入端口相邻格（供给格）**且方向指向端口**——`BeltDockOps.applyDockSnap` 已把落盘方向修正为指向端口，T2.6 可直接复用
4. **端口轮询 (`PortStatusOps` / `MachineSystem`)**：输入轮询走 `inputPollIndex`，2026-09-02 修订为**先到排名序**（`inputArrivalRank` 记录各口首次到货时刻，B 先到 → B-C-A），取代端口定义序
5. **指针相位**：`BeltSegmentComp.phaseOffset` 随机初始化，`BeltPointerRenderer` 用 `beltPhase = (elapsedMS/2000 + phaseOffset) % 1`，**物品进度推进同源**（`BeltSystem` 也用 `beltPhase` 推进 progress），消除物品与箭头相位漂移

## 10. 总结

T2.0 传送带创建系统作为 Phase 2 的**前置基础**，确立了：

1. **状态机驱动的交互模式**（hover/preview 双态，多锚点延长）
2. **双层寻路**（动量 L 形 + BFS 绕障）与**方向约束**（禁止反向、仅 90° 转弯）的工程化落地
3. **矢量带身渲染方案**彻底解决低 zoom 接缝问题，且与 Sprite 渲染管线解耦
4. **链拓扑用空间连通性而非索引维护**，支撑任意段删除后的自动重拆
5. **T2.16 终点对接辅助**把隐式几何判定显式化为吸附/高亮/提示，解决玩家"连不上设备"的核心痛点

这些基础设施为 T2.1 物品移动、T2.2 跨段传输、T2.6/7 设备对接、T2.10 端口轮询等后续任务提供了稳定的数据模型与渲染管线。所有核心数学（方向/转角/寻路/吸附）集中在 `BeltPathGeometry`/`BeltPathfinding`/`BeltDockOps` 三个纯函数模块，**预览/落盘/渲染三方单一事实来源**，避免了历史项目中"预览与落盘不一致""渲染与逻辑脱节"的反复返工。
