# T2.1 — BeltSystem 基础：单段物品移动 实施计划

## 目标与范围

实现物品在一段传送带上的移动逻辑和动画，达成 implementation-phase-2.md T2.1 的全部验收标准：
- 物品 progress 每 Tick +0.025（0.5 格/秒，跨一格 40 Tick / 2 秒）
- 物品沿方向匀速移动，到段尾（progress=0.99）停下
- Pointer 空载时循环流动，段上有物品时隐藏
- 物品/pointer 居中于带面渲染，缩放（放大/缩小）位置正确

**T2.1 范围 = 单段物品移动 + pointer 显隐联动**。跨段传输/堵塞逆流（T2.2）、端口吸入设备（T2.6）、转角传送带的独立任务化（T2.11）不在本任务。转角上物品的位置计算会一并实现（复用已有几何），保证 `spawnBelt` 造的转角链上物品也能正确移动渲染，但转角的"独立验收"留 T2.11。

## 关键架构决策（含理由）

### 决策 1：先建立 Simulation Loop（GameLoop）—— A5 §2 双时钟
**现状**：`main.ts` 主循环只调用 `game.update(deltaMS)`→`renderSystem`，**完全没有 20TPS 仿真循环**。BeltSystem 必须按固定 dt=50ms 运行（A5/DD-004），这是它运行的前提。
**方案**：新建 `GameLoop.ts`，实现 A5 §2 的 accumulator 模式（累积 deltaMS，每满 50ms 跑一次 tick，螺旋追赶上限 250ms）。预留 `paused` 与 `speedMultiplier` 字段（默认 1×、不暂停），但**不加 UI**（速度/暂停 UI 不在 T2.1）。
**理由**：A5 是既定核心决策；不建 GameLoop 就只能用 deltaMS 近似（违背固定 dt、不可复现、与 T2.2+ 的 MachineSystem 无法对齐时序）。

### 决策 2：物品数据加在 `BeltSegmentComp`，不引入完整 LogisticsComp
**方案**：在 `BeltSegmentComp` 增加 `items: BeltItem[]` 字段；同文件定义 `export interface BeltItem { itemId: string; progress: number }`（A9 §2.1）。`createSegment` / `spawnBelt` 初始化 `items: []`。
**理由**：A9 §7.2 的完整 `LogisticsComp` 含大量 Phase 2+ 字段（inputDirections/filter/pollIndex…），T2.1 用不上，过早迁移徒增复杂度。这与 T2.0「临时组件、后续统一」的渐进思路一致。

### 决策 3：物品逻辑 20TPS 推进，渲染读快照（不插值）
**方案**：BeltSystem 每 tick 推进 `item.progress += 0.025`（逻辑）；BeltItemRenderer 每帧读 `progress` 画位置，**不做帧间插值**。
**理由**：符合 A5 §1.1「渲染读上一 Tick 快照」原则；0.5 格/秒慢速下每 tick 仅跳 1.6px，肉眼几乎无感。若验收时用户觉得微颤，再增量加插值（把 `simAccumulator/SIM_STEP` 传给渲染器线性插值即可，成本低）。Pointer 是纯视觉（A9 §5.2.2），继续用 `elapsedMS` 平滑流动，与物品分离。

### 决策 4：新建 `BeltItemRenderer`，独立实现位置计算（不重构 pointer 几何）
**方案**：新建 `BeltItemRenderer`（挂 layer3Item，与 pointer 同层；两者互斥故无冲突）。位置计算：直段用 A9 §5.3.2 `getItemWorldPos` 公式，转角用四分之一圆弧（数学等价于 `BeltPointerRenderer.computeCornerTransform`）。暂不抽取共享函数（避免改动已稳定的 pointer 渲染器引入回归），仅注释标注未来可统一。
**理由**：降低回归风险；物品只需位置，pointer 还需箭头旋转，职责不同。

### 决策 5：同段多物品间距（A9 §2.3）一并实现
**方案**：`MIN_ITEM_GAP = 0.25`，推进时从队首（progress 最大）向队尾处理，后方 `progress = min(推进值, 前方.progress - GAP)`。段尾钳制 0.99（A9 §3.1 情况B 断头停止）。
**理由**：保证多物品正确性（验收脚本可能注入多物品），且实现简单；跨段间距属 T2.2。

## 实现步骤（文件级，有序）

### 1. 新建 `src/game/GameLoop.ts`
A5 §2 accumulator：`update(frameDeltaMS)` 累积→每 50ms `tick()`→调用注册 systems 的 `update(world, 50)`。含 `paused`、`speedMultiplier`、螺旋上限 250ms。导出 `SIM_STEP_MS` 复用 constants。

### 2. 修改 `src/game/components/BeltSegmentComp.ts`
- 新增 `export interface BeltItem { itemId: string; progress: number }`
- `BeltSegmentComp` 增加 `items: BeltItem[]` 字段（带文档注释：T2.1 单段物品队列，T2.2 起跨段）

### 3. 实现 `src/game/systems/BeltSystem.ts`
- `update(world, dt)`：`world.query('BeltSegmentComp', 'Position')`
- 每段：按 progress 降序处理物品，`progress += 0.025`，间距夹紧（MIN_ITEM_GAP=0.25），段尾钳制 `min(., 0.99)`
- 速度常量：`ITEM_PROGRESS_PER_TICK = 0.025`（= 0.5格/秒 × 50ms / 64px）
- **T2.1 不做跨段传输、不做端口吸入**（留 T2.2/T2.6）

### 4. 新建 `src/game/render/BeltItemRenderer.ts`
- 仿 `BeltPointerRenderer` 结构：`world.query('BeltSegmentComp','Position')`，diff 维护「段→物品 Sprite 列表」
- 位置：直段 `getItemWorldPos(pos, direction, progress)`；转角圆弧（复用 turnInfo + pivot 数学）
- 纹理：`getTexture('items', itemId)`，anchor 0.5，缩放到约 0.5 格（32px）
- 挂 layer3Item；`destroy()` 清理
- 接受 `getTexture` 注入（与 RenderSystem 一致）

### 5. 修改 `src/game/render/BeltPointerRenderer.ts`
- `update` 中每段：`seg.items.length > 0` → `entry.cellWrap.visible = false`；空载 → 恢复 `true`（保留现有流动逻辑）
- 注释更新「T2.1：有物品时隐藏」

### 6. 修改 `src/game/Game.ts`
- 持有 `gameLoop: GameLoop`、`beltSystem: BeltSystem`
- 构造时注册 BeltSystem 到 GameLoop
- 新增 `tickSimulation()`（或让 main 直接调 `gameLoop.update`）
- RenderSystem 增加 BeltItemRenderer 实例与转发

### 7. 修改 `src/game/systems/RenderSystem.ts`
- 新增 `beltItemRenderer: BeltItemRenderer`（挂 layer3Item）
- `update` 末尾调用 `this.beltItemRenderer.update()`
- `clear()`/`destroy` 转发清理

### 8. 修改 `src/game/systems/BeltCreationSystem.ts`
- `createSegment`（:583）写 BeltSegmentComp 时加 `items: []`

### 9. 修改 `src/main.ts`
- 主循环 `app.ticker.add` 内：在渲染前调 `game.tickSimulation(ticker.deltaMS)`（驱动 GameLoop→BeltSystem）
- `spawnBelt`（:641）写 BeltSegmentComp 时加 `items: []`
- 新增测试钩子 `spawnBeltWithItem(cells, startDir, itemId, progress?)`：调 `spawnBelt` 后往首段 `items` 注入一个物品（对应验收「一段传送带 + 一个物品」）。暴露到 `window.__game`
- 控制台帮助文本补 T2.1 用法

## 影响面与风险
- **新增 GameLoop** 是最大架构改动，但隔离在 GameLoop.ts + main 一行调用，不破坏现有渲染/交互。
- **BeltSegmentComp 加字段**需同步 `createSegment`、`spawnBelt` 两处创建点（已识别），遗漏会导致 `items undefined`——BeltSystem 会做防御性 `items ?? []`。
- **BeltPointerRenderer 改动**仅加显隐开关，不动流动几何，回归风险低。
- 全程遵循现有代码风格（中文注释、file_path 引用架构文档、diff 渲染模式）。
