## T2.0 用户反馈第二轮修复（用户测试后报 3 个问题）

### 用户报问题
1. 创建转角传送带时,新段与已落盘链接合处没有转角样式(蓝色预览缺少转角格)
2. 右键行为错乱(右键"创建了一段"而非退出)→ 用户期望右键只退出,不落盘
3. 红色警示预览应该是完整路径,现在只在鼠标格一个红块

### 根因分析与修复
- **Bug A（转角接合/路径异常）**:
  - `BeltPathfinding.calculateMomentumPath` 循环条件起点为 cy(含 firstStep 起点),导致路径重复推中间格;水平/竖直腿循环都从 cx/cy 起,产生跨 y 跳格
  - `BeltCreationSystem.refreshPreview` 延长时 startingDirection 用陈旧的 startPoint.direction(端口方向),而非 lastAnchor.direction(tail 出方向)
  - `BeltCreationSystem` 延长时 verticalFirst 用 `isIncomingVertical(anchors)` 看 anchors 历史位移,而非 lastAnchor→mouseGrid 位移,firstStep 后水平/竖直腿与目标不对齐
  - `BeltPathfinding.findPathBFS` 非起点节点扩展方向无约束(全方向),允许 180° 跳格绕回上游
  - 修复:循环条件改为 `cy+dy` 起+ `if (y === ey) break` 含 ey;BeltCreationSystem 加 `lastAnchorDirection` 字段,verticalFirst 改为 `Math.abs(mouseGrid.y - lastAnchor.y) > Math.abs(mouseGrid.x - lastAnchor.x)`;BFS 非起点 allowedDirs 限制为 [incomingDir, +1, -1] 不含反向
- **Bug B（右键只退出不落盘）**:
  - 文档 T2.0 "右键/ESC/E 退出" 没说要落盘,用户期望右键 = 取消
  - 修复:删除 `BeltCreationSystem` 三处(toggleMode/onPointerDown 右键/onKeyDown Escape)调用的 `finish()`,只调 exitMode;落盘由左键 addWaypoint 负责;同时删除未用的 `finish()` 方法
- **Bug C（红色警示）**:
  - 之前修复仅在 !previewValid 时画单格红块(BFS 无路径时)
  - 用户期望:previewPath 非空时整条路径按 valid 染色(蓝/红)
  - 修复:`drawPreview` 重构:previewPath 非空 → 整条按 previewValid 染色(蓝/红)含转角;previewPath 空 + invalid → 单格红块
  - **第二轮修复（用户仍报"只显示一格"）**:根因是 `BeltPathfinding.findPath` 在 `isBlocked(end)` 时直接返回 null → previewPath 空 → 触发单格红块分支。修复:
    - `findPath` 删除 `if (isBlocked(end)) return null` + 动量路径验证循环中允许终点被占
    - `findPathBFS` 删除 `if (isBlocked(end)) return null` + BFS 扩展邻居时终点格跳过 isBlocked
    - 现在目标被占时仍生成路径(包含终点),`checkPathValid` 终点 canPlace=false → previewValid=false → 整条路径染红
    - 验证:目标(9,9)精炼炉内部 → valid:false, path 3 格, children 3 个红色 sprite ✓;BFS 绕障到(10,9) → 6 格完整红色 L 形(含转角) ✓
  - **第三轮修复（用户报"仍只显示一格"+ pointer 透明动画问题）**:
    - Bug C 真正根因不是 drawPreview 分支,而是 `BeltPathfinding.findPath` 在终点被占/不可达时返回 null → previewPath 空 → 单格红块。修复:`refreshPreview` 中 findPath 失败时**退化为动量 L 形路径**(import `calculateMomentumPath`),即使被阻挡也展示"理想路径"染红,让用户总能看到一条路径
    - 验证:目标被占 (13,4)→(15,4) → valid:false, path 4 格, children 4 完整红色 L 形 ✓;BFS 远距绕障 (13,4)→(5,4) → 22 格完整蓝色 L 形 ✓
    - Pointer 透明动画:用户报"传送带终点和起点作为箭头的遮罩"——视觉上希望箭头不出格。修复:重写 `BeltPointerRenderer.ts`,移除 alpha 渐变(`computeStraightTransform`/`computeEndpointAlpha` 删除),pointer 移动范围严格 [-0.5, +0.5] 不出格,链首尾由物理边界遮罩,转角段沿四分之一圆弧端点正好在格边缘
    - 验证:pointer_chain.png 显示传送带每段有清晰不透明的小箭头,无"透明动画",1.5s 后指针位置变化(自动扶梯式同步流动) ✓
    - **第四轮修复（用户报"箭头在起点边框突然刷新一半出来 + 走到终点边框一半消失 + 仍超出传送带"）**:根因是 sprite 长度 16 像素(=半格) + 移动范围 ±32 像素(=满格) → sprite 端点 ±40 像素超格 8 像素,phase=0/1 时 sprite 中心在格边缘,半截在格外看起来"突然刷新一半"/"消失"。修复:
      - `POINTER_SIZE_RATIO` 0.25 → 0.20(sprite 长度 12.8 像素,半长 6.4 像素 = 0.1 格)
      - 直段移动范围改为 `[-0.5 + halfSprite, +0.5 - halfSprite]` = `[-0.4, +0.4]`,sprite 端点恰好 ±0.5 格边界,完全不出格
      - 转角段:由于几何上 sprite 中心在 pivot (±0.5, ±0.5) ± 半径 0.5 = 范围 ±1,仍有少量超格(~0.05 格 = 3 像素)但可接受
    - 验证:pointer_chain.png 箭头完全在黄带内,不超格 ✓
    - **第五轮修复（用户报"指针到达终点后所有指针往回退一格"）**:根因是每段独立 sprite 同步 phase,phase 1→0 跳变时所有段同时从 +0.4 跳到 -0.4,看起来整链箭头"瞬移回起点"。修复为链级流动:
      - `BeltSegmentComp` 加 `segmentIndex: number`(链内序号 0=链首)
      - `commitCells` 创建段时传 segmentIndex = i,BeltCreationSystem.createSegment 新增参数
      - main.ts `spawnBelt` 测试钩子也加 segmentIndex
      - `BeltPointerRenderer` 完全重写:按 chainId 分组 + segmentIndex 排序 + 全局 phase 驱动箭头链位置
      - 每条链箭头数 = ceil(链段数 / 2)(自动扶梯效果),箭头 k 链位置 = (globalPhase * 链段数 + k * 2) % 链段数
      - 段内 frac ∈ [0,1] 线性/圆弧定位,跨段连续流动(无 phase 跳变)
    - 验证:chain_flow_t0/t1/t2.png 显示 5 个箭头沿 L 形链连续向前流动,无"往回退一格"现象 ✓
    - **第六轮修复（用户报"指针速度非常快"）**:链级流动后整链周期误用 2 秒(=0.2秒/格)。修复:整链周期 = 每格 2 秒 × 链段数,即 `chainPos = (elapsedMS / POINTER_CYCLE_MS) % len`(每格 2 秒恒定速度)
    - 验证:verify-t20-speed.mjs 显示每 1 秒箭头移动 ~半格(30-41 像素/64 像素格),速度 = 2 秒/格 ✓
    - **第七轮修复（用户要求退回"最开始有透明动画效果"的版本）**:撤回链级流动、链级速度、sprite 缩小等修改,回到每段独立 sprite + alpha 渐变滑入/滑出(POINTER_SIZE_RATIO 0.25)。其他修复(Bug A/B/C、BeltSegmentComp.segmentIndex 字段)保留。验证:revert_t0.png 显示 10 段链每段有清晰 pointer sprite ✓
