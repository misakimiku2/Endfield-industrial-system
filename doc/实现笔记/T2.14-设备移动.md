> 任务目标/需求/验收标准见计划文档对应章节。浏览器验收 `scripts/verify-t214-browser.mjs` 66/66（真实鼠标/键盘长按流）；

## 核心决策

- **同一实体贯穿，不删不建**: 移动本质是 `delete + place` 的组合，但**唯一被改写的字段是
  `Position.x/y` 与 `BuildingComp.direction`**——缓冲区/生产进度/配方/轮询状态全部原样保留
  （任务卡「搬迁不清空半成品进度」由此零成本成立）。RenderSystem 每帧从 Position+direction
  同步 Sprite（T2.17 数学），提交后无需任何手动渲染修正。
- **「搬迁期间离线」复用 T2.8 暂停语义（MachineSystem 零改动）**: 进入移动态时保存
  `comp.paused` 并置 `true`，重放/取消时还原。T2.8 暂停分支的语义（不推进计时/不吞吐/
  已预约物品放行完成视觉行程）与任务卡要求的「移动中设备离线」逐条一致，不需要新状态字段。
- **传送带/物流连接零处理代码**: 连接判定（`findFeederBelt`/`portStatuses`/
  `collectReceiverBelts`）全部是每 Tick 从几何实时计算的**纯派生值**，Port 世界坐标随
  Position/direction 变化自动重算；`outputPollQueue` 中失效带 handle 由 T2.21 队列同步自动
  剔除。「带不跟随移动、需人工重新接驳」是有意限制，无需实现（验收 K 节断言: 接带设备搬迁后
  旧带原位不动、新位置端口未连接）。
- **原位释放时机 = 进入移动态瞬间**: `occupancy.releaseFootprint(gx, gy, def, direction)`
  （原地 Position 从未改动，取消时同参数 `occupyFootprint` 重占即可，无需恢复坐标）。

## 文件与接线

- **`src/game/render/DevicePreview.ts`（新，从 PlacementSystem 抽出）**: 放置预览（T1.7）与
  移动拾取预览共用的渲染组件——whole（Sprite+PreviewTintFilter 双纹理 mask）/nineslice
  （底座拼装+端口叠加+equipment，逐 Sprite tint）双路径、billboard 徽标反向旋转、
  鼠标=中心吸附（`placementFromMouse` 随迁导出）、R 键世界角换算、canPlace 染色。
  `sync(frame)` 返回采样（grid/world/direction/effW/effH/valid），**落盘直接复用同一采样
  = 所见即所放单一口径**；这也是 Phase 3 组操作「preview 抽象不绑死单设备」的前置。
- **`src/game/systems/MoveSystem.ts`（新）**: 移动态状态机
  `enterMove / rotate / setMouse / tryCommit / cancel / update`。要点:
  - `screenAngle` 初始化 = `(原 direction + viewRotation) % 360`——进入拾取态时朝向不变，
    第一次按 R 才 +90（相对视图换算同 RotationPolicy）。
  - 重放失败（canPlace=false）→ 预览红 + **震动反馈**（在吸附位置叠加 220ms 衰减正弦横移，
    只动预览节点不改采样坐标），保持在移动态。
  - 防御: 实体在移动期间被外部销毁（如控制台 `clearAllPlaced`）→ cancel 只清理移动态不碰
    占用表；取消时原位被占（只可能因调试钩子绕过门控）→ 覆盖占位并 console.warn 留痕。
- **`SelectionSystem`（T1.8 前瞻约束落地）**: 构造器注入 `onLongPress(handle)` 回调；
  pointerdown 命中设备时挂 300ms 定时器——触发前 pointerup = 选中（原逻辑，定时器一并清）；
  触发 = 清 `pendingPress` + 升级移动态（**本次按压的 pointerup 不再提交选中**，重放由
  「下一次」左键 pointerdown 触发，与放置模式同构）。`selectFirstBuilding` 等程序化短按
  钩子走 pointerup 消费路径，定时器同步清除，无残留。
- **`RenderSystem.setSpriteHidden(handle, hidden)`（新）**: 移动态隐藏真身 Sprite（视觉由
  预览接管）。`Set<EntityHandle>` + 每帧 update 末尾维持 `visible=false`（优先于视口剔除），
  实体销毁时清标记防集合滞留。
- **`DeviceDialog`**: 动作行补「移动」按钮（`ui/move` 帧，44×44，在删除左侧）——点击 =
  关弹窗 + 清选中 + `moveSystem.enterMove`，与长按同路径。生产设备与仓库口面板共用
  `buildActionRow`，均获得移动/删除。⚠️ 连带修订: `verify-t215-browser.mjs` F3 的删除按钮
  定位从「第一个 `.efd-action-btn`」改为按文本定位（动作行第一格现在是移动）。
- **main.ts**: pointermove/pointerdown 转发加移动态分支（左键=tryCommit、右键=cancel）；
  新增 `onKeyMoving`（R=旋转、ESC=取消，仅移动态响应）；模式互斥——E 进传送带模式与工具栏
  选设备前先 `cancel()` 归位，Delete 在移动态不响应；HUD 提示行 + 帮助文本 + 控制台说明；
  `__game.move` 暴露（`isMoving()/getMovingHandle()/getPreviewInfo()` 等，验收脚本用）。

## 踩坑

- **验收脚本翻车: 相机边缘滚动污染屏幕坐标**（首版 39/54 的根因）: 点击点取 y=8（屏幕顶端
  32px 边缘滚动区内），鼠标停留期间相机以 900px/s 上漂——`screenToWorld(1120,8)` 从
  (2528,1696) 漂到 (2528,1383)，后续所有"长按设备"的命中测试全部落空，且失败呈连锁传染
  （漂移持续到脚本结束）。修正: 所有测试点位离四边 ≥80px + 每节开始复位相机
  （`camera.x/y/zoom = 默认`）+ 截图前把鼠标停靠屏幕中位。**教训: 任何"屏幕坐标 ↔ 世界格"
  断言类脚本都必须把边缘滚动当一等地形约束。**
- **截图时序: shot() 先停靠鼠标会把预览带离目标格**——D 节「红色无效预览」首版拍到的是
  停靠后的蓝色有效预览（预览跟随鼠标重新染色）。改为在关键断言处、鼠标仍悬停目标上时直接
  `page.screenshot`。同理 H 节弹窗截图必须在点「移动」**前**拍（点完弹窗即关）。
- **端口格几何**: 精炼炉 3×3 @(35,30) 的底中输入端口格 = (36,32)（**footprint 底行自身**），
  供给格 = (36,33)（footprint 外下邻格）——K 节首版把供给带尾格放在 (36,34) 导致"已连接"
  断言失败（同 demoT26 口径: (5,5) 炉端口 (6,7)/供给格 (6,8)）。
- **生产进度保留的断言语义**: 长按阈值 300ms 内设备尚未离线（此时只是"普通按压"），生产
  合法推进 ≤300ms + Tick 量化；进度保留应断言"未被重置、增量在拾取前窗口内"而非"完全冻结"。
