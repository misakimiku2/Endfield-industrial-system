# T2.18 实现笔记 — 仓库口单端口化（仅中间格是输入/输出端）

> 2026-09-04。用户实测反馈：仓库取货口/存货口应该**只有中间部位是输入、输出端**，
> 但两侧格也能创建、连接传送带。计划卡: implementation-phase-2.md T2.18。

## 1. 根因

T2.12 初版沿用了精炼炉「一排三口」的端口设计（`ports` 含 dx=0/1/2 三格）。起点高亮、
终点吸附、对接判定、物流吞吐全部由 `def.ports` 派生——三格在数据上都是端口，所以
两侧格自然能起带/接带。

## 2. 改动：一行数据 + 场景适配

```ts
// buildings.ts（两台仓库口同理）
ports: [
  { type: 'output', position: { dx: 1, dy: 0 } },  // 仅中间格（T2.18）
]
```

**零逻辑改动**——起点候选（BeltCreationSystem）、终点吸附（collectInputPortCells）、
对接判定（findFeederBelt/findReceiverBelt）、吞吐（DepotOps 分支）、端口高亮
（applyDepotStatus / PortHighlightRenderer）全部消费 `def.ports`，数据收敛即全链收敛。
这是 T2.6 起坚持「端口几何单一事实源」的直接红利。

语义变化:
- 创建模式仅中格显示起点高亮；点侧格不起带（实测 0 段落盘，中口对照 2 段）。
- 吞吐 1 件/2 秒/**设备**（原 3 口并行 3 件/2 秒）。
- 90°/270° 竖放时唯一端口 = 1×3 的中间格，功能面随朝向旋转（T2.17 的
  rotatePort/outward 数学原样生效）。

## 3. demoT210 场景重构（单口化的连锁适配）

场景 A 原布局「一台取货口的三个输出口各接一条 3 格带」失效（每台只剩 1 口）。三台
取货口中口相距 3 格，直接并排会互相重叠（3×1 占地），改为**错行排布 + L 形带**：

- 左取货口 (3,11) 中口 (4,11) → 带 `[[4,10],[5,10],[5,9],[5,8]]`（右转上行，startDir 270
  使首格成为"从下方进入"的转角，findReceiverBelt 判定成立）
- 中取货口 (5,12) 中口 (6,12) → 直行 `[[6,11],[6,10],[6,9],[6,8]]`
- 右取货口 (7,13) 中口 (8,13) → 上行后左转 `[[8,12],[8,11],[8,10],[7,10],[7,9],[7,8]]`

三门口格 (5,8)/(6,8)/(7,8) 不变，稳态采样逻辑零改动；实测输入轮询 3→1→2→3→1→2 循环 ✓。

场景 B/C: 存货口只接中带（中口唯一）。场景 B 断言取前 6 件出货（左右带 3 格暂满
堵停发生在第 7 件之后，轮转断言不受影响，实测 1→2→3→1→2→3 ✓）；场景 C 左右带
改为"暂存排货"（容量 3+3 覆盖 4 件采样与步骤 8 腾位重注，实测跳过 1→3→1→3、
恢复 1→3→2 ✓），并移除了不再吸收任何带的原存货口摆设。
