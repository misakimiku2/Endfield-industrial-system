# 02 · 整体架构

> 上一篇：[01-项目概览](01-项目概览.md) ｜ 下一篇：[03-核心框架与世界模型](03-核心框架与世界模型.md)

本文描述项目的顶层架构：分层模型、ECS、双时钟仿真、渲染管线、坐标体系与关键设计决策。各子系统的内部细节见后续专题文档。

## 1. 架构分层总览

```
┌─────────────────────────────────────────────────────────────────┐
│  输入层  main.ts（唯一入口）                                       │
│  DOM 指针/键盘事件 → 转发给各 System（System 自身不监听 DOM）        │
├─────────────────────────────────────────────────────────────────┤
│  交互层  PlacementSystem / BeltCreationSystem / SelectionSystem   │
│         DeleteSystem / CameraController / InventoryUI             │
│         （交互状态是 UI 态，不进 ECS；落盘才创建实体）                │
├─────────────────────────────────────────────────────────────────┤
│  仿真层  GameLoop（20 TPS 固定步长）                               │
│    Tick 内注册序：BeltSystem → MachineSystem（→ 占位: Turret/Enemy）│
│    MachineSystem 编排：ProductionOps / IntakeOps / OutputOps /    │
│                        BufferOps / DepotOps（纯函数 ops 层）       │
├─────────────────────────────────────────────────────────────────┤
│  数据层  ECS World（实体+组件）  +  OccupancyMap（格子占用）        │
│         BuildingComp / BeltSegmentComp / Position / SpriteComp    │
│         data/：BuildingDefinition / ItemRegistry / Recipe（静态）  │
├─────────────────────────────────────────────────────────────────┤
│  渲染层  RenderSystem（query diff → PixiJS 场景图同步）            │
│    + 传送带渲染器组（矢量带身/指针/物品/悬停）+ 端口高亮 + 网格 + 相机 │
├─────────────────────────────────────────────────────────────────┤
│  资产层  AssetsLoader（devices/items/ui 三张图集）                 │
│         ← scripts/pack-assets.ts 构建期生成（SVG/sharp → 图集）     │
└─────────────────────────────────────────────────────────────────┘
```

核心原则：

- **System 不监听 DOM**：所有原生输入由 `main.ts` 转发（`src/main.ts:172` 注释），避免与 CameraController 双监听冲突。
- **状态全在 Component（DD-011）**：系统无跨 Tick 状态（仅遍历缓存），存档 = Component 快照（DD-012）。
- **逻辑为纯函数 ops**：生产的各个环节拆成 `machine/*Ops.ts` 纯函数，MachineSystem 只做编排。
- **渲染读快照**：RenderSystem 永远读"上一个完整 Tick 结束后"的状态，不存在半个 Tick 的中间态。

## 2. ECS 模型

自研轻量 ECS（`src/game/ECS.ts`，零依赖，166 行），定位是支撑 300–500 实体 @60FPS（Phase 1 目标 100 实体）。

- **实体句柄**：`EntityHandle = number`，编码 `(generation << 20) | index`。index 20 bit（约 104 万），generation 12 bit（4095 回绕）。实体销毁时代数 +1，旧句柄**永久失效**（DD-001，防悬空引用）；`isAlive` 做"越界/存活位/代数"三重校验。
- **组件 = 纯数据对象（DD-002）**：以字符串 key（`'BuildingComp'`、`'Position'`、`'SpriteComp'`、`'BeltSegmentComp'`…）存入 `Map<key, Map<index, data>>`。`getComponent` 返回**对象引用**，调用方直接 mutate 即生效（Phase 1 简化设计，全项目无 setter）。
- **查询**：`world.query(...keys)` 返回同时拥有全部 key 的存活实体**数组**（非迭代器）；实现取最小 store 做基底遍历，Phase 1 有意选择最简单方案。
- **销毁语义**：`destroyEntity` 清空该 index 所有组件槽并回收 index；**不负责清理 PixiJS 对象**——由 RenderSystem 的 query diff 下帧自动移除 Sprite。
- **无 archetype、无 system 基类、无事件总线**（事件总线明确 YAGNI）。

组件与系统接口：

```
interface SimulationSystem { update(world: World, dt: number): void }   // dt 恒为 50ms
```

## 3. 双时钟仿真（20 TPS 逻辑 / 60 FPS 渲染）

`GameLoop.ts`（依据 A5 simulation-spec、DD-004、DD-014）：

```
每渲染帧: game.tickSimulation(frameDeltaMS)
  simAccumulator += frameDeltaMS * speedMultiplier
  钳制: simAccumulator ≤ SIM_ACCUMULATOR_MAX_MS (1000ms)   ← 螺旋追赶保护，最多追 20 Tick
  while (simAccumulator >= SIM_STEP_MS /* 50ms */):
      simAccumulator -= SIM_STEP_MS
      依次调用 systems[i].update(world, 50)                 ← Tick 内 dt 恒定

每渲染帧: game.update(frameDeltaMS)
  alpha = simAccumulator / SIM_STEP_MS   (0~1)              ← 渲染插值系数
  renderSystem.update(deltaMS, alpha)                       ← BeltItemRenderer 用 alpha 帧间内插
```

关键点：

| 机制 | 说明 |
|---|---|
| 固定步长 | 逻辑稳定且与帧率解耦；系统内不需要处理变长 dt |
| 系统顺序 = 注册顺序 | **BeltSystem 先于 MachineSystem**（DD-010：物品先到端口、设备再结算）；规划顺序 Belt → Machine → Turret → Enemy → Cleanup |
| 渲染插值 | 全局插值系数 `alpha`（`Game.ts:107`）+ 物品级 `BeltItem.delta`（本 Tick 增量）双重机制，消除 20Hz 卡顿 |
| 暂停/倍速 | `paused` 直接跳过；`speedMultiplier`（2/4/8）只改累积速率，单 Tick 逻辑不变 |
| 后台保活 | `main.ts` 的 `setInterval(250ms)`：页面隐藏时按真实流逝时间喂 `tickSimulation`，rAF 停转下仿真慢放而不冻结 |
| 读快照 | `tickSimulation` 必须先于渲染 `update` 调用（`Game.ts` / `main.ts` 注释） |

## 4. 渲染管线

每渲染帧（`main.ts` ticker 回调，`src/main.ts:310` 起）执行序：

```
1. 视口轮询            app.screen 尺寸变化 → camera/gridRenderer/inventoryUI 同步
                       （每帧轮询而非 resize 事件：绕开 PixiJS ResizePlugin 异步时序竞争）
2. controller.update   相机输入意图合成（WASD/边缘滚动）
3. camera.update       缩放指数趋近 + 视图旋转过渡动画
4. camera.updateTransform  把相机状态写入 worldContainer（scale/pivot/position/rotation）
5. gridRenderer.update 屏幕空间网格重绘（旋转感知）
6. placement.update    设备放置预览跟随
7. belt.update         传送带创建模式高亮/预览
8. selection.update    选中框跟随相机重绘
9. game.tickSimulation ★ 仿真 Tick（可 0~N 个）
10. game.update        ★ RenderSystem：query diff 同步 Sprite + 视口剔除 + 五个传送带/端口渲染器
11. HUD 节流块          250ms(4Hz) 一次：FPS/内存/模式提示；文本变化才赋值（防文本纹理重绘）
```

场景分层（`render/SceneRenderer.ts`）：

```
app.stage
├─ backgroundLayer  [屏幕空间] 网格背景与网格线
├─ worldContainer   [世界空间] 受相机变换
│   ├─ layer0Terrain / layer1Grid（空）
│   ├─ layer4Enemy / layer5Effect（预留）
│   ├─ layer2Building  带身(z0) < 物品层belowItems(z0.5) < 设备(z1) < 悬停框(z15000)
│   └─ layer3Item      端口高亮(z14000) / 提示文字(z16000) / 传送带指针
└─ overlayLayer     [屏幕空间] 暗角 + InventoryUI 工具栏（不随视图旋转）
```

所有层 `sortableChildren: true`，层内用 `zIndex` 细排。详见 [07-渲染与UI](07-渲染与UI.md)。

## 5. 坐标体系与方向约定

依据 A6 coordinate-spec（DD-009），三层坐标、无 Grid→Screen 捷径：

| 坐标系 | 形式 | 转换 |
|---|---|---|
| Grid（格） | 整数 `(gx, gy)`，原点左上 | `worldToGrid` = `floor(world / CELL_SIZE)`；吸附用 round |
| World（世界） | 像素浮点，1 Cell = **64px** | `gridToWorld = g × CELL_SIZE` |
| Screen（屏幕） | canvas 像素 | `camera.worldToScreen / screenToWorld`（含旋转与缩放） |

- **CELL_SIZE = 64**（`render/constants.ts`）；默认地图 64×64 Cell = 4096×4096 世界像素（尺寸唯一真相源是 `MapInstance`，非全局常量）。
- **方向约定**：`Direction = 0 | 90 | 180 | 270`（世界相对：0°=右、90°=下、180°=左、270°=上）。存档/模拟/轮询全部存**世界朝向**。
- **旋转参考系**：视图旋转（Ctrl+R）不改 ECS 数据；WASD/边缘滚动是屏幕相对（经 `camera.screenDirToWorld` 换算）；R 键旋转设备是"相对视图"——`世界朝向 = 屏幕朝向 − viewRotation (mod 360)`（`PlacementSystem.worldAngleFromScreen`）。
- **billboard**：设备徽标层每帧 `rotation = camera.displayRotation − sprite.rotation`，保持屏幕朝上。

## 6. 世界模型与占用

- `MapInstance`：地图尺寸唯一真相源（Phase 1–2 固定 64×64；接口为 Phase 3a 无限世界预留）。
- `OccupancyMap`：`Map<"gx,gy", definitionId>`，**不属于 ECS**（世界结构而非组件）。核心 API：`canPlace / occupy / release / occupyFootprint / releaseFootprint`，占地计算统一走 `effectiveFootprint(footprint, direction)`（90°/270° 宽高互换）。
- 设备与传送带共用同一占用表：传送带落盘 `occupy(gx, gy, 'transport_belt')`，因此设备不能压带、带不能穿设备——**格位互斥完全由占用表中立**。

## 7. 数据流总览（以"一次完整生产"为例）

```
玩家操作                    仿真 Tick (50ms)                         渲染帧 (60FPS)
────────                    ────────────────                         ─────────────
工具栏选设备
  → placement.enterMode
R 旋转 / 左键落盘
  → 创建 Entity(Position +
    BuildingComp + SpriteComp)
  → occupancy.occupyFootprint
E 起画传送带 → 左键逐段落盘
  → 创建 Entity(BeltSegmentComp)
  → occupancy.occupy
                             ① BeltSystem: 物品 progress += 0.025
                                跨段/间距/钳制/链级堵塞分类
                             ② MachineSystem:
                                吸入: 门口0.5 预约 → 放行1.5 移除 → 输入槽+1
                                生产: 计时 elapsed += 50
                                      完成且产物有位 → 原子结算(扣料+落产物)
                                      产物无位 → blocked(原料不扣)
                                输出: 相位窗口内 轮询队列 → 空段注入 progress=0
                                                                      RenderSystem diff:
                                                                        组件快照 → Sprite 同步
                                                                        物品按 alpha 内插
                                                                        端口/堵塞状态 → 染色
```

## 8. 关键设计决策索引

项目宪法为 `doc/architecture/core-decisions.md`（DD-001~DD-015）。代码中最常遇到的：

| 决策 | 含义 | 代码落点 |
|---|---|---|
| DD-001 | generation-based 实体 ID，防悬空引用 | `ECS.ts:21` |
| DD-002 | Component 纯数据、引用语义 | `ECS.ts:114` |
| DD-003/005 | 数据驱动：建筑 = Definition，静态数据不引用实体 | `data/buildings.ts` |
| DD-004 / DD-014 | 20 TPS 固定步长 + 帧预算（逻辑 ≤5ms 渲染 ≤11ms） | `GameLoop.ts` |
| DD-008 | 设备/UI 美术源 = SVG，物品 = PNG；构建期 sharp 光栅化打包图集 | `scripts/pack-assets.ts` |
| DD-009 | 三层坐标体系，无 Grid→Screen 捷径 | A6 全局 |
| DD-010 | Tick 内 System 顺序严格固定 | `Game.ts:71` |
| DD-011/012 | 状态全在 Component；存档 = Component 快照 | 各组件 |
| DD-013 | 每逻辑组一张图集（devices/items/ui） | `render/AssetsLoader.ts` |
| DD-015 | 图集 mipmap（zoom<1）+ 4× 超采样（zoom>1）+ ATLAS_PADDING=8 | `AssetsLoader.ts:51` |

派生的代码级强约束（违反会产生隐蔽 bug，详见 [09-依赖关系](09-依赖关系.md)）：

1. **常量同源**：`IntakeOps.PORT_ENTER_PROGRESS === BeltSystem.STOP_MAX`、`PORT_RELEASE_PROGRESS === BeltSystem.PORT_ENTER_DONE`，禁止各自定义。
2. **几何单一事实源**：端口格几何只有 `PortGeometry`（逻辑/吸附/高亮三处共用）；旋转占地只有 `effectiveFootprint`（五处共用）。
3. **禁止成环**：`BeltSystem` 不得 import `machine/`（因此端口几何下沉到共享的 `PortGeometry`）。
4. **执行顺序**：`BeltSystem → MachineSystem` 由 Game 的注册顺序保证。
