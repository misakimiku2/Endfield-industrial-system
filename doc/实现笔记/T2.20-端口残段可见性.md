# T2.20 实现笔记 — 端口残段可见性修复（旋转设备"半截带"被贴图遮挡）

> 2026-09-04。用户反馈（附两图）：0°/180° 水平放置时端口处能看到对接的**半截传送带**，
> 设备旋转 90°/270° 后这半截带不见了（"旋转后端口下方没有出现传送带"）。
> 计划卡: implementation-phase-2.md T2.20。

## 1. 现象与根因

对接段会在**端口格内**画半格带身残段（2026-09-02 引入：物品 progress 1.0→1.5 走进设备
期间有带身可骑；输出侧对称——物品从端口格中心冒出）。残段挂 `layer2Building`
**zIndex 0，位于设备 Sprite（zIndex 1）之下**——当年注释写明这是有意的"钻入设备"观感。

但"能否看见残段"实际取决于**设备美术在端口格的透明边距**：

- 仓库口 0°/180°（横放）：端口格的上/下缘是透明区 → 残段透出来，可见半截带 ✓；
- 旋转 90°/270°（竖放）：端口格的侧边是**不透明的边框/凸缘贴图** → 残段被完全遮住 ✗。

即残段一直都有画，只是可见性"碰运气"——由美术透明区随朝向轮转的位置决定。竖放时
带子看似停在设备边框外、与面板之间有一段空隙，观感如"没连上"。

## 2. 修复

### 2.1 水平残段镜像（核心修复）

`drawStraightBeltStub` 本地几何以「上半格=进入侧」表达，配 `beltTextureRotation(dir)`
旋转。竖直带流（dir 90/270，对应水平放置的设备）旋转量为 0/π，本地"上"旋转后仍在
上下向，残段天然落在靠带一侧 ✓；水平带流（dir 0/180，对应旋转 90°/270° 的竖放设备）
旋转量为 ±π/2，本地"上"被转到流动背侧，残段画在背离带子的一侧 ✗（用户截图:
存货口背侧冒出半截黄带）。

修复（`updatePortStubs` 一行）: 水平方向取反 `exitHalf`，残段恒落在靠段一侧:

```ts
const horizontal = f.dir === 0 || f.dir === 180;
drawStraightBeltStub(stub.g, CELL_SIZE, colors, horizontal ? !f.exitHalf : f.exitHalf);
```

### 2.2 z-order 保持设备之下（二次修订，回退首次方案）

首次修复曾把整图设备的残段抬到设备之上（zIndex 2）以求"任意朝向可见"——用户实测
否决: 残段画在了设备边框/面板**之上**，盖住了设备美术。最终方案: **残段恒挂
zIndex 0（设备之下）**，与带身/物品同层的"钻入设备"观感——

- 0°/180°: 残段经设备美术透明边距可见（半截带伸到面板旁，用户认可的原观感）；
- 90°/270°: 残段塞在端口边框之下，带子齐平接到设备边框（放大核验 `_z` 系截图，
  无缝隙、不盖框）。

若后续希望旋转后残段也如 0° 那样明显外露，属美术任务: 在 Depot.svg 端口凸缘面
开透明 mouth（残段即可从口内透出），代码侧无需再动。

## 2.5 补充修复: 水平残段镜像（同日用户二次反馈）

抬到设备之上后暴露出第二个 bug: **水平方向（dir 0/180）的残段画在背离带子的一侧**
（用户截图: 竖放设备的端口背侧冒出半截黄带）。根因是旋转数学:

- `drawStraightBeltStub` 本地几何以「上半格=进入侧」表达（`exitHalf=false`），
  配 `beltTextureRotation(dir)` 旋转；
- 竖直方向 dir=90/270 的旋转是 0/π——本地"上"旋转后仍是上/下，天然落在靠段一侧 ✓；
- 水平方向 dir=0/180 的旋转是 ±π/2——本地"上"被转到**右侧/左侧**，恰为流动背侧 ✗
  （±π/2 的镜像性所致）。

修复（`updatePortStubs`，一行）: 水平方向取反 `exitHalf`，使残段恒落在靠段一侧:

```ts
const horizontal = f.dir === 0 || f.dir === 180;
drawStraightBeltStub(stub.g, CELL_SIZE, colors, horizontal ? !f.exitHalf : f.exitHalf);
```

实测（用户同场景: 取货口 90° + 存货口 270° + 水平带，`t20-mirror-fixed.png`）:
两台设备残段均出现在靠带一侧，带子视觉上接到面板；0°/180° 不受影响。

### 2.6 补充修复: 创建预览残段同源镜像（普通设备 90°/270°）

用户三次反馈: 普通设备（精炼炉）旋转 90°/270° 后，E 模式创建传送带的**蓝色/红色预览**
在端口格内出现穿模。根因与 §2.5 完全同源——`BeltCreationSystem.drawPreview` 的两个
预览残段（对接确认进入侧 / 输出口起点出口侧）用的是**未修正**的
`drawStraightBeltStub` 约定，水平带流下半格画在设备内侧（透过九宫格美术的透明区
可见 = 穿模）。修复: 两处同样按水平方向取反 `exitHalf`。实测
`t20-preview-fixed.png`: 蓝带整齐止于设备边框，绿色"将连接"端口不再被压。

## 3. 验证

- 四朝向残段截图（`t20-stub-d0/d90/d180/d270.png`）: 半截带均伸进端口格、接到面板 ✓。
- 用户场景复现（`t20-repro-rotated.png`）: 取货口 90° + 存货口 270° 水平带连接，
  出货/进料事件正常（本就是通的，本修复只补视觉）。
- 回归: verify-t212-depot.ts 53/53、verify-t217-rotation-browser.mjs 17/17、demoT212 实测、`tsc` 绿。
- 精炼炉（nineslice）残段行为不变（仍设备之下）。

## 4. 备注

- 残段收集逻辑（① 输入对接进入侧 / ② 输出接出出口侧）本身是旋转感知的
  （PortGeometry 单一事实源），本次未动——纯 z-order 修复。
- 若后续美术在 Depot.svg 端口凸缘上开出"开口"（透明 mouth），可考虑恢复统一的
  设备之下渲染；当前以 z-order 分派为准。
