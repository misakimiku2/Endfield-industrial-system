# T2.28 — 指针循环装饰层（0/1 统一模型）· 实现笔记

> 任务卡: 用户 2026-09-07 提出指针/物品统一概念模型——"传送带是 root，上面的
> 东西分两种：指针 0（循环播放）和物品 1（有 ID、会堵塞），本质同一种东西、
> 运行逻辑相同，只是两层动画表现"｜ 状态: 完成 ✅（浏览器逐帧验收）

## 设计（用户语言 → 机制）

- **0（指针）**: 传送带**自带的循环图案**。位置 = 全局时钟 + 每链固定偏移
  （`chainVirt` 纯函数），永远以带速循环：滑出带终点（带身遮罩裁剪 + 半透明
  渐隐）→ 从起点再进来。无 ID、不排队、与物品**零耦合**——堵塞时照常循环，
  在堵塞前沿被吞（用户原话: "三个 0 循环播放"）。
- **1（物品）**: 同类但带 ID、会排队堵塞、走进设备消失。**实现完全不动**
  （BeltSystem/BeltItemRenderer 原样）。
- **接触即消失**: 0 与任一 1 的链坐标距离 ≤ 0.5 格 → 该 0 不绘制。0 永不穿过
  1（用户: "1 盖到 0 上方，1 停止时 0 消失"）；1 堵住时 0 流到它边缘被吞。
  物品以带速平滑移动 → 消失点平滑跟随，无硬切。

## 实现（净删除 ~150 行）

- `BeltPointerPhase.ts`: 整体替换为 `chainVirt(chainId, globalPhase)` 纯函数。
  **PointerPhaseClock 积分器整体删除**（领头内插扫描 / WeakMap 物品内插 /
  换领头 Tick 差 / 首件校准 / 跨段跳过判定——约 150 行状态机）。
- `BeltPointerRenderer.ts`:
  - 删: 领头跟随、同格 floor 隐藏、deadHead/deadTail 占用查询（连同
    BuildingComp/buildings 导入）；
  - 增: 接触消失（物品链坐标快照 ≤0.5）、带身遮罩（每链格矩形并集
    Graphics，格集指纹变化才重建；箭头/白箭头 `sprite.mask` 指向它）、
    端部渐变（尾: 1 @ d ≤ len−0.125 → 0 @ d ≥ len+0.125；头对称——遮罩裁
    几何 + 渐变给半透明，合成参考图的"半透明滑出"观感）。
- `BeltArrowStream.ts`: 不变（槽位几何）；注释同步。

## 为什么闪烁被根治（机制级）

旧架构指针 = "物品队列的导数再积分"：物品侧每个事件（吸收/跨段/换领头/
重建基线断裂）都传导为全链箭头的位置跳变，T2.22~T2.27 五轮修的都是这些
事件的传导路径。新架构 virt 是全局时钟的纯函数——**不存在任何能改变指针
速度/相位的事件**；可见性变化（接触消失、端部出入）全部由物品自己的平滑
移动驱动。诊断脚本 S1~S10 全绿、瞬移计数 0，且不再需要"身份交换帧跳过"
之类的豁免口径。

## 语义变更（相对旧决定的反转，均已用户确认）

## 教训

- 用户的概念模型（"0 和 1 是同一种东西"）直接指向了正确架构——五轮修补
  都在给"箭头跟随队列"这个错误前提打补丁。**当修复越修越多时，应该回到
  用户的需求本源重新推导架构**，而不是继续打补丁。
- "派生量积分"（箭头跟随队列）必然继承源的所有事件噪声；"纯函数"（全局
  时钟）结构性免疫。能纯函数就不要积分。
