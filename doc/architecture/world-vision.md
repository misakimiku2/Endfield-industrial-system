## 0. 一句话总结

> **一个持续存在的无限世界**。玩家在一个世界里慢慢探索、开发、积累，流水线永久保留，不会因"开新关卡"清零。所谓的"关卡/任务" = 世界中某块区域 + 目标，不是独立地图。

## 2. WV-001 世界形态：持续存在的无限世界

### 2.1 决策

游戏世界是**一个持续存在、向任意方向扩展的无限世界**。不是"多张地图之间切换"，也不是"每开一关进一张新图"。

### 2.2 理由

工厂建造类游戏的核心乐趣是**积累**——流水线、产能、优化都是玩家的长期资产。一旦每次开新关卡要重来一遍，乐趣被摧毁（玩家自己的直觉："辛辛苦苦摆放设计的流水线也不用在新开地图后重新来过"）。

### 2.3 对架构的影响

- `World` 设计为**可扩展**（向任意方向生长），而非固定大小容器。
- 占用表、地形表、实体索引都**跟着世界实例走**，不挂全局单例。
- 存档 = **整个世界的快照**（含所有已探索区域、所有流水线、所有远征前哨），不是"每关一个存档"。
- "切地图"概念**不存在**；只有"在同一世界里加载/卸载不同区域"（见 WV-003 Chunk）。

### 2.4 反面

不做：独立关卡地图、关卡间资产清零、每关独立存档槽。这些与"积累"乐趣冲突，明确排除。

## 3. WV-002 地图来源：手工核心 + 程序生成外围

### 3.1 决策

世界地形/资源由两部分组成：

| 区域 | 来源 | 特点 |
|------|------|------|
| **手工核心区**（出生点、任务区、关键剧情节点） | 美术/策划**手工设计** | 体验精心打磨，第一印象好，任务关卡可精确布置 |
| **外围探索区** | **程序生成**（带种子） | 真·无限感，每个玩家世界不同，驱动探索 |

### 3.2 理由

- 纯程序生成：地形质量难保证，出生点体验随机，任务区域无法精确设计。
- 纯手工大地图：不是真无限，有物理边界，改图成本高。
- 混合方案取两者之长：出生点精心设计（低门槛上手），外围探索仍有无限感（深度内容）。

### 3.3 实现路线（分阶段，不一次到位）

| 阶段 | 地图来源 | 数据格式 |
|------|----------|----------|
| **Phase 1–2** | 手工固定地图（demo） | JSON 数据文件（`maps/*.json`） |
| **Phase 3** | 手工核心 + 手工 demo 地图 | JSON，但接口按"地图实例"设计 |
| **Phase 3+ / 5+** | 加入程序生成模块负责外围 | 程序生成 + 种子，与手工核心拼接 |

> **关键约束**：程序生成是一个独立大模块（可能占一整个 Phase），**不在 Phase 1–2 啃**。先用手工地图把核心玩法跑通，再迭代程序生成。

### 3.4 地图数据格式约定（Phase 1–2 即采用）

```jsonc
// maps/demo_01.json
{
  "id": "demo_01",
  "size": { "w": 64, "h": 64 },          // Phase 1-2 仍为有限尺寸
  "spawn": { "x": 32, "y": 32 },          // 出生点
  "terrain": [
    // 非平地 Cell，默认全平地（ground）
    // Phase 1-2 这些字段读了也忽略，仅占位，避免 Phase 3 改 schema
    { "x": 10, "y": 10, "type": "ore_patch", "ore": "copper" },
    { "x": 0, "y": 0, "type": "blocked" }
  ],
  "buildings": [
    // 预放置设备（做关卡预设），Phase 1 可为空数组
    { "def": "furnace", "x": 5, "y": 5, "dir": 0 }
  ]
}
```

> **Phase 1 即采用 JSON 加载**：替换当前硬编码的世界尺寸，让 T1.8 放置 / T1.10 性能测试能加载真地图。

## 4. WV-003 Chunk 系统：提前到 Phase 3

### 4.1 决策（修订 A2 §3.3 / §8）

Chunk（分块加载/卸载）系统**从 Phase 4 提前到 Phase 3**。

### 4.2 理由

文档原把 Chunk 归在 Phase 4（性能优化）。但定了无限世界 + 探索玩法后，Chunk 的性质变了：

- **它不再是"性能优化"，而是"世界模型的地基"**。无限世界没有 Chunk 根本跑不起来——玩家往外走，地图越来越大，内存会爆。
- **资源点散落远处 = 玩家必然走出加载范围**。Phase 3 加资源点时若世界还是"固定大地图一次性全加载"，资源点要么挤在出生点（失去探索感），要么世界大到内存扛不住，两条死路。
- **Phase 4 才做 = Phase 3 先用"假无限世界"撑着，再推翻重做**，典型返工。一次到位更省。

### 4.3 关键解耦：Chunk 不依赖程序生成

即使 Phase 3 所有地图仍是手工设计的，Chunk 依然工作——它只是"按区域加载/卸载"的机制，跟地图数据从哪来无关。所以 Chunk 提前**不绑架**程序生成的进度。

### 4.4 Phase 1 的过渡处理

Phase 1 维持 64×64 固定世界，但做**一个接口预留**：

- `WORLD_WIDTH_CELLS` / `WORLD_HEIGHT_CELLS` 从"全局常量"改为"**地图实例属性**"。
- 占用表、边界 clamp 都读地图实例的属性，不读全局常量。
- 这样 Phase 3 把世界换成 Chunk 化时，不需要扫全代码改硬编码。

> **Phase 1 改动范围**：仅常量→实例属性的改造，不引入 Chunk 本身。✅ 已在 T1.6 落地（`src/game/world/MapInstance.ts`），不破坏 T1.5 进度。

## 5. WV-004 资源点定位：C 派（前期建厂 + 后期远征）

> **⚠️ 已据 A12 EC-006 修订（2026-07 第七次讨论）**：原"玩家亲自远征"语义被排除——管理员世界观下玩家不亲临世界。"远征"改为**任务驱动 + 派居民探索队**。资源点 C 派定位（前期就近 + 后期稀有资源散落远处）不变。

### 5.1 决策（✅ C 派定位不变，远征语义修订）

资源点（矿脉）采用**C 派**玩法定位：

- **出生点附近**：资源管够、就近分布，前期建厂体验好（B 派体验）。
- **外围远处**：稀有/高级资源散落，驱动玩家**派居民探索队**去解锁、建次级基地开采、运回主基地（A 派体验）。

### 5.2 远征方式的修订（依据 EC-006 管理员世界观）

| 原描述（已废） | 修订后（✅） |
|----------------|--------------|
| 玩家亲自远征走出去 | ❌ 排除（玩家不亲临世界） |
| 玩家亲自建分基地、运资源 | ❌ 排除 |
| — | ✅ **任务驱动 + 派居民探索队**：游戏到某阶段/需要某材料时，出现"可派居民探索某区域"的任务，居民出去探索（消耗游戏内时间，有伤亡风险），回来后迷雾解锁，玩家在新区域建次级基地 |
| — | ✅ **次级基地共享全局仓储**（EC-008），不是从 0 开始 |

详见 A12 EC-006（§10）、EC-003（§3.5/3.6）。

### 5.3 理由（决策框架，保留）

| 派别 | 核心乐趣 | 资源点定位 | 与无限世界的关系 |
|------|----------|------------|------------------|
| A 派 | 探索 + 远征 | 散落远处 | 契合，但技术代价最大 |
| B 派 | 建厂优化 | 就近管够 | **矛盾**——没探索就没必要无限 |
| **C 派** | **混合**：前期建厂 + 后期远征 | 近够远稀 | **完美契合**手工核心+程序外围 |

选 C 的理由：
1. B 派与已定的无限世界冲突（资源全在附近，玩家没理由往外走）。
2. C 是 Factorio/Satisfactory 验证过的黄金配方：前期低门槛上手，后期深度内容。
3. **塔防自然落地**——次级基地/矿点需要防御（怪物袭击），塔防系统有真实玩法落点。

### 5.4 衍生约束

C 派 + 管理员世界观下，"远征"= 任务驱动派居民 + 次级基地开采 + 轨道列车运输（见 WV-005）。不再是玩家亲自跑。

## 6. WV-005 远距离物流（✅ 已据 A12 EC-008 全面重写）

> **⚠️ 本节已据 A12 EC-008（经第三~六次讨论精化）全面重写**。原"简化卡车/无人机起步，火车留 Phase 5+"作废。当前方案：**固/液/气分类传输**——固体走全局仓储+矿点开采系统（轨道无人列车），液体/气体走管道（普通管道+地下暗管）。合法性来源是 EC-006 管理员世界观（"管理员调度的自动化载具"，非玩家亲自搬运）。

### 6.1 决策（✅ 重写）

物流按**物品类型分类**，不同类型走完全不同的机制：

| 物品类型 | 基地内传输 | 跨基地/远距离传输 | 全局仓储 |
|----------|------------|-------------------|----------|
| **固体**（矿石/锭/零件） | 传送带（基地内） | **全局仓储**（成品无线共享）+ **矿点开采系统**（轨道无人列车运矿，见 §6.3） | ✅ 成品适用 |
| **液体/气体** | **普通管道**（早期）/ **地下暗管**（后期研发解锁） | **无全局共享**——当地产或物理运输（管道/暗管） | ❌ 不适用 |

### 6.2 固体矿物运输：矿点开采系统（✅ EC-008 §18 定型）

早期固体矿物（矿石）的完整运输链条：

```
矿点(多种矿物,崎岖地形)
  ├─ 基础采矿机(建矿脉上,3×3规格,通电即采)
  │    └─ 短距离无线传输(小范围,默认就有,范围以矿机为中心具体数值留调参)
  │         └─ 把矿无线传到范围内的【矿点储存站点】
  │
  └─ 矿点储存站点(中转仓库,可升级:1车→多车)
       └─ 专用轨道(单一类型,离散铺设像传送带)
            └─ 无人货运列车沿轨道往返(契合"集成工业系统"世界观)
                 └─ 基地储存站点
                      └─ 自动进入【全局仓储】(任何基地可取)
```

**演进**：后期研发解锁**高级采矿机**（长距离无线回仓，耗电多，免规划），替代轨道列车。

**复杂度**：🟡 中偏低。轨道离散铺设像传送带，列车天然沿轨道走无需寻路，可大量复用 A9 传送带机制。

### 6.3 液体/气体运输：管道系统（✅ EC-008 §11.6/§11.7 定型）

| 设备 | 定位 | 复杂度 | 时机 |
|------|------|--------|------|
| **普通管道** | 液体版传送带，复杂拓扑（分流器/汇流器/准入口/管道桥，与传送带同构，A9 §10 已预留） | 🟡 中 | Phase 3b（建议，从 Phase 4+ 提前） |
| **地下暗管** | 极简 A-B 点对点传输，不占地，有距离上限（参考 300m）。研发解锁 | 🟢 低 | Phase 3b 后期或 Phase 5 |

### 6.4 关键排除项

| 排除项 | 原因 |
|--------|------|
| ❌ 完整卡车系统（自由寻路） | 复杂度过高，且管理员世界观下不需要玩家亲自调度 |
| ❌ 有人火车 | 用无人货运列车替代（契合世界观） |
| ❌ 液体/气体全局仓储 | 保留物流玩法深度，忠于工业常识 |
| ❌ 固体地下传送带 | 与全局仓储冲突，徒增复杂度 |

### 6.5 设计语言统一

所有物流手段都有"早期物理（占地/慢/低能耗）→ 后期高级（不占地/快/耗电或研发）"的曲线：

| 物料 | 早期（物理） | 后期（高级） |
|------|--------------|--------------|
| 固体矿物 | 轨道无人列车（低能耗，要规划） | 高级采矿机无线回仓（耗电多，免规划） |
| 液体/气体 | 普通管道（占地） | 地下暗管（不占地，研发解锁） |
| 固体成品（基地间） | — | 全局仓储（全期无线） |

## 7. WV-006 小地图 + 战争迷雾

### 7.1 决策

Phase 3 引入**小地图（Minimap）+ 战争迷雾（Fog of War）**。

### 7.2 理由

无限世界没有小地图，玩家会迷路——"我的主基地在哪""那个铜矿在北边""我的流水线铺多大了"全靠脑子记。小地图是导航刚需。

战争迷雾反过来要求世界有"**已探索/未探索**"概念——否则小地图一开始全亮，探索没意义。两者绑定实现。

### 7.3 实现要点（Phase 3a）

- 小地图：把世界缩放渲染到屏幕角落的小 Canvas / PixiJS Container。
- 战争迷雾：每个 Cell 有 `explored: boolean` 状态，玩家视野（相机可见范围 或 单位感知范围）内的 Cell 标记为已探索。
- 小地图只显示已探索区域，未探索为黑/迷雾。
- 小地图支持点击跳转（点小地图某处 → 主相机移到那）。

## 8. WV-007 关卡/任务语义：区域目标，非独立地图

### 8.1 决策

"关卡/任务" = **世界中某块区域 + 目标**，不是独立地图。

### 8.2 示例

| 传统关卡设计（排除） | 本项目设计（采用） |
|---------------------|-------------------|
| 开新关 → 进新地图 → 从零建厂 | 在已有世界里圈一块区域，给一个目标 |
| 关卡间资产清零 | 玩家资产（流水线、产能、库存）**跨任务持久** |
| 每关一个存档 | 一个世界一个存档，任务进度存在世界里 |

例子："在北部矿区建立日产 100 铜锭的产线"是一个任务。它发生在你已经建好的世界里，你的主基地物流还能支援它。

### 8.3 玩家资产持久性

玩家在一个世界里积累的所有资产——流水线、设备、库存、已探索区域——**永久保留**，不会被任务进度清零。这是 WV-001"积累乐趣"的具体体现。

### 8.4 任务系统的实现时机

任务/目标系统本身（UI、目标追踪、奖励）**不在 Phase 1–3 范围**，留到核心世界 + 物流 + 塔防跑通后再加。本决策只定型"任务 = 区域目标"的语义，避免后期返工成"独立关卡地图"。
