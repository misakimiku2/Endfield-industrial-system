# T2.17 实现笔记 — 仓库口四向旋转（占地宽高互换）

> 2026-09-04。用户反馈：仓库取货口/存货口只能 180° 旋转，要求像精炼炉一样四向（0/90/180/270）旋转。
> 计划卡: implementation-phase-2.md T2.17。

## 1. 背景与根因

T2.12 初版的 180° 两档限制源于 A3 §6 旧约定「旋转后占地不变」：`PortGeometry.rotatePort` 的
「绕占地中心旋转」数学只对**正方形**占地自洽——3×1 占地旋转 90° 后端口会旋出占地（如顶边端口
转到「右侧第 4 列」，而占地根本没有第 2 列），Sprite 视觉与 OccupancyMap 占地也会错位。故当时
`RotationPolicy` 对非正方形占地只给 0°/180° 两档。

## 2. 方案：占地约定修订（3×1 ↔ 1×3）

对齐业界惯例（Factorio 等）：**90°/270° 旋转时占地宽高互换**，0°/180° 不变。新增单一事实源：

```ts
// buildings.ts
export function effectiveFootprint(footprint: Footprint, direction: Direction): Footprint {
  return direction === 90 || direction === 270
    ? { w: footprint.h, h: footprint.w }
    : { w: footprint.w, h: footprint.h };
}
```

所有「占地 × 朝向」的消费方一律改问有效占地，不再各自手写 w/h：

| 消费方 | 改动 |
| --- | --- |
| `PortGeometry.rotatePort` | 改占地互换感知的直算公式（见 §3） |
| `OccupancyMap.occupy/releaseFootprint` | 启用闲置的 `direction` 参数，按有效占地填充/释放 |
| `PlacementSystem` | 预览锚点 `placementFromMouse`、`canPlace`、落盘 anchor 全走有效占地；中心 = 有效占地中心 |
| `RenderSystem` | 设备 Sprite 中心（pos + eff/2，旋转绕该中心恰覆盖占地）、视口剔除 AABB |
| `SelectionSystem` | `pickBuildingAt` 命中 AABB、`buildingScreenPolygon` 选中框四角 |
| `PortHighlightRenderer` | 端口高亮锚容器位置（与 RenderSystem 同数学） |
| `main.ts placeAt` | canPlace 按有效占地；`selectFirstBuilding` 中心同源 |
| `RotationPolicy` | 统一 90° 四档循环，非正方形两档特例删除 |

**SpriteComp 语义保持不变**：恒存 0° 未旋转尺寸（whole Sprite 内容 192×64），90°/270° 的旋转由
渲染侧 `sprite.rotation` 绕有效占地中心完成——旋转后的视觉边界恰好落在互换后的 1×3 占地上
（中心重合 + 尺寸互换 = 精确覆盖），无需为竖放另切纹理。

## 3. rotatePort 公式与等价性

新公式（`dx,dy` 为 0° 朝向下的端口偏移，w×h 为 0° 占地）：

- 0°: `(dx, dy)` 不变
- 90°（顺时针）: `(dx, dy) → (h-1-dy, dx)`，占地变 h×w
- 180°: `(dx, dy) → (w-1-dx, h-1-dy)`，占地不变
- 270°: `(dx, dy) → (dy, w-1-dx)`，占地变 h×w

**对正方形占地（w=h=n）与旧「绕中心旋转」数学逐点等价**（旧式：`rx=-y, ry=x` 再加回中心，
展开即 `(n-1-dy, dx)`）——精炼炉等既有设备端口格零变化，回归零风险。注意 A3 §2.2 规范文档
旧版的 90°/270° 两式标反（与代码顺时针约定不符），本次一并修正并补修订注记。

端口**朝外方向**不受影响：`portOutwardBase`（0° 基准朝向）+ `rotateDirection(base, direction)`
本就与占地无关；仓库口 h=1 的顶/底歧义消解（输入朝下/输出朝上）在旋转后自然给出正确功能面
（90° 取货口朝右接出、90° 存货口朝左供给）。

## 4. 放置预览的关键细节

`refreshPreview` 先算 `worldAngle = screenAngle - viewRotation` → 有效占地，再：

1. `placementFromMouse(mx, my, effW, effH)` —— 鼠标=设备中心，对**互换后**的宽高取整吸附；
2. `preview.position = topLeftWorld + (effW·CELL/2, effH·CELL/2)` —— 预览根节点锚在有效占地中心；
3. sprite 内容仍按 0° 尺寸绘制、`rotation = worldAngle` 整体旋转。

三者合成后，预览蓝色轮廓、占用红绿判定、落盘实体三者像素级重合（B1/B2 断言 + 截图核验）。
