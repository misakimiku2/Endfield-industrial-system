# T2.19 实现笔记 — 存货口接带面统一朝上（与取货口一致）

> 2026-09-04。用户反馈（附截图）: 仓库取货口和存货口的"创建方向都一样，都是↑"，但存货口
> 实际方向反了——传送带只能从下方连接。计划卡: implementation-phase-2.md T2.19。

## 1. 根因

2026-09-02 对 h=1 占地的端口朝向消歧拍板为「输入口朝下（90）、输出口朝上（270）」
（`portOutwardBase` 的 `port.type === 'input' ? 90 : 270` 分支）。当时两台仓库口各有
3 个口、且玩家里"取货口出料向上/存货口从下方进料"尚可记忆。T2.18 单端口化后问题凸显:

- 两台设备**外观完全相同**（共用 Depot.svg、同位置蓝面板、同 billboard LOGO），
  创建模式高亮也一致——玩家自然认为接带方向相同；
- 实际上存货口接带面在**底侧**，按取货口直觉从上方拖带永远接不上（T2.16 的 dock
  重定向会把路径绕到设备下方，形成用户截图里的怪异 S 形）。
  指示与行为相反 = "方向实际上是反了"。

## 2. 方案: 行为向外观对齐（用户拍板）

`portOutwardBase` 的 h=1 分支一律返回 270（朝上），删除按端口类型分叉:

```ts
if (footprint.h === 1) return 270; // T2.19: 接带面统一顶侧
```

效果（0° 朝向）:
- 取货口: 带从上方接出（不变）；
- **存货口: 带从上方落入**——供给格在中口正上方，带方向朝下（90）指入端口，
  物品"落"进设备顶面；
- 两台设备接带面一致，用户截图的 S 形绕底接法不再需要，直接从上方接入即可。

旋转语义与所有设备一致: R 一次 90° → 接带面朝右；180° → 朝下（旧"从下方接线"
布局用 180° 的存货口即可原样兼容）。

## 3. 连锁适配（"从下方接线"的既有场景全部转 180°）

| 场景 | 改动 |
| --- | --- |
| demoT212 | 存货口 `placeAt('depot_loader', 5, 0, 180)` |
| demoT210 场景A/B | 存货口 (5,2)/(5,1) 同上 180° |
| verify-t212-depot C 节 | 两处 loader place +180（供给带 (6,11)/(6,1) 布局不变） |
| verify-t212-browser | 存货口放置前 R×2（真实键鼠路径） |
| verify-t217-browser | C 节存货口 90°→270°（功能面朝左，保持左侧供带布局） |
| 15i/15j 断言 | 存货口 90° outward 期望 180→0（输入口与输出口同向旋转） |

逻辑层零改动——outward 是唯一事实源，findFeederBelt/dockRedirect/dockInfoOf/
applyDepotStatus 全部自动跟随。

## 4. 验证

- `verify-t212-depot.ts` 53/53（含 15j 新朝向断言；C 节两处存货口 180° 场景全链路照常）。
- `verify-t217-rotation-browser.mjs` 17/17（90° 取货口右出 → 270° 存货口左入，端到端流通）。
- 用户场景正向用例: 两台 0° 并排、S 形带从取货口上方绕到存货口上方落入 →
  出货 7 件/进料 ≥1（`t19-top-connect-flow.png` 截图，即用户截图布局的可用版）。
- demoT212、demoT210 一键测试全流程通过（180° 存货口）。
- `tsc --noEmit` 绿。

## 5. 备注

- 精炼炉等 h≥2 设备走多行占地的边判定（底行输入口朝下），不受影响——"输入口朝下"
  的原语义只存在于 1 行高的仓库口，本次仅收回该特例。
- 若后续想让两台设备外观也区分方向（如存货口 LOGO 镜像/箭头指示），属素材任务
  （Depot_Unloader_logo.svg / Depot_Loader_logo.svg），代码侧已无阻碍。
