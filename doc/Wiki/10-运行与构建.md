# 10 · 运行与构建

> 上一篇：[09-依赖关系](09-依赖关系.md) ｜ 下一篇：[11-关键类与函数速查](11-关键类与函数速查.md)

## 1. 环境要求

- **Node.js**（需支持 `node --experimental-strip-types`，即 Node ≥ 22.6，用于直跑 TS 脚本）
- npm
- Windows / macOS / Linux 均可（桌面打包另需 Rust 工具链 + Tauri 系统依赖，仅 `npm run tauri` 需要）

## 2. 首次运行（三步）

```bash
npm install
npm run pack-assets      # ★ 必须！生成 public/spritesheets/（.gitignore 不入库）
npm run dev              # http://localhost:5173
```

> 跳过 `pack-assets` 的后果：`Assets.load('/spritesheets/devices.json')` 404，启动失败或全部纹理缺失。
> 判据：dev 控制台 T1.3 验收会打印 `transport_belt` 等三个关键纹理是否可取。

## 3. npm 命令一览

| 命令 | 实际动作 | 说明 |
|---|---|---|
| `npm run dev` | `vite` | dev server @ **5173**（`strictPort: true`——端口被占直接报错退出，杜绝多实例漂移） |
| `npm run build` | `tsc && vite build` | 先全量类型检查（noEmit），再产 `dist/`；target es2020；pixi.js 单独分包 |
| `npm run preview` | `vite preview` | 本地预览 `dist/` 构建产物 |
| `npm run pack-assets` | `node --experimental-strip-types scripts/pack-assets.ts` | SVG/PNG → `public/spritesheets/{devices,items,ui}.{png,json}`；详见 [08-数据与资产](08-数据与资产.md) |
| `npm run tauri dev` | `tauri dev` | 自动先跑 `npm run dev`，再开 1280×720 WebView 窗口 |
| `npm run tauri build` | `tauri build` | 先 `npm run build` 再 Rust 编译打包（bundle targets: all） |

## 4. 端口固定策略（5173）

`vite.config.ts` 设 `strictPort: true`：端口被占用 = 有残留 dev 实例，**直接报错退出**而不是自动 +1 换端口（防止多个 dev server 跑着不同版本代码的排查混乱）。处置：

```bash
netstat -ano | findstr ":5173"     # 找 PID（Windows）
taskkill /PID <pid> /F
```

## 5. Tauri 桌面端（src-tauri/）

| 项 | 值 |
|---|---|
| 产品名 / 标识 | 集成工业系统 / `com.mingzhou.industrial` |
| 窗口 | 1280×720，可缩放，非全屏 |
| 前端接入 | `devUrl: http://localhost:5173`（dev）、`frontendDist: ../dist`（build） |
| 权限 | capabilities 仅 `core:default`（最小权限） |
| 自定义命令 | 无——Rust 侧零自定义 IPC，前端与 Web 版完全一致 |

日常开发用 `npm run dev`（浏览器）即可；桌面壳只在验证发布形态时使用。

## 7. 常见问题（FAQ）

| 现象 | 原因与处置 |
|---|---|
| 启动即白屏/纹理缺失 | 未跑 `npm run pack-assets`（spritesheets 不入库）。跑一次即可 |
| `npm run dev` 报端口占用 | strictPort 故意为之；按 §4 找到残留实例 kill |
| 切后台再回来仿真"跳进度/慢放" | 设计行为：rAF 停转后由 250ms 定时器按真实流逝时间补 Tick，accumulator 钳制 1000ms（最多追 20 Tick），保证慢放不冻结 |
| 改了 SVG/物品 PNG 没生效 | 打包产物不热更新，需重跑 `npm run pack-assets` 并刷新页面 |
| 新增配方没出现 | 检查 CSV：设备名需匹配 `BuildingDefinition.name`（或 id 映射），物品名需在物品注册表；不匹配会进 `SkippedRecipe` 并打 warn（`__game.listRecipes` 核对） |
| 传送带看着连上端口但不吸入 | 三处同口径判定：必须是**端口朝向侧**的供给格且段方向为逆朝向（侧向横穿不算）。用 `__game.portStatus()` 看 connected |
| 预览红色但看不出哪格冲突 | 红色 = `checkPathValid` 失败（越界/占用/绕回起点）；终点格占用不阻断寻路，只是染红提示 |

## 8. 性能验收基准

- 目标：同屏 300–500 实体 @60FPS（Phase 1 验收线：100 设备 avg/p95 FPS ≥ 55）；
- 工具：`__game.runFpsBenchmark()`（min/avg/max/p95 + 内存增量）、`fillBenchmarkDevices()`（21×21=441 台 3×3 密铺）；
- 当前实测参考：九宫格烘焙后 100×3×3 + 50×6×6 avg 144 FPS（见 `doc/nine-slice-device-base.md` §11.2）。
