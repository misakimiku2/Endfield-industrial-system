## 0. 一句话总结

> **工厂生产工业品 → 居民（人口）消耗工业品 → 人口提供劳动力（探索/研发）→ 探索消雾发现新资源/研发解锁新科技 → 新资源/新科技反馈回工厂**。这是一个以"人口"为核心驱动力的内部经济闭环。市场作为补充渠道，创造模式作为独立沙盒。

## 1. 已识别的核心循环构想（EC-001）

### 1.1 循环图

```
        工厂生产工业品（食物/装备/日用品…）
                    │
                    ▼
              居民（人口）消耗
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
    消耗物品     派去探索     派去研发
   （被动需求）  （主动消雾）  （主动解锁）
                    │           │
                    ▼           ▼
            消散迷雾/发现     解锁科技/
            高级资源区        升级装备
                    │           │
                    ▼           ▼
              新资源/新需求 ← 货币（升级用）
                    │
                    ▼
            反馈回工厂（新配方/新产能需求）
```

### 1.2 关键设计洞察

| 洞察 | 说明 |
|------|------|
| **人口是需求方** | 完美解决"谁在买玩家生产的东西"——居民消耗是稳定、可预测的需求，不需要虚拟 NPC 经济的复杂模拟 |
| **人口是劳动力池** | 居民不只是消耗，还可分配去探索（消雾）和研发（解锁），是多功能资源 |
| **探索有代价** | 派居民探索要消耗工业品（装备/补给），探索变成有策略的选择，不是免费行为 |
| **工厂有了消耗出口** | 工厂游戏经典后期问题"产能爆炸无处用"被解决——产能喂给人口/探索/研发 |
| **市场是补充渠道** | 探索所需工业品可自己造也可买，给玩家提供"免远征"选项 |

### 1.3 为什么这个循环是健康的

工厂游戏的核心驱动力是"**让产能有意义**"——玩家扩张产能必须有一个对应的消耗出口，否则后期无聊。Factorio 用"科技消耗资源"、Satisfactory 用"电梯里程碑"做这件事。本项目的"**人口消耗 + 探索/研发投入**"是同一类机制，但更丰满：它把消耗、探索、成长绑成了一个自洽闭环。

## 2. EC-002 创造模式（✅ 已定型）

> 本节内容已定型，可作为实施依据。

### 2.1 决策

提供一个**创造模式（Creative Mode / Sandbox）**，作为主线（无限世界）之外的独立游戏模式。

### 2.2 模式特征

| 特征 | 创造模式 | 主线模式（无限世界） |
|------|----------|---------------------|
| 资源 | **无限**（建造不消耗） | 有限（要采集/生产） |
| 地形 | **无限制**（纯平地，无矿脉/障碍） | 有矿脉/障碍/不可建造区 |
| 区域 | **有限大小**（不能无限铺） | 无限世界 |
| 目标 | 纯粹搭流水线的模拟器 | 完整游戏循环（采集→生产→探索→塔防） |
| 系统 | 关闭资源消耗、关闭地形限制、关闭塔防 | 全部启用 |

### 2.3 定位

创造模式 = **给玩家纯粹搭建生产线的模拟器**。不需要管资源采集、远征、塔防，专注产线设计。类似 Factorio / Satisfactory / Mindustry 的沙盒模式。

### 2.4 实现要点

- **与主线共用同一套引擎**，通过 `GameMode` 开关控制各 System 行为：
  ```ts
  type GameMode = 'main' | 'creative';
  // 各 System 读 GameMode 决定是否跳过某些逻辑
  // 例如 ResourceConsumptionSystem 在 creative 模式下跳过
  ```
- **建造区域有限大小**：复用 `MapInstance.widthCells/heightCells`（A11 WV-003 §4.4）。主线模式这俩是"初始已生成区域"，创造模式这俩就是"建造硬边界"。
- **多档区域可选**：玩家进入创造模式时选区域大小（小/中/大）。

### 2.5 区域大小档位（✅ 已定型：多档可选）

| 档位 | 尺寸 | 适合场景 |
|------|------|----------|
| 小 | 64×64 | 小型演示、教学 |
| 中 | 256×256 | 完整中型工厂（推荐默认） |
| 大 | 512×512 | 巨型产线网络（需视口剔除到位） |

### 2.6 实现时机

创造模式依赖核心建造系统（Phase 1–2 的设备放置/流水线）成熟后才能做。**初步排期在 Phase 4 之后**（核心玩法跑通后作为独立模式加入），不进 Phase 1–3。

## 3. ⚠️ 待定型：探索方式（EC-003）

> **这是最关键的待定型决策**，决定了游戏的核心手感，且与 A11 WV-004/WV-005（资源点/远征物流）互相影响。本节记录三种方案的对比，供后续讨论会话决策。

### 3.1 背景

玩家讨论中同时出现了两种探索构想，它们是**不同的核心玩法**，不能同时是主线：

- **构想一（上轮 A11 定的）**：玩家亲自远征，走出去建分基地、运资源回来（Factorio 式）。
- **构想二（这轮新提出的）**：派居民去探索，居民消雾、带回资源（经营模拟式）。

### 3.2 三种方案对比

#### 方案 A：纯玩家亲自远征（Factorio / Satisfactory 式）

**一局游戏体验**：玩家造装备 → 亲自走出主基地 → 迷雾在玩家周围消散 → 发现远处矿 → 亲自走过去建采矿机+仓库 → 解决运输（长传送带/铁路）→ 运输线/前哨被袭击时亲自跑去防御 → 来回奔波管理分布式工业帝国。

**手感关键词**：身临其境、奔波、空间感强、操作密集。

| 优点 | 缺点 |
|------|------|
| 极强的"经营真实帝国"代入感 | 操作量大，中后期来回跑累 |
| 无限世界意义最大化 | 门槛高，新手易迷路/被劝退 |
| 塔防天然落点（守运输线/前哨） | 节奏慢，大量时间在赶路 |
| 长距离物流有真实价值 | **跟人口系统接不上**——居民没活干 |

#### 方案 B：纯派居民探索（经营/模拟 式）

**一局游戏体验**：玩家基本不离开主基地 → 造工业品喂居民 → 打开远征面板分配居民+装备派去北方 → 探索后台发生，过段时间远征队带回情报+资源 → 小地图迷雾消散 → 决定建分基地还是派采矿队 → 分基地/前哨抽象管理（派居民运营），不亲自建造。

**手感关键词**：经营、统筹、低操作、重策略。

| 优点 | 缺点 |
|------|------|
| 操作量小，专注建厂+管理+决策 | **无限世界意义大打折扣**——玩家不离主基地，世界大部分区域只在小地图上 |
| 人口系统完美落地 | 塔防落点弱（玩家不亲自去，前哨被袭要不要管？） |
| 节奏舒服，适合休闲/手游 | 代入感弱，一切靠面板数字 |
| 与市场衔接自然 | 重心可能从"造产线"漂移到"管人口" |

#### 方案 C：混合（近处亲自 + 远处派居民）—— AI 推荐

**一局游戏体验**：近处（主基地周围）玩家亲自跑消雾、建厂；远处（视野外）派居民远征队消雾、带回资源；玩家可选择亲自去远处建前哨（深度）或派居民托管（轻松）。

**手感关键词**：灵活、可选深度、兼顾两类玩家。

| 优点 | 缺点 |
|------|------|
| 吸收 A 和 B 的优点 | **开发量最大**（两套系统都要做） |
| 无限世界有意义 + 人口系统有意义 | 设计复杂（亲自 vs 居民产出怎么平衡） |
| 难度分层（近处主线，远处进阶） | 玩家可能困惑"该亲自还是派居民" |
| 塔防接得上（亲自守+居民自守） | |

### 3.3 总览表

| 维度 | A 纯亲自 | B 纯居民 | C 混合 |
|------|----------|----------|--------|
| 核心手感 | 身临其境、奔波 | 经营、统筹 | 灵活、可选 |
| 操作量 | 大 | 小 | 中 |
| 无限世界意义 | 最强 | 弱 | 强 |
| 人口系统 | 浪费 | 完美 | 完美 |
| 塔防落点 | 天然 | 弱 | 好 |
| 市场角色 | 边缘 | 核心 | 中等 |
| 开发复杂度 | 高 | 中 | 最高 |
| 目标玩家 | 硬核工厂沙盒 | 休闲经营 | 广泛 |

### 3.4 AI 推荐：长期走 C，开发路径走 A→C 演进

1. **先做 A**（玩家亲自远征）：与 A11 已定方向一致（Phase 3b），不返工，上线即可玩。
2. **后补 B 的远征队部分**作为 A 的补充（进阶玩法）：给玩家"远处太远不想亲自跑，派居民去"的选项。
3. **逐步演变成 C**：玩家有选择，近处亲自、远处居民。

**理由**：直接上 C 风险大（开发量爆炸+平衡难）；先 A 后补 B 是渐进式，每步可玩可发布；B 作为 A 的减负选项引入，定位清晰不打架。

> **⚠️ 此选择最终由玩家决策。** 决策后需同步修订 A11 WV-004（资源点定位）、WV-005（远距离物流）的相关章节。

### 3.5 ⚠️→✅ 管理员世界观（EC-006，本轮澄清，待写入正式条款）

> 本节是 2026-07 第二次讨论的**关键澄清**，从根本上重塑了 EC-003 的选择空间。

#### 3.5.1 世界观设定

- **玩家身份**：明日方舟：终末地的"**管理员**"，操作的是一个游戏设定内称为"**集成工业系统**"的软件（实际上就是本游戏）。
- **玩家不亲临其境**：玩家永远在"操作台/界面"后面，**不进入世界**，不是世界里的一个角色。
- **视角对应**：游戏是**俯视网格**，因为玩家看的是"集成工业系统"的规划界面，不是某个角色的眼睛。这让网格俯视有了**世界观合法性**，不是随便选的美术风格。
- **玩家做的事**：规划（建流水线）、管理（居民的衣食住行）、决策（派居民探索/研发）。
- **忠于原作**：明日方舟：终末地的管理员本来就是"远程指挥"角色，不是冲锋陷阵的战士。本设计忠于原作设定。

#### 3.5.2 这个世界观如何化解 EC-003 的矛盾

EC-003 原列三种探索方式（A 亲自 / B 居民 / C 混合）。管理员世界观一经确立，**A（玩家亲自远征）被根本排除**——因为玩家不是角色，不存在"亲自跑"的语义。

| EC-003 原方案 | 在管理员世界观下的状态 |
|---------------|------------------------|
| A 纯玩家亲自远征 | ❌ **根本排除**（玩家不进入世界） |
| B 纯派居民探索 | ✅ **唯一符合世界观的方案** |
| C 混合 | ❌ 不成立（A 部分被排除） |

因此 **EC-003 实际上已收敛为 B**。下面的探索流程是玩家进一步细化的形态：

#### 3.5.3 任务驱动的居民探索流程（玩家描述）

```
1. 游戏到某阶段 / 需要某材料 → 出现"可派居民去探索某区域"的任务/提示
2. 玩家接受任务，分配居民（+ 所需工业品：装备/补给）派出去
3. 居民自己出去探索（玩家不操作）
4. 探索消耗【游戏内时间】（玩家可用 2×/4× 加速；玩家在基地继续建厂的同时探索在进行）
5. 探索完成 → 居民回来汇报 → 地图迷雾解锁
6. 玩家在新解锁区域建【次级基地】（继续规划流水线）
7. 以此类推，逐步把世界往外推
```

#### 3.5.4 该世界观带出来的衍生系统

| 衍生系统 | 说明 | 当前状态 |
|----------|------|----------|
| **任务系统**（进度主控） | 触发探索、引导节奏。是游戏进度的主要驱动 | 待细化 |
| **次级基地机制** | 解锁区域后建新基地，多基地并存。基地关系见 EC-007 | 待定型 |
| **居民探索任务** | 派出去→游戏内时间消耗→回来汇报→解锁迷雾 | 流程已清晰，细节待细化 |
| **基地间物流** | 替代"远征物流"，是"管理员指挥的开发工具"（卡车/无人机），不是玩家代办 | A11 WV-005 已规划，世界观赋予其合法性 |

#### 3.5.5 对 A11 的反向影响（待 EC-006 正式定型后修订）

管理员世界观定型后，A11 以下决策需要修订：

| A11 决策 | 需修订为 | 原因 |
|----------|----------|------|
| WV-004 资源点 C 派（含玩家亲自远征） | 资源点仍 C 派（前期就近 + 后期远），但**远征改为任务驱动 + 派居民**，不是玩家亲自 | 玩家不亲临 |
| WV-005 远距离物流 | 方向不变（简化物流起步），但**语义从"玩家亲自运"变为"管理员调度"** | 同上 |

### 3.7 ⚠️ 待定型：多基地关系（EC-007，本轮新增）

> **⚠️⚠️ 本节已作废 —— 见 EC-008（§11.4）**。EC-007 的三方案对比（相对独立 / 分工协同前哨 / 统一布局）已被 EC-008 的"方案 4：全局仓储共享"取代。本节保留仅为历史讨论记录，实际设计以 EC-008 §11.4 为准。
>
> **读者注意**：以下内容是作废前的原始讨论，阅读无意义。请直接跳至 §11（EC-008）查看当前设计。

> 管理员世界观（EC-006）确立后，"探索解锁新区域 → 建次级基地"是核心循环。但**主基地与次级基地是什么关系**尚未定型，这直接决定物流系统的复杂度、玩家的操作量、以及游戏的积累感。本节记录三种方案的对比，供下轮决策。

#### 3.7.1 共同前提

无论哪种关系，"次级基地"都意味着玩家在新解锁的区域**重新进行规划/建设**。区别在于"建什么、跟主基地什么关系"。

#### 3.7.2 方案 1：相对独立（各自产各自用）

- 主基地产 A 类，次级基地产 B 类，**两个基地各自完整的工厂**，自采自产自耗。
- 基地间**不直接连物流**，通过"任务交付"或"市场"交换。
- 玩家体验：每解锁一个新区 = 开一局新游戏；多个基地是并行的小游戏。

| 优点 | 缺点 |
|------|------|
| 物流系统最简单（无基地间物理物流） | **重复劳动**——每基地从头搭基础产线，中后期腻 |
| 每基地规模可控，性能压力小 | 积累感被稀释（几个小厂而非一个大厂） |
| 多点开花的经营感，适合手游碎片化 | 基地间协同比直接连物流低效 |

代表：辐射避难所（多个避难所）、手游的"分城"。

#### 3.7.3 方案 2：分工协同 / 前哨模式（AI 推荐）

- **主基地是核心**：生产设备、核心部件、研发，产线最复杂。
- **次级基地是"前哨"**：主要功能是**就地采矿**（高级矿在远处），把矿/初级产品**运回主基地**。
- 基地间**有物流连接**（卡车/无人机/火车），把前哨产出运回主基地，主基地也可能把设备/补给运到前哨。
- 玩家体验：主基地是主要精力所在（深度优化产线），前哨是轻量扩展（采矿+装卸+防御）；物流网络本身是玩法核心。

| 优点 | 缺点 |
|------|------|
| **积累感最强**——主基地越建越大，成就感来源 | 物流系统复杂度最高（基地间远距离运输） |
| 物流系统有真实价值，是核心玩法而非装饰 | 主基地性能压力大（复杂产线集中） |
| 塔防天然落点（前哨守采矿/运输 + 主基地守推进） | 物流网络设计不好会让玩家挫败（堵车/运力不足） |
| **Factorio/Satisfactory/DSP 验证过最成功的模式** | |

代表：Factorio（主基地+矿区前哨+火车）、Satisfactory（主基地+卫星工厂+卡车/火车）。

#### 3.7.4 方案 3：统一布局（多个基地只是一个大工厂的分区）

- 严格说**没有"基地"概念**，世界是一整块大画布，玩家在不同区域建不同产线分区。
- 所有分区**共享一个统一物流网络**，物品在全图自由流动（物流配送系统）。
- 玩家体验：经营一个超大型工厂，分布很广；物流是全局优化。

| 优点 | 缺点 |
|------|------|
| 最灵活，玩家可任意组织产线 | **物流系统最复杂**（全图自动配送，巨型工程） |
| 没有"基地"概念包袱，纯工厂沙盒 | 失去"基地"节奏感，玩家易迷失 |
| | 性能压力最大（全局物流计算） |
| | **跟"任务解锁区域"接不上**——区域无基地概念，解锁意义模糊 |

代表：戴森球计划（物流塔）、异星工厂后期（全局物流）。

#### 3.7.5 总览表

| 维度 | 1 相对独立 | 2 分工协同（前哨）⭐ | 3 统一布局 |
|------|-----------|---------------------|------------|
| 核心手感 | 多个小游戏并行 | 一个大基地 + 多个采矿前哨 | 一个超大工厂分区 |
| 积累感 | 弱（几个小厂） | **最强** | 中（无里程碑） |
| 物流系统复杂度 | 🟢 最低（无基地间物流） | 🟡 中（基地间物流是玩法） | 🔴 最高（全图自动配送） |
| 重复劳动 | 🔴 高（每基地从头建） | 🟢 低（前哨轻量） | 🟡 中 |
| 塔防落点 | 每基地各自守 | 主基地 + 前哨都守 | 全局防御 |
| 跟"任务解锁区域"契合度 | 🟢 高 | 🟢 高 | 🔴 低 |
| 性能压力 | 🟢 低（分散） | 🟡 中（主基地密集） | 🔴 高 |

#### 3.7.6 AI 推荐：方案 2（分工协同 / 前哨模式）

理由：

1. **工厂游戏验证过最成功的模式**——Factorio/Satisfactory/DSP 都是这个套路，玩家口碑最好。
2. **积累感最强**——工厂游戏核心乐趣。方案 1 稀释它，方案 3 模糊它。
3. **与"管理员 + 任务解锁"世界观完美契合**：
   - 管理员远程指挥，主基地是"指挥部所在"，前哨是"派出去开发的资源点"。
   - 任务解锁新区 → 玩家建**轻量前哨**（采矿+装卸+防御）→ 矿运回主基地深加工。
   - 符合"管理员不亲临，但通过建设开发世界"的设定。
4. **塔防天然落地**——玩家已选"保卫基地"，前哨模式下 = 前哨防御（采矿点常被袭）+ 主基地防御（敌人推进）。
5. **物流复杂度可控**——比方案 3 简单，且 A11 WV-005 已规划"简化物流起步（卡车/无人机）"，正好用在前哨运输上。**方案 2 印证了 A11 WV-005 物流决策的正确性，无需修改 A11**。

#### 3.7.7 有趣的副产品：世界观让"物流"有了理由

在方案 2 下，"管理员不亲临"反而让物流系统**更有意义**：

- 玩家不能亲自扛东西过去（不是角色），所以**必须**靠物流系统（卡车/无人机）运送。
- 物流系统是"管理员指挥的开发工具"，不是玩家的代办。
- 这让卡车/无人机/火车的设计有了世界观合法性——它们是"集成工业系统"里的调度模块。

**管理员世界观（EC-006）和方案 2（EC-007）是互相强化的。** 这比 Factorio 那种"玩家亲自铺传送带"更符合"管理员操作软件"的设定。

> **⚠️ 此选择最终由玩家决策。** 玩家本轮要求"先听三种玩法后果再决定"，已在本节讲透。决策后更新本节为正式条款，并据此调整 A11 WV-005 / Phase 3b 物流部分。

## 4. ⚠️ 待定型：人口定位（EC-004）

### 4.1 待定问题

"人口"在游戏里是核心驱动力还是次要系统？

| 选项 | 说明 | 影响 |
|------|------|------|
| **核心驱动力** | 人口=产能消耗出口+探索/研发劳动力，整个游戏围绕"养人口"展开 | 经济循环以人口为中心，市场/研发都服务于此 |
| **次要系统** | 人口只是个数字指标，不是核心循环，核心还是建厂优化 | 人口轻量化，市场/探索另找驱动 |

### 4.2 AI 倾向：核心驱动力

理由：工厂游戏最稀缺的是"让产能有意义的消耗出口"。人口作为消耗出口 + 劳动力，天然填了这个缺口。如果只是次要系统，等于浪费了这个设计的潜力，且工厂后期仍会面临"产能爆炸无处用"问题。

> **依赖**：此决策跟 EC-003（探索方式）绑定——如果选 B/C（派居民探索），人口必然是核心；如果选 A（纯亲自），人口会退化为次要。

## 5. ⚠️ 待定型：市场角色（EC-005）

### 5.1 待定问题

市场是"主舞台（股市式动态价格）"还是"调节阀（静态基准价+缓慢漂移）"？

### 5.2 背景

玩家最初设想是"股市式"动态价格（基础价 + 供需波动）。讨论中识别出：在有了"人口消耗"作为主需求方之后，动态市场的角色应该重新评估。

### 5.3 两种方案

| 方案 | 说明 | 风险 |
|------|------|------|
| **主舞台（股市式）** | 价格随供需剧烈波动，体验刺激 | 极难平衡；与人口消耗叠加会失控；单玩家经济难自然稳定 |
| **调节阀（推荐）** | 人口消耗是主需求，市场只做补充买卖，静态基准价+缓慢漂移 | 体验平淡，但可控、可平衡 |

### 5.4 AI 倾向：调节阀

理由：
- 人口消耗已经是稳定的需求主体，价格波动主驱动力已被人口吃掉。
- 股市式波动 + 人口消耗叠加，两套需求系统互相干扰，极难平衡。
- 把"动态"留给"人口需求随发展变化"（可设计、可预测），市场本身保持稳定。

### 5.5 已识别的根问题（无论选哪个都要解决）

| 根问题 | 说明 |
|--------|------|
| **需求方** | 已由"人口消耗"解决（EC-001），不需要虚拟 NPC 经济 |
| **货币出口** | 玩家赚货币能干嘛？已识别候选：买资源、买扩张基建（非"买地权"，见 §6）、升级设备/研发。需在后续会话细化 |
| **远征 vs 市场边界** | 市场太方便→远征没意义；远征太必需→市场没用。需在 EC-003 定型后定义边界 |

## 6. 已识别的衍生约束（讨论中确认的）

### 6.1 货币出口：不是"买地权"，是"买扩张基建"

玩家讨论中提到"买土地/扩张权"。但与 A11 无限世界冲突——地是无限的，不需要买。**重新定位为"买扩张基建"**：

- 无限世界里，远处的地是未开发状态（迷雾、无道路、无电力覆盖）。
- 玩家花货币"建设前哨基地/铺设基础设施"，才能在那块地有效运作。
- 这样货币出口是"基建投入"，不是"地权"，与无限世界不冲突，且与塔防（前哨要防御）接上。

### 6.2 产能与消耗的平衡

工厂产能可无限扩张，人口增长有限。需设计"**人口随玩家进度增长**"机制，形成"产能扩张 → 养更多人 → 需求更大 → 倒逼产能再扩张"的正循环，避免：
- 产能 > 消耗：东西堆成山没人要（工厂游戏经典后期问题）。
- 消耗 > 产能：前期被人口需求逼疯，失去建厂悠闲感。

## 10. ✅ EC-006 管理员世界观（正式条款，第七次讨论定型）

> **本节为正式条款（2026-07 第七次讨论定型）。** EC-006 是本文件最核心的根决策，定型后触发 EC-003 升级、A11 WV-004/WV-005 修订。玩家身份、视角、职责边界全部锁定。

### 10.1 世界观核心（✅ 定型）

- **玩家身份**：明日方舟：终末地的"**管理员**"。
- **操作对象**：一个游戏设定内称为"**集成工业系统**"的软件（实际上就是本游戏）。
- **玩家不亲临其境**：永远在"操作台/界面"后面，不是世界里的角色，不进入世界。
- **网格俯视视角的合法性**：玩家看的是"集成工业系统"的规划界面，所以是网格俯视。这让美术/交互风格有了世界观依据（偏管理工具感，非角色扮演感）。
- **忠于原作**：明日方舟：终末地的管理员本来就是远程指挥角色，不是战士。

### 10.2 玩家职责边界（✅ 定型）

| 玩家**能**做（管理员职责） | 玩家**不能**做（超出管理员身份） |
|----------------------------|----------------------------------|
| 规划建设（放设备、铺轨道、建产线、规划防御布局） | ❌ 亲自进入世界当角色 |
| 管理人口（分配探索/研发、看人口指标） | ❌ 亲自战斗（不操作任何战斗单位） |
| 决策（派居民探索、选研发、调度列车/资源） | ❌ 亲自采集/运输（都由设备自动） |
| **使用技能**干预局势（见 §10.3） | ❌ 操作塔防炮台（炮台自动战斗） |

### 10.3 塔防与技能系统（✅ 第七次讨论定型）

> **关键澄清**：塔防炮台是**纯自动战斗**，玩家**不操作**任何炮台。玩家的干预手段是**技能**。

- **塔防炮台**：放置后自动索敌、自动射击（A1 TurretSystem 已规划）。玩家不操作单个炮台。
- **玩家干预 = 技能**：玩家通过"集成工业系统"的软件功能释放技能，影响战局。
  - 技能**数量不多**（不是技能繁多的动作游戏）。
  - 候选技能方向（待细化）：
    - 快速清理一个范围内的怪物（AOE 清场）
    - 延缓怪物的进攻速度（减速）
    - 其他战术/支援类技能（待设计）
- **技能的合法性**：技能是"集成工业系统"的软件功能（如"调用轨道轰炸""启动力场减速"），不是管理员亲自下场。契合世界观。
- **技能资源**：技能消耗什么？（货币？能量？冷却？）待 Phase 3c 塔防细化。

### 10.4 派生结论（✅ 定型）

## 11. ✅ EC-008 全局仓储 + 无线物流（路线 A，本轮定型）

> **本节为正式条款。** 玩家在第三次讨论中明确定型物流路线，忠于原作《明日方舟：终末地》。

### 11.1 决策

游戏物流采用**路线 A：全局仓储 + 无线传输**（仅限固体）。不是路线 B（物理运输）。

> **⚠️ 第四次讨论修订（2026-07）**：原第三次讨论定"全局仓储覆盖所有物品，卡车/火车不做"。本次修订为：**全局仓储只覆盖固体**，**液体/气体不走全局仓储，必须走管道**。理由：① 保留部分物流玩法深度（避免路线 A 让游戏过浅）；② 忠于工业常识（液体/气体现实中也必须管道）；③ 现有 A9 §10 已预留管道系统，本修订与其契合。详见 §11.6。

### 11.2 物流形态（按物品类型分类）

> **第四次讨论修订**：物流形态按物品类型分为两套，固体和液体/气体走完全不同的机制。

**固体的物流形态**：

> **⚠️ 第六次讨论精化（2026-07）**：固体矿物运输形成完整的"矿点开采系统"——基础采矿机短距离无线 + 储存站点中转 + 专用轨道无人货运列车运输。详见 §18 矿点开采系统专题。

| 组成 | 形态 | 阶段 |
|------|------|------|
| **全局仓储（固体成品/半成品）** | 所有基地（主 + 所有次级）**共用一个全局仓库**。固体物品任何基地存入，任何基地可取。忠于原作设定。 | 全期 |
| **基础采矿机 + 短距离无线（固体矿，早期）** | 普通采矿机**只能建在矿脉上**。默认有**短距离无线传输**（小范围），把采集的矿无线传到范围内的**矿点储存站点**。解决崎岖地形无法车辆对接的问题。 | **早期**（一开始就有） |
| **矿点储存站点** | 在矿机无线范围内建的中转仓库。接收矿机无线传来的矿。**可升级**（提升列车效率/车数）。 | 早期 |
| **专用轨道 + 无人货运列车** | 矿点储存站点 ↔ 基地储存站点之间铺**专用轨道**（离散铺设，像传送带）。**无人货运列车**沿轨道往返运输（契合"集成工业系统"世界观，无需驾驶员）。单一轨道类型，升级站点提效率。 | 早期 |
| **基地储存站 → 全局仓储** | 列车运到基地储存站的矿，**自动进入全局仓储**（任何基地可取）。全局仓储是矿物运输的最终归宿。 | 早期 |
| **高级采矿机 + 长距离无线（固体矿，后期）** | 高级采矿机**研发解锁后可造**。采集的矿通过**长距离无线传输自动回全局仓库**，不需储存站点/轨道/列车。**耗电多**、快。 | **后期**（研发解锁） |
| **次级基地共享仓库** | 次级基地**不是从 0 开始**，建好后可直接从全局仓库取固体物资开始生产。 | 全期 |
| **传送带定位** | 传送带 = **基地内部（生产区域内）固体物流设备**，负责设备之间固体物品移动（熔炉→组装机→仓库）。**基地之间不靠传送带运输**，靠仓储全局性。 | 全期 |
| **卡车** | ❌ **不再单独存在**——被"轨道 + 无人货运列车"替代（列车沿轨道行驶，本质是"会动的传送带"）。 | — |
| **有人火车** | ❌ **不做**。用无人货运列车（契合世界观，无需火车头/驾驶员）。 | — |

**固体矿物运输的完整流程（早期）**：

```
矿点(多种矿物,崎岖地形)
  ├─ 多台基础采矿机(建在矿脉上,通电)
  │    └─ 短距离无线传输(小范围,默认)
  │         └─ 把矿无线传到范围内的【矿点储存站点】
  │
  └─ 矿点储存站点(中转仓库,可升级)
       └─ 专用轨道连接到【基地储存站点】
            └─ 无人货运列车沿轨道往返(1车→升级后多车)
                 └─ 基地储存站点
                      └─ 自动进入【全局仓储】(任何基地可取)
```

**固体矿物运输的演进曲线**：

```
早期（电力不足）：基础采矿机 + 短距无线 + 储存站点 + 轨道无人列车（零/低能耗，但要规划）
                        ↓ 研发解锁
后期（电力充足）：高级采矿机 + 长距无线回仓（耗电多，快，免规划）
```

**液体/气体的物流形态**：

| 组成 | 形态 |
|------|------|
| **全局仓储** | ❌ **不适用**。液体/气体**不走全局仓储**，不能跨基地无线共享。 |
| **普通管道** | 液体版的传送带。**复杂拓扑**：创建流程、分流器、汇流器、准入口、管道桥等，本质和传送带同构（详见 A9 §10）。占用地形。 |
| **地下暗管** | **极简 A-B 点对点传输**，仅此而已。不是管道的升级版，是**完全不同的设备**。不占地形，按距离计算（有最大距离上限，参考 300m）。解决"长距离液体线不想铺一堆管道"的痛点。 |
| **跨基地液体运输** | 必须当地产，或物理运输（普通管道硬拉 / 地下暗管）。**无无线捷径**。 |

### 11.3 对 A11 / A12 / A9 其他章节的影响

| 受影响 | 修订内容 |

| **A11 WV-005**（原"简化卡车/无人机起步，火车留 Phase 5+"） | **作废重写**：固体改为全局仓储 + 无线回仓（卡车/火车不做，无人机=无线回仓视觉）；液体/气体走管道系统。 |

### 11.4 多基地关系重新定义（方案 4：全局仓储共享）

EC-008 定型后，EC-007 的三方案对比失效。新的多基地关系定义为：

- **主基地 + 多个次级基地，全部共享一个全局仓储**。
- 主基地是核心枢纽（主核所在），次级基地是"扩展生产区"（次核开辟）。
- 基地间**无物理运输需求**——仓储全局共享。
- 各基地**功能可自由分工**（主基地做复杂产线，次级基地就近做初级加工等），由玩家自由决定。
- 物品的"位置"概念在基地间消失——只有"在仓库里"和"在某条传送带上"。

### 11.5 玩法后果（第五次讨论修订）

**优点**：
- ✅ 忠于原作（固体成品仓储全局共享）。
- ✅ **固体物流工作量可控**（卡车简化版，固定路径，远低于完整卡车/火车）。
- ✅ "次级基地不是从 0 开始"自然成立（固体成品共享仓库）。
- ✅ **固体矿物也有早期→后期曲线**（卡车→无线），与液体（管道→暗管）形成对称设计语言。
- ✅ **"能耗 vs 便利"权衡**：早期没电用卡车（零能耗），后期电多用无线（耗电换便利）。把电力系统和物流绑定，电力不孤立。
- ✅ **液体/气体保留了物流玩法深度**——铺管道、优化液体网络仍是核心乐趣。
- ✅ "早期痛苦→后期解锁解法"的工厂游戏经典曲线，固体液体两套都有。

**需注意**：
- ⚠️ 中后期深度靠**产线复杂度 + 液体管道优化 + 卡车路线优化（早期）+ 多基地战略 + 塔防 + 探索**支撑。
- ⚠️ 液体/气体跨基地运输是真实痛点（无无线捷径），需平衡。
- ⚠️ 卡车→无线的过渡平衡：无线不能太早解锁（否则卡车没存在感），也不能太晚（否则早期太痛苦）。

### 11.6 固/液/气分类传输（第四次讨论定型）

| 物品类型 | 基地内传输 | 跨基地传输 | 全局仓储 |
|----------|------------|------------|----------|
| **固体**（矿石/锭/零件） | 传送带（占地） | **全局仓储**（无线，自动） | ✅ 适用 |
| **液体/气体**（水/石油/气） | **普通管道**（早期，占地）/ **地下暗管**（后期，不占地） | **无全局共享**——当地产或物理运输（管道/暗管） | ❌ 不适用 |

**设计依据**：
1. **保留物流深度**：纯路线 A（所有物品全无线）会让游戏过浅。液体/气体保留管道玩法。
2. **忠于工业常识**：现实工业液体/气体也必须管道，固体可仓储配送。
3. **契合现有架构**：A9 §10 已预留管道系统，本设计是其语义补充。

### 11.7 普通管道 vs 地下暗管（第四次讨论定型，明确区分）

> **关键澄清**：管道和地下暗管是**两种完全不同的设备**，不是"升级版"关系。

| 维度 | 普通管道 | 地下暗管 |
|------|----------|----------|
| **定位** | 液体版的传送带 | 极简 A-B 点对点传输 |
| **复杂度** | **复杂拓扑**：创建流程、分流器、汇流器、准入口、管道桥（与传送带同构，见 A9 §10） | **极简**：A→B，仅此而已 |
| **占地** | 占用地形（像传送带） | **不占地形** |
| **距离** | 无上限（一节节铺） | **有最大距离上限**（参考 300m） |
| **解决的痛点** | 基地内液体物流（与传送带对称） | "长距离液体线不想铺一堆管道" |
| **实现时机** | Phase 3b（建议，见 §17） | Phase 3b 后期或 Phase 5（研发解锁） |

**设计逻辑**：
- 普通管道 = 基地内的液体物流，玩家要设计液体网络（像设计传送带网络一样）。
- 地下暗管 = 长距离液体传输的"捷径"，研发解锁后可用，让玩家不用为了远处一口井铺几百节管道。
- 两者**不冲突**：管道管基地内，暗管管跨区/长距离。

## 13. ✅ EC-010 主核危机与恢复机制（正式条款，第七次讨论全部细节定型）

> **本节为正式条款（2026-07 第七次讨论全部细节定型）。** 这是玩家提出的**特别精彩**的失败处理设计——主核打爆≠直接 GG，而是触发"入侵-重建"流程。五个细节（D-001~D-005）已全部定型。

### 13.0 关键澄清：居民是数字，不在世界地图上（✅ 第七次讨论定型）

> **这是定型 EC-010 的关键前提**，由玩家在第七次讨论明确：**居民（人口）本质上是数字，不出现在世界地图中**。

- 居民没有世界实体（不寻路、不碰撞、不被怪物物理追击）。
- 居民 = 一个数字 + UI 展示（人口数量、消耗速率、分配状态）。
- 这极大简化了系统：不需要做居民的实体 AI，危机机制变成**状态机驱动**而非物理碰撞。

### 13.1 危机机制总览（✅ 定型）

危机是**两阶段**的，核心是"怪物攻击对象的变化"：

```
【阶段1：推进期】怪物从基地外进攻 → 一路推进到主核心
  → 路上遇到设备就破坏
       → 设备被破坏 = 经济损失（产能下降）
       → 但【人口完全不减】（阶段1人口安全）
            → 主核承受伤害

【主核被打爆】→ 主核变【残骸】（D-001），功能停止

【阶段2：灭口期】主核爆后，怪物"攻击对象切换为人口"
  → 人口开始【快速大幅下降】（怪物攻击人=抽象的人口下降机制）
       → 玩家必须尽快清怪（用塔防+技能）

【清完怪】→ 主核残骸开始【修复】（D-004）
  → 修复 = 资源 + 时间，人口加速修复
       → 修复完成，主核恢复，危机解除

【真 GG】主核爆 + 人口归零 → 无法清怪、无法修复 → Game Over
```

### 13.2 D-001 主核"打爆"的具体状态（✅ 定型：残骸）

主核被打爆后变成**残骸**（还在原地，功能停止）：

| 主核状态 | 形态 | 功能 | 重建方式 |
|----------|------|------|----------|
| 正常 | 完整 | 全功能（区域有效、设备运转） | — |
| ✅ **打爆 → 残骸** | 破损残骸（原地） | 所有功能停止（区域失效、设备停转） | 清完怪后，花资源+时间修复残骸 |

**理由**：残骸方案最平衡——玩家不会因"主核没了完全没退路"绝望（残骸还在=有希望），也不会太轻松（修复要花资源+时间）。视觉上能传递危机感。

### 13.3 D-002 怪物行为（✅ 定型：两阶段攻击对象切换）

| 阶段 | 触发条件 | 怪物攻击对象 | 人口影响 |
|------|----------|--------------|----------|
| **阶段1：推进期** | 怪物从基地外进攻 | **设备**（世界实体） | ❌ **人口不减**（只损失设备/产能） |
| **阶段2：灭口期** | 主核被打爆（变残骸） | **人口**（数字，抽象下降机制） | ✅ **人口快速大幅下降** |

**怪物 AI 简化**：怪物只攻击设备（世界实体），不需要追居民（居民不在地图）。主核爆后，人口下降是**全局状态切换**（不是怪物行为变化）。

### 13.4 D-003 居民战力（✅ 归并到 D-004）

既然居民是数字不在地图上，"微弱自卫"的物理语义不成立。**归并到 D-004 的人口下降公式**——人口下降速率本身体现"韧性"（人多时下降减缓），取代"居民反击怪物"。

### 13.5 D-004 人口下降与修复公式（✅ 定型：方案 B，阶段1不减人）

**人口下降**（采用方案 B，惩罚分层）：

```
【阶段1：推进期】人口完全不减
  → 只损失设备（经济惩罚），人口安全
  → 玩家翻盘希望保留（人没在推进期死光）

【阶段2：灭口期】主核爆后，人口快速下降
  下降速率 = 固定高速率（远大于阶段1的零）
  → 模拟"怪物攻击对象只剩人"
  → 玩家必须尽快清怪，否则人没了=GG
```

**主核修复**（清完怪后）：

```
修复主核 = 固定资源消耗（大）+ 修复时间
修复时间 = 基础时间 ÷ (1 + 人口系数)
  例：基础时间 10 分钟
     人口 100 → 系数 1.0 → 实际 5 分钟
     人口 200 → 系数 2.0 → 实际 3.3 分钟
     人口 0 → 无法修复（真GG条件）
```

**采用方案 B 的理由**：
1. 玩家原始描述即方案 B（"本质上不会有很大的人员损失"指阶段1，"主核心爆了之后...大幅下降"指阶段2）。
2. **惩罚清晰分层**：推进期=设备损失（经济），主核爆=人口损失（生存）。不叠加，避免双重惩罚挫败感。
3. **翻盘希望明确**：只要主核爆时人还多，清完怪就能修。"主核爆≠GG"的设计初衷得以落实。
4. **主核爆的分量更强**：人口下降作为主核爆的专属后果，让这个事件有冲击力。

### 13.6 D-005 危机期间玩家操作（✅ 定型：技能干预，不操作炮台）

> **关键澄清**：玩家**不能操作塔防炮台**（炮台纯自动战斗）。玩家的干预手段是**技能**（见 EC-006 §10.3）。

| 玩家**能**做 | 玩家**不能**做 |
|--------------|----------------|
| ✅ 释放**技能**（范围清怪、延缓进攻等，见 EC-006 §10.3） | ❌ 操作塔防炮台（纯自动） |
| ✅ 紧急建造/修复塔防（花资源补防御） | ❌ 修复主核（必须先清完怪） |
| ✅ 观察人口下降（制造紧张感） | ❌ 正常生产（设备停转/被毁） |

**理由**：玩家用技能（集成工业系统的软件功能）干预，不操作炮台，契合管理员世界观。清完怪才能修主核，形成明确目标节奏。

### 13.7 这套设计的精妙之处（AI 评价）

- **失败本身变成玩法**：不是粗暴 GG，而是一段紧张的危机体验（推进→主核爆→灭口期→清怪→重建）。
- **人口有了第二战略价值**：人口是"灾后恢复力"（修复加速 + 翻盘底气）。养人口从"不得不做"变成"主动想做"。**人口的三重价值闭环**：① 消耗出口；② 探索/研发劳动力；③ 灾后恢复力。
- **惩罚分层健康**：阶段1只损失设备（经济），阶段2才损失人口（生存）。不双重惩罚。
- **塔防 + 人口 + 技能 + 装备生产四者焊死**：塔防是清怪主力，技能是玩家干预，人口是恢复力，装备决定探索伤亡（反哺人口）。四者绑定。

## 18. 矿点开采系统专题（第六次讨论重写，替代原卡车专题）

> 本节集中记录"矿点开采 + 轨道无人货运列车运输"系统的设计决策，供 Phase 3b 开发依据。这是早期固体矿物运输的完整方案，替代第五次讨论的"卡车"设计。

### 18.0 设计演进说明

本节经历了两次演进：
- **第五次讨论**：定为"普通采矿机 + 固定路径卡车"。
- **第六次讨论**：升级为"基础采矿机短距无线 + 储存站点 + 专用轨道无人货运列车"。"卡车"改为"无人货运列车"，复杂度反而降低（轨道是离散铺设像传送带，列车天然沿轨道走无需寻路）。

### 18.1 完整流程

```
矿点(Mine Site,地理概念：多种矿物 + 崎岖地形)
  ├─ 多台基础采矿机(只能建在矿脉上，通电即采)
  │    └─ 短距离无线传输(小范围，默认就有)
  │         └─ 把矿无线传到范围内的【矿点储存站点】
  │              (解决崎岖地形车辆无法到每台矿机对接的问题)
  │
  └─ 矿点储存站点(Mine Depot，中转仓库，可升级)
       └─ 专用轨道(Rail)连接到【基地储存站点】
            └─ 无人货运列车沿轨道往返(初始1车，升级后多车)
                 └─ 基地储存站点(Base Depot)
                      └─ 自动进入【全局仓储】(任何基地可取)
```

**设计逻辑**：
- 矿机在崎岖地形，车辆到不了每台矿机 → 用**短距无线**集中到储存站点。
- 储存站点是玩家选的平地 → 车辆只需到储存站点，不需到每台矿机。
- 把"崎岖地形"变成"玩家要规划储存站点位置"的玩法。

### 18.2 关键决策（✅ 第六次讨论定型）

| 决策点 | 选择 | 说明 |
|--------|------|------|
| **运输载具** | **无人货运列车**（非卡车/有人火车） | 契合"集成工业系统"世界观——系统调度的自动化载具，无需驾驶员。更科幻、更工业 |
| **轨道** | **专用轨道，单一类型**（不分级） | 离散铺设（一节节铺，像传送带）。升级靠储存站点，不靠轨道。复杂度低 |
| **矿机短距无线** | **基础采矿机默认有**（小范围） | 解决崎岖地形对接问题。范围待量化（D-023） |
| **储存站点升级** | **升级站点提升效率**（1 车→多车） | 像纪元 1800 石油铁路的站点升级 |
| **基地储存站接入** | **列车运到基地储存站 → 自动进入全局仓储** | 全局仓储是矿物运输的最终归宿，列车只是把矿从远处运到能进仓储的地方 |
| **能耗** | 低/零额外能耗（早期优势） | 列车由系统调度，相对后期无线回仓的低能耗选择 |

### 18.3 复杂度评估（AI 判断）

**复杂度🟡 中等偏低可控**——比第五次讨论的"卡车"还低。

| 复杂点 | 方案 | 难度 |
|--------|------|------|
| 路径 | **铺轨道节**（离散，像传送带） | 🟢 低 |
| 寻路 | **完全不需要**——列车只能沿轨道走 | 🟢 低 |
| 多车调度 | **轨道本身是队列**——列车一节跟一节，天然有序 | 🟢 低 |
| 碰撞 | **轨道是专用通道**，列车不撞别的东西 | 🟢 低 |
| 装卸 | 到站自动装卸（端口触发，同传送带） | 🟢 低 |
| 站点升级 UI | 升级菜单（加车/提速） | 🟢 低 |
| 视觉 | 列车精灵沿轨道移动（直线/弯道动画） | 🟢 低 |
| 矿机短距无线 | 范围判定（类似电力系统的供电范围） | 🟢 低 |

**总评**：核心机制与传送带同构（沿轨道节移动），复杂度接近传送带系统。可大量复用 A9 传送带的基础设施。

**对比各方案复杂度**：

| 方案 | 路径 | 寻路 | 调度 | 总复杂度 |
|------|------|------|------|----------|
| 完整卡车（不做） | 自由 | 需要 | 网络调度 | 🔴 高 |
| 固定路径卡车（第五次讨论） | 连续路径点 | 不需要 | 排队 | 🟡 中 |
| **轨道无人列车（本项目，第六次讨论）** | **离散轨道节** | **不需要** | **轨道即队列** | **🟡 中偏低** |

### 18.4 与"后期无线"的演进关系

| 阶段 | 设备 | 流程 | 能耗 | 体验 |
|------|------|------|------|------|
| **早期** | 基础采矿机 + 储存站点 + 轨道 + 无人列车 | 矿机→(短距无线)→储存站→(列车)→基地储存站→全局仓储 | 低 | 要规划（矿机布局/储存站位置/轨道），但低能耗 |
| **后期** | 高级采矿机（研发解锁） | 矿机→(长距无线)→全局仓储 | 高（耗电多） | 免规划，但耗电 |

**演进逻辑**：早期电力不足，用低能耗但需规划的轨道列车；后期电力充足，换高能耗但免规划的无线。形成"能耗 vs 便利"权衡，绑定电力系统。
