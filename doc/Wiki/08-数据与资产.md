项目坚持**数据驱动**（DD-003/005）：设备、物品、配方全部是声明式定义；物品与配方由 CSV 加载，设备是 TS 常量表，视觉资产由构建脚本打包成图集。

## 1. 设备定义 data/buildings.ts（505 行）

### BuildingDefinition（`src/game/data/buildings.ts:72`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一标识（= devices 图集 key 前缀），如 `refining_unit` |
| `name` | string | 显示名（中文） |
| `category` | `'extraction' \| 'production' \| 'logistics' \| 'defense' \| 'agriculture'` | 分类 |
| `footprint` | `{w, h}`（Cell） | 90°/270° 旋转时宽高互换（`effectiveFootprint`） |
| `ports` | `Port[]` | 默认朝向（0°）下的端口表 |
| `texture` | string | devices 图集 key；nineslice 时语义 = equipment 透明底帧 |
| `baseStyle?` | `'whole' \| 'nineslice'` | 缺省 whole；nineslice（w,h≥2）走九宫格拼装 |
| `depot?` | `'unload' \| 'load'` | 仓库口标记：无限源 / 无限汇（MachineSystem 走 DepotOps 分支） |
| `logoTextureKey?` | string | billboard 徽标层（+`-glow` 底层、`_white` 高亮变体） |
| `selectable` | boolean | 是否可被点击选中 |
| `buildCost` | `{itemId, count}[]` | 占位（Phase 1 不实现成本约束） |
| `powerConsumption` | number (W) | Phase 3+ 电力（当前假定供电） |
| `inputSlotCount` / `outputSlotCount` | number | 输入/输出槽数（0 = 无缓冲区） |
| `bufferCapacity` | number | 每槽容量（全部为 50） |

### Port（`src/game/data/buildings.ts:36`）

```ts
interface Port {
  type: 'input' | 'output' | 'liquid';
  position: { dx: number; dy: number };   // 相对 footprint 左上角的格偏移（默认朝向）
  itemFilter?: string[];                   // 预留
}
```

方向约定（九宫格端口体系定型）：**顶=出口、底=入口、左=液体出、右=液体入**；违反约定的口走 equipment 自画。

## 2. 物品定义 data/items.ts（139 行）

interface ItemDefinition {

  category: 'mineral_ore' | 'natural_liquid' | 'plant' | 'aic_products' | 'usable_items';

CSV 驱动：`parseItemCsv`（自然资源.csv）+ `productItemsFromRecipeCsv`（recipe.csv 产物行）+ `EXTRA_ITEM_DEFS`（仅 `sewage 污水`，只出现在副产物列）。`loadItemRegistry(resourceCsv, recipeCsv) → ItemRegistry {byId, byName}`（重复先注册者优先）。CSV 解析为 RFC4180 引号感知（`splitCsvLine`）。

## 3. 配方定义 data/recipes.ts（217 行）

```ts
interface RecipeAtom  { kind: 'item' | 'tag'; ref: string; count: number }
interface RecipeInput { alternatives: RecipeAtom[] }   // 长度 1 = 确定需求；>1 = "或"
interface RecipeOutput{ itemId: string; count: number }
interface Recipe {
  id: string;              // recipe_{equipmentId}_{主产物itemId}_{序号}
  outputs: RecipeOutput[]; // outputs[0] 主产物 + 副产物（如赤铜块副产污水）
  equipmentId: string;
  inputs: RecipeInput[];   // 多组 = "和"关系
  time: number;            // ms
  level: number;
}
```

### CSV 语法（`doc/csv/recipe.csv`）

- 原料列：`+` 分组（和）、组内 `/` 分（或）；
- `（任意X类别的物品）*n` → tag 原子；`名称*n` → 数量；
- 跳过规则：`unknown-equipment`（设备无 BuildingDefinition）/ `unknown-item`，记入 `SkippedRecipe` 打 warn，**不崩溃**。

`buildRecipeIndex(recipes) → Map<equipmentId, Recipe[]>`；`formatRecipeSummary` 生成"晶体外壳(源矿×1/晶体外壳粉末×1, 2秒)"式摘要。**配方切换的玩家交互未实现**——当前按 CSV 列表序自动匹配第一条可满足配方。

## 4. 资产管线 scripts/pack-assets.ts

`npm run pack-assets` → `node --experimental-strip-types scripts/pack-assets.ts`。**产物 `public/spritesheets/` 不入库（.gitignore），克隆后必须先跑一次，否则首屏无纹理。**

### 三阶段流程

| 阶段 | 内容 |
|---|---|
| A 扫描+光栅化 | 按 `scripts/assets/asset-manifest.ts`（单一真相源）扫描输入目录；SVG 用 **sharp** 按 `DEVICE_RASTER_SCALE=4` 光栅化（匹配 CAMERA_ZOOM_MAX=4），PNG 直读 |
| B 打包 | `shelfPack` 装箱（POT，上限 4096；块间 `ATLAS_PADDING=8` 抗 mipmap 渗色） |
| C 合成+输出 | sharp 合成 → `{group}.png` + PixiJS v8 格式 `{group}.json`（帧 key 带 `.png`；trim 帧写 trimmed/spriteSourceSize，PixiJS 原生解析） |

### devices 组专属处理

| 机制 | 说明 |
|---|---|
| alpha trim | 全图扫描裁透明（省 < 4096px² 不裁）；`*_arrow_mask` 帧例外不裁（滤镜依赖"帧=全画布"契约） |
| 功能层子帧 | SVG 内 `display:none` 切换法提取层级：key = `设备名/logo`、`/logo-glow`、`/status`、`/port-in-0`、`/arrow-*`、`/state-*`（白名单） |
| 箭头 mask 帧 | 识别 `fill:none + stroke:#828080` 的箭头 path，生成"其余透明、箭头变白"的 `*_arrow_mask` 帧（PreviewTintFilter 用） |
| 九宫格切片 | `nineslice_unit.svg` 按格 ±4px（deco 8px）窗口光栅化 29 组切片：slice-* 9（底座）+ port-* 6 + emblazon-* 4 + lport-* 8 + deco-l/r；key = `nineslice/<方位>`；**不输出整机主帧** |

当前产物：devices 4096×2048（63 帧）、items 4096×2048（93 帧）、ui 2048×256（26 帧）。

### 何时重跑

- 新增/修改 `src/assets/svg|png` 下任何文件；
- 改动 asset-manifest（分组/白名单/倍率/padding）；
- 补齐缺失设备 SVG（当前用占位图的设备）之后。

dev 模式下 Vite 直接 serve `public/`，但打包产物**不热更新**，需手动重跑。
