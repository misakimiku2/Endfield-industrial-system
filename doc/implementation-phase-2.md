## T2.0 — 传送带创建系统

### 目标
实现从设备输出端或已有断头传送带发起的传送带绘制：基础创建、延长、删除，以及方向约束和防穿模检查。截断、合并、物流桥交叉等高级编辑放到 T2.0 之后的任务。

> **设计依据**: A9 §6（传送带创建与编辑系统）及用户提供的 A1/A2/A3 样图。本任务是 Phase 2 的前置基础——后续所有传送带相关任务（T2.1 物品移动、T2.2 跨段传输）都依赖玩家能先创建出传送带。

### 范围

T2.0 分两个阶段完成：

- **阶段 1：基础创建与预览**
  - 按 `E` 进入/退出传送带创建模式
  - 高亮设备输出端口和已有断头传送带末端
  - 点击起点 → 移动鼠标显示蓝色预览路径 → 点击目标空格落盘为黄色传送带
  - 目标格被占用/越界时预览变红，点击无效
  - `右键` / `ESC` / 再按 `E` 退出创建模式

- **阶段 2：链管理与延长**
  - 每段传送带作为独立 ECS Entity，记录 `chainId`、`direction`、`isCorner`、`isTail`
  - 从断头传送带末端继续延长，新段继承原 `chainId`
  - 方向约束：禁止反向，允许同向和 90° 转弯
  - 选中任意一段高亮整条链
  - `Delete` 删除整链，`Shift+Delete` 删除单段

- **明确排除（后续任务）**
  - 截断已有传送带并创建分支
  - 合并孤立传送带
  - 物流桥作为合法交叉点
  - 物品移动动画与 pointer 流动（T2.1）

### 入口规则

- 玩家按 `E` 进入**全局传送带创建模式**，无需先选中设备
- 进入创建模式后，鼠标 hover 到设备输出端口格或断头传送带末端时，该格高亮
- 左键点击高亮格作为路径起点
- 再按 `E`、`右键` 或 `ESC` 退出创建模式
- 创建模式下普通设备选中逻辑暂停，避免与创建操作冲突

### 路径生成规则

- 点击起点后，鼠标移动时实时显示从起点到鼠标所在网格的预览路径
- 预览路径为 L 形：第一段固定沿起点方向延伸，第二段转向目标格
  - 起点为设备输出端口时，第一段沿端口朝向出去
  - 起点为断头传送带末端时，第一段沿该末端方向继续
- 如果目标格与起点在同一行或同一列，则生成直线传送带
- 预览路径上的每个网格若未被占用，显示蓝色 A1 纹理；任一网格被占用或越界，整段预览变红 A3
- 点击目标空格后，预览路径上的所有格子落盘为真实传送带段

### 数据模型

新增 `BeltSegmentComp` 组件，标记一个 Entity 是传送带段：

```ts
interface BeltSegmentComp {
  /** 所属链 ID，同一次创建/延长的段共享 */
  chainId: string;
  /** 段朝向：0°=右, 90°=下, 180°=左, 270°=上 */
  direction: Direction;
  /** 是否为转角段（连接两个方向不同的直段） */
  isCorner: boolean;
  /** 是否为链末端（可被继续延长） */
  isTail: boolean;
}
```

新增 `BeltLinkComp` 组件，记录段与段、段与设备端口的关系：

```ts
interface BeltLinkComp {
  /** 上游段，null 表示起点接设备输出端口 */
  prev: EntityHandle | null;
  /** 下游段，null 表示当前是链尾 */
  next: EntityHandle | null;
  /** 起点连接的设备端口（可选） */
  sourcePort: {
    buildingHandle: EntityHandle;
    portIndex: number;
  } | null;
}
```

传送带段同时需要 `Position`（左上角世界坐标）和 `SpriteComp`（纹理、层级）用于渲染。

### 交互状态机

| 状态 | 触发 | 表现 |
|------|------|------|
| `idle` | 默认 | 普通地图交互，左键选中设备 |
| `belt_hover` | 按 `E` 后 | 鼠标 hover 到输出端口/断头末端时高亮 |
| `belt_preview` | 点击起点后 | 显示蓝色预览路径；无效时变红 |
| `belt_placed` | 点击目标空格后 | 落盘并回到 `belt_hover`，可继续创建 |

### 方向约束

- **延长约束**：禁止朝上游方向（逆流）延长；允许同向继续或 90° 转弯
- **转弯约束**：仅允许 90° 转弯，不允许 180° 掉头
- 违反约束时预览变红，点击无效

### 防穿模

- 创建前检查预览路径上的每个目标 Cell 是否被占用
- 被普通设备（生产设备、分流器、汇流器等）占用 → 创建失败，预览变红
- 地图边界外 → 创建失败，预览变红
- 传送带段之间允许重叠吗？**不允许**：同一 Cell 只能有一段传送带（T2.0 基础版）
- 物流桥例外留到后续任务

### 链管理

- 每次创建新链时生成唯一 `chainId`
- 从断头末端延长时继承原 `chainId`，并更新 `isTail` 和 `next/prev` 链接
- 选中任意一段时，通过 `chainId` 查询同链所有段并高亮
- 删除规则：
  - `Delete` 删除当前选中的整链
  - `Shift+Delete` 删除当前选中的单段（若删除中间段，下游链变为断头链）

### 渲染方案

- **正常传送带**：黄色 A2 纹理，静态箭头表示方向
- **预览可放置**：蓝色 A1 纹理，半透明
- **预览不可放置**：红色 A3 纹理
- **转角段**：使用旋转后的直段纹理，或单独转角纹理（优先复用直段纹理 + 旋转）
- **端口高亮**：设备输出端口格叠加蓝色半透明矩形
- **断头末端高亮**：链尾段叠加蓝色半透明标记
- **链选中高亮**：同链所有段叠加白色描边

### 验收标准（你在浏览器看到的效果）

- 按 `E` → 进入传送带创建模式，设备输出端口高亮
- 点击输出端口 → 鼠标移动时出现蓝色预览路径
- 移动鼠标到设备右侧 → 预览先向上再向右形成 L 形
- 点击目标空格 → 生成黄色传送带链
- 把目标移到已被其他设备占用的格 → 预览变红，点击无效
- 右键 / ESC / 再按 `E` → 退出创建模式
- 点击已有传送带链尾 → 可继续延长，新段与旧段同色同属一条链
- 点击任意一段 → 整条链高亮白色描边
- 选中链后按 `Delete` → 整链消失

### 预估工时

2 次会话（阶段 1 基础创建 + 阶段 2 链管理与延长）

## T2.1 — BeltSystem 基础：单段物品移动

### 目标
实现物品在一段传送带上的移动逻辑和动画。

### 需求
- 物品 progress 推进（每 Tick +0.025，跨一格需 40 Ticks / 2秒）
- Pointer 动画（空载时循环，有物品时隐藏）
- 物品/pointer 居中于传送带表面渲染

### 验收标准（你在浏览器看到的效果）
- AI 执行测试命令 → 一段传送带出现在画布上，上面有物品
- **物品沿传送带方向匀速移动**（从一端走向另一端）
- **当物品走到尽头** → 停在段尾
- **画面没有物品时** → 黄色箭头（pointer）沿传送带循环移动
- 放大/缩小 → 物品和 pointer 位置正确

### 预估工时
1 次会话

### 实现笔记（2026-08-13 完成 ✅）
- **GameLoop 双时钟**（A5 §2）：新增 `src/game/GameLoop.ts`，20TPS 仿真 + 60FPS 渲染 accumulator，BeltSystem 作 SimulationSystem 注册。这是 T2.1 的关键前置（之前主循环只有渲染）。
- **beltPhase 全局相位**：pointer 和物品共用 `BeltSystem.beltPhase`（logical tick 推进），消除两者（pointer 旧用 elapsedMS、物品用 logical tick）不同源导致的相位漂移与跨段闪烁。物品注入时 `progress = beltPhase` 对齐（"物品=实体 pointer"，间距/节奏完全一致）。
- **delta 帧间插值**：`BeltItem.delta`（本 tick 增量），渲染 `renderProgress = progress + alpha*delta`（alpha=accumulator/SIM_STEP，0~1）。流动物品 delta=0.025 平滑滑动、停止/被夹住 delta=0 静止，消除 20TPS 阶跃在 60FPS 下的卡顿。
- **物品旋转**：直段朝流向（`directionToIndex×π/2`）、转角沿弧切线（复用 pointer `computeCornerTransform` 数学），与 pointer 朝向一致。
- **停止居中**：`STOP_MAX=0.5`（格中心），物品停在最后一格正中（完全在格内、视觉居中）；跨段时 progress 仍到 1.0（边缘世界坐标连续，多格链流动无缝）。
- **pointer 接近物品渐变**（ptrAlpha）：物品所在格的 pointer 接近前方物品时 alpha 渐变淡出（`POINTER_FADE=0.15`），替代旧版硬切 `visible=false`；物品后方无前方物品时 alpha=0 隐藏。
- 验证：`scripts/verify-t21-item-move.mjs`（8/8）、`verify-t22-anim.mjs`（3/3 居中/同步/转角）、`verify-pointer-fade.mjs`（4/4）。

## T2.2 — BeltSystem 扩展：跨段传输与堵塞 ✅

### 目标
实现物品从一段传送带传到下一段，以及堵塞逆流传播。

### 需求
- 段尾检测：progress ≥ 1.0 时检查相邻 Cell 是否有传送带
- 有 → 物品移到下一段重新走；无 → 停在段尾
- 下游段满 → 上游也停；下游疏通 → 上游恢复

### 验收标准（你在浏览器看到的效果）
- AI 执行测试命令 → 两段相连的传送带出现，上面有物品
- **物品走到第一段尽头** → **自动进入第二段**，继续前进
- **物品走完第二段到头**（无连接）→ 停在末端
- AI 执行"堵满"测试 → 下游堵住时，上游的物品也停下来
- AI 执行"疏通"测试 → 下游有空间后，上游物品恢复前进

### 预估工时
1 次会话

### 实现笔记（2026-08-13 完成 ✅）
- **跨段传输**（A9 §2.2/§3）：队首 `progress≥1.0` + 出口方向相邻 Cell 有下游段且入口有空位（`hasSpaceAtEntry`：min progress ≥ MIN_ITEM_GAP）→ 物品移到下游段 `progress=0`。无下游/下游满 → 钳制 STOP_MAX 等待。
- **堵塞逆流**（A9 §3.4）：下游满 → 本段队首停段尾 → 后方被最小间距夹住 → 本段塞满 → 更上游跨段失败 → 逆流向源头传播。
- **疏通**（A9 §3.5）：下游消耗/腾位 → `hasSpace` 恢复 → 上游恢复跨段流动。
- **反向遍历**（消除跨段顿）：`BeltSystem.update` 从链尾→链头遍历。跨段物品 push 到下游时下游已处理 → 本 tick 不推进新物品（progress 保持 0），renderProgress 跨段边界连续（消除 50ms 停滞"顿一下"）。query 顺序=段创建顺序=链头→链尾，反向即物流逆序，堵塞时上游看到下游最新状态。
- **delta 连续**：跨段 push `delta=0.025`、beltPhase 重置 `beltPhaseDelta=0.025`（不再为 0），消除重置/跨段 tick 内 renderProgress 固定导致的停滞。
- **测试钩子修复**：`clearAllPlaced` 清传送带（原只清设备，导致"一堆物品"累积）、`spawnBelt` 占用检查、`spawnBeltWithItem` 清场、`consumeBeltTailItem` 模拟设备消费（测堵塞→疏通）。
- 验证：`scripts/verify-t22-cross-segment.mjs`（跨段+堵塞+疏通）、`diag-item-stutter.mjs`（跨段 renderProgress 连续性）。
- **已知遗留**：堵塞多物品场景间距 bug（"不后退"逻辑导致后方物品卡在 0.5，间距违规）——**已于 T2.7 一格一物品模型重构中消除**（2026-08-17，多物品同格状态不复存在，见 T2.7 实现笔记）。

> **追加背景（2026-08-24）**: 用户以玩家身份实测发现逻辑层全绿但"连不上设备"——传送带创建只解决了**起点**（输出端口/断头末端高亮），**终点**没有任何对接概念。编号为追加序号（晚于 T2.14/T2.15 提出），**建议执行时机: T2.12 之后、T2.13 之前**（依赖 T2.12 的取货口作为玩家可见的物品来源；与 T2.10 无耦合）。

### 目标
让玩家在传送带创建模式下，把带子接到设备输入端口这件事**可发现、可确认、可纠错**。

### 问题清单（2026-08-24 实测结论，现状）
1. **终点无对接概念**: `BeltCreationSystem` 的 BFS 只寻路到鼠标格——输入端口不是合法终点，无高亮、无吸附、无"将连接"反馈。
2. **连接成立是隐式几何**: T2.6 `findFeederBelt` 要求末段落在输入端口相邻格**且方向指向端口**（`段格 + directionVector(direction) === 端口格`）——玩家无从得知；末段方向由"沿用上一格方向"推得，从侧面接近供给格时末段指向侧面，物品到带尾只会停住，无任何提示。
3. **起点反例无反馈**: 创建模式只认输出端口/断头末端为起点（`port.type !== 'output'` 跳过），点击输入口或设备机身**静默无效**。
4. **几何硬约束不可见**: 输出口在顶边、输入口在底边 → 下游设备须在上游上方且至少隔一格；并排摆放需 U 形绕行，紧贴摆放物理不可连——玩家没有渠道获知这些规则。

### 需求
- **输入端口终点高亮**: preview 态下，与预览末段位置/方向兼容的设备输入端口格显示高亮（与现有输出端口起点高亮同视觉语言，颜色区分输入/输出）
- **末段方向吸附**: 鼠标悬停在"某输入端口的合法供给格"（端口相邻格）时，预览末段方向自动指向该端口（覆盖默认尾向），落盘即保证 `findFeederBelt` 判定成立
- **"将连接"确认反馈**: 预览末段与输入端口形成有效对接时，该端口显示连接确认色（如绿色描边/面板染色，与 T2.8 端口面板染色体系一致）
- **起点反例提示**: hover 输入口时显示"输入端口不能作为起点"提示（文字或图标），不再静默
- **断头带供给提示**（可选，时间不够可裁）: 已落盘断头带若指向某输入端口，该端口常态微高亮，帮助玩家识别"哪些口已接上"

### 验收标准（你在浏览器看到的效果）
- 精炼炉 A（下）与 B（上）中间隔一格，E 模式从 A 顶边输出口起带，**拖到 B 正下方一格悬停** → B 的底边输入口出现高亮，预览末段自动转为朝上
- 左键落盘 → 端口显示"已连接"确认色
- **两台炉子并排摆** → 绕行拖带时能清楚看到哪个输入口"够得着"，末段指向它时端口亮起
- hover 输入口尝试作为起点 → 出现"输入端口不能作为起点"提示，不再静默
- t21~t28 全量回归无破坏（寻路/落盘数据结构不变，只加终点辅助层）

1 次会话

## T2.14 — 设备移动（长按拾取 + 旋转 + 重放）

### 目标
实现已放置设备的搬迁：长按进入"拾取态"，可旋转朝向，左键重新放置，右键/ESC 取消放回原位。

### 背景
Phase 1 只做了放置/选择/删除，不支持改变已放置设备的朝向或位置。本任务是改变已放置设备朝向的**唯一入口**——主流建造游戏没有"原地旋转已放置物体"，改朝向通过"长按拾取 → R 旋转 → 左键重放"完成。Phase 2 产线变复杂后，搬迁/改朝向需求显著增加，值得作为独立操作加入。

> **设计依据**: A3 §2.2（Port 旋转数学）、A2 §7（占位表 release/occupy）。移动本质是 `delete + place` 的组合，但**保留设备运行时状态**（BuildingComponent 的缓冲区/生产进度）——搬迁不应清空已生产到一半的进度。

> **前置约束已在 T1.8 实现**：Phase 1 的 T1.8 选择系统已按"pointerdown 记录时间戳+命中设备，pointerup 提交选中"的结构实现（见 T1.8「前瞻约束」）。本任务在该基础上叠加：pointerdown 后挂 300ms 定时器，定时器触发前 pointerup = 选中（走 T1.8 原逻辑），定时器触发 = 升级为移动态。**若开发 T2.14 时发现 T1.8 未遵守该结构，需先回退修正 T1.8 再开发本任务。**

### 需求
- **进入移动态**：长按已放置的设备（按住超过阈值，如 300ms）→ 设备进入拾取态，视觉上变为半透明预览（复用 T1.7 放置预览样式），跟随鼠标吸附网格
- **原位释放**：进入移动态的瞬间，`OccupancyMap.release` 释放原 footprint 占位，原位置可被其他操作占用
- **旋转**：移动态下按 R 键 → 预览顺时针旋转 90°（0°→90°→180°→270°→0°），Port 朝向跟随（A3 §2.2）
- **重放（左键）**：点击地图 → 检查 `canPlace`（新朝向的 footprint 是否全空）
  - 成功 → 更新 Position、`BuildingComponent.direction`、重算 Port 世界坐标、`OccupancyMap.occupy` 新占位、Sprite 固定
  - 失败（被其他设备占用）→ 预览变红 + 震动反馈，保持在移动态
- **取消（右键/ESC）**：退出移动态 → 设备放回原位原朝向（`release` 已释放的原占位需重新 `occupy` 回去）
- **运行时状态保留**：移动/旋转不重置 BuildingComponent 的 `bufferInput`/`bufferOutput`/`progress`/`state`——搬迁过程中设备处于"离线"（不参与生产/轮询），重放后恢复
- **传送带/物流连接处理**：搬迁后设备 Port 位置变化，与传送带的连接自动重算（Phase 2 产线中传送带不会自动跟随移动，需人工重新接驳——这是有意限制，避免复杂度爆炸）

### 验收标准（你在浏览器看到的效果）
- **（前提：AI 放置一个设备，T2.14 验证脚本会先用 `/test` 预置场景）**
- **长按一个已放置的设备（>300ms）** → 设备变半透明跟随鼠标，原位置空出来
- **移动态下按 R** → 预览顺时针旋转 90°，每按一次转一次
- **左键点击空白处** → 设备按新朝向重新固定
- **把预览拖到另一台设备上 → 左键** → 预览变红，放置失败，仍在移动态
- **移动态下按右键 或 ESC** → 设备回到原位原朝向，无变化
- **设备带半成品生产进度时移动**（AI 注入测试数据）→ 移动后进度保留，重放后继续生产
- **短按（<300ms）设备** → 仅触发选中（T1.8），不进入移动态——短按 = 选中，长按 = 移动，两者不冲突
- 移动操作不影响相机平移/缩放、其他设备
- 多次移动/取消后，`OccupancyMap` 状态一致，无占位泄漏（AI 通过调试钩子验证）

### 预估工时
1.5 次会话（长按手势识别 + 移动态状态机 + 占位 release/re-occupy + 取消回滚）

> **为 Phase 3 组操作铺路**：本任务的「单设备移动态」（preview 跟随鼠标 + release/occupy 占位 + R 旋转）是 Phase 3「多选与组操作」的机制原型。Phase 3 的 X 框选多选 + 组移动/旋转/删除/复制粘贴会在本任务基础上扩展：
> - 组移动 = 多个设备同时进入类移动态，校验所有目标格同时空闲
> - 组旋转 = 选定枢轴 + 组内每个设备绕枢轴转 90°（含朝向）
> - 传送带入组 = 框选可含传送带，组操作时重建 chainId 和连接关系（与 T2.0 链管理耦合，是组操作复杂度最高的部分）
>
> 开发本任务时请保持移动态逻辑的**可复用性**（preview/occupy/release 抽象成不绑死单设备的 API），降低 Phase 3 扩展成本。

## 关于测试效率

你描述的问题我非常理解——"修改→手动搭建→观察→描述症状→再修"这个循环确实很痛苦。解决方案是一个**测试场景速建系统**：

### 工作原理

Phase 2 开始时，AI 先创建一条特殊的**测试命令**，你只需要输入一条指令，比如：

```
/test 产线1
```

AI 会在游戏里**自动搭建**一套完整的测试产线，不需要你手动放任何设备。

### 预置测试场景

| 命令 | 自动搭建的内容 | 测试目的 |
|------|---------------|----------|
| `/test belt_create` | 一个精炼炉 + 已放置的几段传送带链 | 传送带创建/延申/截断交互 |
| `/test belt_single` | 一段传送带 + 一个物品 | 单段移动/pointer |
