## 症状 → 根因（三个独立的机制，全部定位并修复）

1. **图2/3 棋盘缺失 + 玄学自愈** = 两件事叠加:
   - T2.24 `slotPlacement` 把注入落在 `frac(链领头)`——领头相位是各链历史的
     任意值（首件注入 Tick 的余量），跨带图案偏移 = 出货节拍差 + (类A − 类B)，
     后者是任意的，在接入瞬间被**冻结**进图案 → 平行（图2）或错开整格（图3）。
   - 物品 progress 按 `+0.025`（二进制无限小数）逐 Tick 累加，在 1.0 跨格边界
     下欺（0.975+0.025 = 0.9999…9 < 1.0）→ 跨格晚 1 Tick → 节拍 Tick 上段首
     非空 → 轮询成功时刻偏离 40-Tick 网格 → 相位永久漂移。这些罕见事件的慢速
     随机游走 = "跑久了又变正常"的自愈假象。
   - **修复**: ①BeltSystem 全部 progress 赋值后对齐 1/40 格栅（`snapProgress`，
     格点幂等）→ 跨格恰在注入后 40 Tick、相邻出货间隔恒 40、相位零漂移;
     ②注入统一**段首 progress=0 + 随流 delta**（删 `slotPlacement`/`chainDownstreamMin`）
     → 注入相位 = 出货 Tick 网格 → 跨带偏移 = 节拍差 × 1 格，**棋盘从第一件
     交替起精确成立且永不漂移**（旧版"自愈"变确定性的快速排出）。
   - 关键认知: `frac(领头)` 放置（T2.24）对**带内**整数间距是必要的，但对**跨带**
     图案是把任意相位写进物品位置——T2.28 相位解耦后箭头不再需要跟随领头相位，
     `frac(领头)` 的存在理由消失。
2. **图1 指针与物品网格错开** = T2.28 的 `chainVirt`（全局时钟 + 链哈希）纯滑行流:
   箭头相位与物品无关；堵塞时箭头滑过静止物品队列（"接触即消失"只是遮住半格）。
   **修复 = 指针队列物理**（§十三 用户模型的完整实现），见下。
3. **指针消失过早**: `CONTACT_KILL_DIST 0.5` = 跨格即死。队列化后合并进击杀规则:
   仅**停稳**物品（delta=0）以 **0.375**（物品半宽 0.25 + 指针半高 0.125 = 像素
   接触）接触时击杀；流动的 1 从 0 身上碾过时 0 在其下方继续存在（zIndex 0.4 < 0.5）。

## 指针队列物理（`BeltPointerQueue.ts` 新纯逻辑模块，node 可驱动）

指针 0 = 无 ID 的"队列实体"，运行逻辑与物品同构:
- **流动/钳制**: +0.025/Tick；前方 ≥1 格的物品/指针 → 上限 = 对方 − 1（排队，
  停走队列把 0 整列冻结在格心——与物品排队同构）；前方 <1 格（**骑行区**，被 1
  碾住）→ 上限 = 物品当前位置（跟随同速，不得超车——否则物品前移后"严格在前"
  的钳制会把骑在身下的 0 冻在原地）；entering 过客不钳制（0 从其下方滑入设备）。
- **击杀**: 停稳物品接触（≤0.375）→ 移除（"1 停稳后 0 才消失"；击杀天然不可见
  ——被碾住的 0 本就在物品下方）。击杀消耗由补充规则回填（数量 < 链长+1 时在
  最末实体后方一格补充）。
- **循环（尾→首瞬移）**: 到达链尾余量（遮罩外）→ 入链槽位 ≡ **当前物品格网**
  （新鲜锚定，对齐折叠进不可见瞬移 = 零可见跳变）；链首侧被占时整格下移到带外
  更深处等待（遮罩裁剪不可见），随队列流动 lockstep 跟进，首个钳位处精确对齐
  （自愈）。base 用**未截断**越界位置（被 tailLimit 截断会丢相位）。
- **注入重相位**: 物品数增加的帧（渲染器判定），全体 0 按最短模距离（≤半格）
  刚体平移到新物品格网——正常流动 δ=0 零开销；仅停走恢复后新注入与旧队列相位
  分裂时实际平移，旧相位物品随吸收排出。**顺序必须是先推进后重相位**（注入 Tick
  物品不推进而指针推进，先重相位会错开一个流动量）。

## 渲染器时钟（`BeltPointerRenderer` 重写）

- 队列按**整数 Tick** 推进（beltPhase 差值折算，暂停 = 0）→ 指针真值恒在 1/40
  格网上（与物品同一纪律，无分数步长浮点漂移）。
- 渲染内插 = `prevD + α×(lastD − prevD)`——与物品渲染（prevTick + α×Δ）**完全
  同公式**，两者逐帧严格同余（一 Tick 视觉滞后的既有语义对齐）。
- 早期版本的分数步长时钟（帧间相位差连续推进）会让指针位置脱离格栅、且比物品
  渲染领先一 Tick——已废弃。
- 删除: `chainVirt`/`BeltPointerPhase.ts`/`BeltArrowStream.ts`/接触消失 alpha 规则/
  窗口池（精灵池改按指针 id 键控，prevD/lastD 随 entry 持久化）。保留: 带身遮罩、
  端部渐变、堵塞 tint 渐变、选中白 pointer、延长预览隐藏格。

## 教训

- **"自愈"是诊断金矿**: 玄学的"跑久了又变正常" = 罕见浮点事件的慢速随机游走——
  找到游走机制就找到了根因（浮点累加在阈值边界下欺）。
- **注入相位是跨带图案的全局变量**: `frac(领头)` 把每链的历史任意值写进物品
  位置，任意相对错位被永久冻结；"格网注入"（Tick 网格）才是跨带图案的确定性根基。
- **派生渲染实体的时钟必须与被对齐的实体同公式**: 指针用逻辑相位内插、物品用
  prev+α×Δ 滞后内插——一个 Tick 的时钟差就是恒定 1px 级错开；分数步长推进还会
  让位置脱离离散格栅。整数 Tick 推进真值 + 同公式内插渲染 = 逐帧严格同余。
- **多实体单 pass 钳制中，"瞬移类"事件（循环）必须放在所有互相钳制的移动之后，
  或对后方实体屏蔽**: 队首瞬移后其新位置会成为后方"前方指针 − 1"钳制的输入，
  整列丢一步（0.025 恒定偏差）。
- **骑行动作与排队钳制是两个区**: 前方 <1 格（被碾）跟随同速、前方 ≥1 格保持
  间距——用同一个"对方 − 1"公式会把被碾的 0 甩在原地。

## 补记 T2.29-a — 空带移动空洞 + 循环瞬移内插横扫（浏览器复测两缺陷，2026-09-07）

用户复测（空带、无物品）报告两症状，均复现并修复:

1. **移动空洞 `0-0-0-空`**（2 格带 3 指针 + 1 空格循环; 5 格带 6 指针 + 1 空格，
   指针数 = 输出端口 + 带长 ✓ = 补充目标 len+1）: 空带 re-entry 槽用未对齐的
   base（0.15，与指针类差 0.025）→ 与队尾指针连生两次 ≥1 冲突下移 → 落到队尾
   后约 2 格 → 一个空槽随流循环（圈长 len+2 而非 len+1，实测周期 160/279 Tick）。
   **修复**: 空带锚定改为**最末其他指针的类**（有物品仍锚物品格网）→ 槽恰落
   队尾 −1，整列间距恒 1、圈长恰 len+1（120/240 Tick，连续流）。
2. **循环瞬移内插横扫（双影闪烁）**: 尾→首瞬移（−(len+1) 格）被渲染内插
   `prevD + α×(lastD − prevD)` 当成连续位移——α 扫过中段，幽灵箭头逐帧从带顶
   移到带底（用户连续两帧截图: 顶部双指针 → 中部双指针）。**修复**: Tick 边界
   位移 > 0.55（正常 0.025 / 重相位 ≤0.525）判定为瞬移 → prevD = lastD（本 Tick
   直接渲染在新位置; 两端都在遮罩外/渐变区，跳变不可见）。
3. **顺带修复整列停顿**（实验暴露）: 前排被钳在链尾余量的一 Tick 里，全员恰距 1
   → 整列跟停、循环腾位晚一 Tick 释放（每圈一次全场 50ms 停顿，周期 +1）。
   **修复**: 移动 pass 中"已到链尾余量（即将离场）的前排"不再钳制后方（mid-tick
   的 0.975 间距只存在于移动与循环两 pass 之间，不参与渲染/判定）; 循环 pass
   独立在移动之后，ents/锚定全部用本 Tick 推进后的新鲜位置（无流动量陈旧）。

验证: S14 新增（空带连续流: 指针数恒 len+1、间距恒 1.0 峰值偏差 <2e-14、零停顿
Tick、渲染内插跨度 ≤0.025——瞬移中和后横扫结构性不可达）; S6 记账改"瞬移 Tick
记一份流动量"（圈长 len+1 下 mod len 记账会灌入圈长误差）; 全量 12 脚本（含
_stress-t29 压测）全绿、tsc 干净。

教训: **循环系统的"瞬移类"事件（尾→首）绝不可进入帧间内插**——内插的前提是
位移连续，瞬移会让 α 扫描出横跨全场的幽灵; **空带（无锚定物）时的相位锚 =
队列自身**，否则入链槽的浮点余量会被冲突消解放大为整格空洞。

## 补记 T2.29-b — 空带相位独立 + 满载无下骑（浏览器复测两缺陷，2026-09-07 第二轮）

用户复测报告（已提交工作区后逐项修复）:

1. **空带全局同相**（所有空传送带指针动画完全同步，无论创建先后）: 空带相位
   此前 = 播种时全局相位/被设备节拍重相位后的残留——同源设备喂过的带排空后
   全部同相。**修复**: 每链**创建相位** = frac(chainId 时间戳 / 2000ms)（
   `chainCreationClass`）——播种用它; 带过物品时仍被注入重相位对齐物品格网
   （0-1 同格网所需）; **排空后回归创建相位**（≤半格刚体平移一次）。语义:
   "每条带的图案从创建时刻起跑"（用户拍板: 每条带创建时间不一样）。
2. **满载运输物品下方跟指针**: 注入"弹入"链首格不检查指针——物品与入链指针
   同速同行、亚格间距（0~0.9）永不自解（速度相同不碰撞也不分离）。**修复 =
   击杀规则三分**（一格只能 0 或 1）: ① 停稳物品接触 ≤0.375 → 0 消失（原规则，
   "1 停稳后 0 才消失"; 排队静止的 0 被走近的 1 盖住是唯一合法同格瞬态）;
   ② **在流**指针被物品重合（≤0.375，物品停稳与否不论）→ 立即让位;
   ③ **注入格击杀**: 新物品注入的格上若有指针（0.4~0.9 亚格同行前兆）→
   让位后重相位。
3. **架构收拢**: 逐 Tick 编排（播种/击杀/前进/循环/注入格击杀/注入重相位/空带
   回归）整体收进 `ChainPointerQueue.tick()`——渲染器与诊断脚本跑**同一入口**，
   镜像漂移结构性消失（此前 diagnose 的 QueueMirror 手工复刻渲染器逻辑）。

验证: S15 新增（满载流 700 Tick 指针-物品最小距离恒 1.0、同格共存 0）; S16
新增（两链空带相位各 = 创建相位且恒定; 带过物品排空后回归创建相位）; 全量
12 脚本（含 _stress-t29）全绿、tsc 干净。

教训: **装饰层实体与仿真实体速度相同时，任何初始重叠都不会自愈**——同速 = 
间距冻结，必须在产生重叠的事件（注入）处消灭它; **"相位"是有主权的**——
空带的相位属于带自己（创建时刻），设备的节拍只在物品在场时借用。

## 补记 T2.29-c — 空带静止回归 + 取货口前导空格（2026-09-07 第三轮）

T2.29-b 的两笔修复各引入一个新缺陷，用户复测报告:

1. **空带指针完全静止**: "回归创建相位"用了**静态**创建相位作目标——指针每 Tick
   前进 0.025 又被拉回 0.025，净位移 0（S16-a 断言的恰是冻结态，测试与缺陷同错）。
   **修复**: 目标改为**虚拟创建时钟** `freeRunClass`——从创建相位起每 Tick +0.025
   持续累积（"这条带的图案从创建时刻起跑"的相位轨迹）。空带指针与时钟同速前进
   （回归成无操作），带过物品排空后滑回**此刻**的时钟值并随时钟继续流动。
2. **取货口前导空格 `1-空-0-0-0` + 前两三件"指针变物品"**: 注入格击杀发生在
   重相位**之前**且按"格"判——播种相位 0.9 时，0.9 处的指针与注入物品同格
   （floor 相同）但距离 0.9，被误杀; 而重相位本会把它刚体归位到物品 +1.0 的
   合法槽——于是它该覆盖的格永远空一格（是否触发取决于创建相位 = 用户"非100%
   复现"）。**修复**: 顺序反转为**先重相位后清除**——重相位把全体 0 对齐到物品
   格网（亚格同行者归位到 0=被盖住 或 ±1=合法），随后只清除与任一物品距离
   <1 的 0（恰在物品身上的）。相位扫描实验（0.05~0.95 十档）: 前导空格 0 Tick、
   可见击杀 0 次、布局恒 `IIAAAAAA`。
3. 顺带: 循环转运中的指针补 `flowing = true`（瞬移后一 Tick 不被当作静止）。

验证: S16 断言重写为流动时钟语义（800 Tick 空带相位 = 创建相位 + 流逝，非静止;
排空回归 = 当前时钟值）; 全量 12 脚本（含 _stress-t29）全绿、tsc 干净。

教训: **"回归到 X"的目标若本身不随时间前进，就会把流动实体锁死在 X**——回归
目标必须是与实体同速前进的轨迹（时钟），不是一个静止点; **按格判杀与格网重排
（重相位）同 Tick 共存时，判杀必须用重排之后的几何**——重排会把"同格但距离远"
的实体归位到合法位置，先用旧几何杀 = 误杀合法者。

## 补记 T2.29-d — 空带相位抵消（代理浏览器验证发现，哈希锚修复，2026-09-07）

T2.29-c 交付后 @general-purpose 代理做浏览器视觉验证（截图在 log/t29c-*）:
取货口前导空格（15 张连拍 0 空格）、满载无下骑、空带流动全部通过; 但**空带
互不同步不成立**——三条间隔 3.2s 创建的空带像素实测相位差 0.000/0.000/0.010。

**机理（结构性数学抵消）**: freeRunClass 从 frac(ts/2000) 起以带速推进——
phase(T) = frac(ts/2000) + (T−ts)/2000 ≡ frac(T/2000)。创建偏移被"创建以来的
流动量"**精确抵消**，任何空带都收敛到同一全局相位。任何"相位常数 = 创建时刻
按带速周期折算"的派生都逃不掉该抵消。node 侧 S16-a 之所以漏检: 两条链同一
时刻播种（未建模错时刻播种）——已补 S16-a2（B 在 A 跑 100 Tick 后播种，断言

## 补记 T2.29-f — 堵塞生长的渐隐完整性（出场口锁定，2026-09-07 第五轮）

用户复测（双带轮询 + 断头链，`0→2→0→1` 布局）: 走到 1（带尾停止物品）那格的
指针**立刻消失**，而 2 后面的 0 能走到 2 的停止位置才消失——交替循环。

**机理**: 堵塞虚拟终点是**离散后跳**的——每件物品停稳，终点从旧前沿跳到新前沿
（3.5→2.5→…）。物品 2 与它前方的指针同速推进: 物品 2 停稳的瞬间，该指针恰好
在旧前沿 3.5 处渐隐中——瞬间越过新终点 2.625 被硬传送回带首（渐隐中断 = 立刻
消失）; 下一支指针则正常向新终点 2.5 渐隐 = 交替。用户看到的"走入 1 那格就立刻
消失"正是这个同速相位锁定的巧合时序。

**修复 = 逐支出场口锁定（exitAt）**: 指针进入渐隐区（终点−余量）即锁定它正在
滑入的终点; 终点后跳不影响已锁定者——完整滑入原前沿、渐隐归零才循环（循环时
解锁）; 越过终点的存量指针（堵塞形成瞬间在裸带上）锁定真实带尾去完成滑出;
疏通（终点前进越过锁定值）解锁跟随。渲染层逐支以 `arrow.exitAt ?? 当前虚拟
终点` 为渐隐中心。

验证: S18 新增（堵塞生长: 锁定 ✓、无硬传送、完整滑入 3.5 至 3.625 循环、后来
者锁定新终点 2.5）; S1~S18 + 全量 14 脚本 + tsc 全绿。

教训: **离散事件的派生量（虚拟终点）对"正在途中的过渡实体"必须快照语义**——
过渡开始时锁定目标，后续离散跳变只影响后来者; 否则每次跳变都会把在途过渡
硬切（视觉 = 瞬移/消失）。

## 补记 T2.29-g — 交替消失仍未根除的三个真根因（2026-09-08 第六轮）

T2.29-f 的出场口锁定**方向正确但没有修干净**，用户复测原场景（设备输出接两带:
一条通存货口、一条断头堵塞）交替消失依旧。本次用 node 逐 Tick 复刻原场景
（断头链 3~8 格 × 900 Tick）把**全部**消失事件按"消失前一 Tick 的渲染 α"分类
（α=1 的击杀 / α>0.5 的循环硬切 / α 跳变），定位到**三个独立根因**，其中两个是
T2.29-f 遗漏的:

### 根因① 注入清扫的判定错了格网（主因，"走入物品那格立刻消失"）

`tick()` 注入 Tick 的清扫用 `|物品 − 指针| < 1` 判定，隐含假设是"全链实体在**同一
格网**上，距离 <1 ⟺ 重合"。但**堵塞生长期这条假设不成立**: 移动中的物品在
class 0.0 格网（注入时 progress=0），已停稳的堵塞队列在 class 0.5 格网
（STOP_MAX=0.5），二者相差半格；重相位只能对齐到最末物品（=新注入的 0.0）那一
个格网，于是**合法停在 0.5 格网上的 0 与堵塞物品距离恰 0.5 < 1 → 被整批删除**。
这些 0 当时 α=1.00（远未进入渐隐区），删除 = 精灵直接销毁 = **全亮瞬消**。
实测样本（断头 4 格链）: `t201 指针#4 2.975(α1.00)`、`t281 指针#2 0.975(α1.00)`
——正是用户说的"2 后面的 0 刚走入 2 停止的这一格就瞬间消失"。

**修复**: 判定改为"重相位后**重合**（距离 < 1e-6）"。重相位后指针必落在物品格网上
（间距恒 1 的推论），距离非 0 即 ≥1，0.5 一律是合法槽位。

### 根因② 出场口锁定把"终点之后的指针"锁到了它身后的值

`exitOf` 先判 `pos ≥ terminus − 余量` 就锁 `terminus`——这是**单侧**条件，终点后跳
后**远在终点之后**的指针也满足它，于是被锁到一个在它**身后**的终点值 → 同 Tick
被判越界、硬传送回带首（`t302 指针#2 2.500(α0.50) → 循环 −3.500`）。用户看到的
"走到 0.5 停止位置就消失"就是它（α 从 1 掉到 0.5 再被瞬移）。

**修复**: 分支顺序调换——**先判"越过终点"（`pos > terminus + 余量`）锁真实带尾**，
再判渐隐区锁当前终点。越过终点者按 T2.29-f 既定的"存量指针滑出真实带尾"语义
处理（这支就是用户说的"1 后面的指针能顺利走到 1 的 0.5 位置"那支，行为不变）。

### 根因③ 补充回补产出"离格指针"（根因①修复后暴露的次生问题）

`replenish` 按"最末**实体**（含物品）− 1"回补。当最末实体是物品且它的格网 ≠ 指针
格网时，补出的指针落在**异格网**上 = 离格指针，直接破坏"0 与 1 同格网"不变量:
它此后既不在注入清扫的判定格网上（永远杀不掉，根因①修好后尤其明显），又会一路
流进带内与物品重合被击杀 = 新的带内全亮瞬消（`_stress-t29c` 组1 全相位扫描
10/25 档复现，全部落在链首格 d≈0.2~0.36）。

**修复**: 落点改为**最末指针 − 1**（与既有指针同格网）；与物品 <1 格时**整格后退**
（保持格网，退到带外等待区，遮罩外不可见）。

### 验证

- 新增 **S19**（`scripts/diagnose-pointer-flicker.ts`）: 复刻用户原场景（精炼炉输出
  → A 通存货口 / B 断头 4 格），900 Tick 逐 Tick 按渲染层同一 α 公式判定——**全亮
  瞬消 0、全亮硬切 0、α 跳变 0**（链首注入格让位 1 支为设计内的"一格只能 0 或 1"，
  不计）。用 HEAD 旧码跑同一断言: **瞬消 2 + 硬切 1**（`t241 2.975(α1.00)`、
  `t321 0.975(α1.00)`、`t302 2.500(α0.50)→−3.500`），断言确实捕获修复前行为。

  遮罩外不可见、α=0.40）的链首让位击杀。
- S1~S19 + 全量 24 脚本 + `tsc --noEmit` 全绿（`verify-belt-blocked` /
  `verify-intake-cadence` 各 3 条失败与指针无关，为既有遗留，未引入也未恶化）。

### 教训

1. **"<1 格内即重合"这类判定是把不变量当前提**——一旦场景破坏该不变量（本例:
   堵塞生长 = 双格网共存），判定就从"精确"变成"滥杀"。凡是靠格网/间距不变量
   简化的判定，都要先问"这个不变量在本场景成立吗"。
2. **修了可见症状要回头查"不变量是否被破坏"**：根因③就是根因①修好后暴露的
   （异格网指针不再被误杀，于是活到带内才死）——修复后必须重跑**全相位/全场景**
   扫描，而不是只跑复现场景。
3. 单侧区间判定（`pos ≥ X − ε`）表达"进入区间"时必须补上另一侧，否则会把区间
   外的远端点一并纳入（根因②）。
