# 《明日方舟终末地的集成工业系统》—— 项目开发总文档


## 一、项目概述

### 1.1 项目定位

《明日方舟终末地的集成工业系统》（以下简称“集成工业系统”）是一款**异星工场风格**的2D工厂建造类游戏，融合塔防元素。玩家在异星地表搭建自动化工业生产线，同时抵御敌人入侵。

### 1.2 核心需求

| 需求项 | 具体要求 |
|--------|----------|
| **目标平台** | Web（浏览器）、PC（Windows/macOS/Linux）、Android、iOS |
| **性能目标** | 同屏**300-500个设备/实体**保持60FPS |
| **美术风格** | 浅灰网格工业风，SVG作为美术源文件 |
| **视觉基调** | 网格背景#E6E4E4、线条#D6D4D4、四角暗角径向渐变、网格线条屏边渐隐透明 |
| **核心玩法** | 资源采集→自动化生产→科技树→塔防抵御 |
| **开发模式** | 单人 + AI辅助开发 |


## 二、技术选型

### 2.1 最终技术栈

| 层级 | 技术选型 | 选型理由 |
|------|----------|----------|
| **2D渲染引擎** | **PixiJS v8** | GPU加速2D渲染，支持百万级精灵，原生SVG导出支持 |
| **跨平台框架** | **Tauri 2.x** | 轻量级（2-10MB vs Electron 80-150MB），已稳定支持iOS/Android |
| **前端构建工具** | **Vite** | 快速热更新，TypeScript原生支持 |
| **开发语言** | **TypeScript** | AI代码生成质量高，类型安全 |
| **后端语言（Tauri）** | **Rust** | 高性能、安全，处理存档/寻路等重型逻辑 |

### 2.2 PixiJS v8 关键特性

- **渲染性能**：PixiJS渲染大量元素（10,000+精灵）时帧率比Canvas 2D方案提升5~10倍
- **SVG支持**：v8.18.0新增 `graphicsContextToSvg()`，可将Graphics序列化为SVG字符串
- **AI开发辅助**：官方已发布25个PixiJS AI Skills，支持Claude Code、Cursor、Codex等工具
- **纹理图集合批**：Sprite使用纹理图集时，单个批次可合并最多16种不同纹理
- **HTML-in-Canvas**：v8.19.0支持将活DOM元素渲染为PixiJS纹理

### 2.3 Tauri 2.x 关键特性

- **跨平台覆盖**：Windows、macOS、Linux、Android、iOS
- **包体极小**：常见几MB，优化后可小于1MB
- **移动端成熟**：V2已将iOS/Android支持作为核心功能
- **多窗口支持**：已支持iOS/Android多窗口

### 5.2 轻量ECS架构

ECS（Entity-Component-System）是支撑500设备60FPS的核心架构。详见 **[A1 — ECS 设计规范](doc/architecture/ecs-spec.md)**。

**核心变更（相对旧版代码）：**
- Entity ID 从纯 `number` 改为 **generation-based** 的 `EntityHandle`，永不回收（DD-001）
- Component 禁止引用其他 Entity（DD-005）
- 所有运行时状态存储在 Component 中（DD-011）

**核心实现约定：**

```typescript
// ECS.ts 约定接口（详见 A1）
type EntityHandle = number;  // 内部编码: (generation << 20) | index

class World {
  createEntity(): EntityHandle;
  destroyEntity(handle: EntityHandle): void;
  isAlive(handle: EntityHandle): boolean;
  addComponent<T>(handle: EntityHandle, key: string, data: T): void;
  getComponent<T>(handle: EntityHandle, key: string): T | undefined;
  hasComponent(handle: EntityHandle, key: string): boolean;
  removeComponent(handle: EntityHandle, key: string): void;
  query(...componentKeys: string[]): EntityHandle[];
}
```

### 5.4 核心系统实现

系统执行顺序由 **[A5 §5 — Tick 内 System 执行顺序](doc/architecture/simulation-spec.md)** 和 **[A5 §5.2 — 设备事件顺序](doc/architecture/simulation-spec.md)** 严格定义。

**渲染系统 — 60 FPS**

```typescript
// systems/render-system.ts
// 详见 A6 §2.1 像素对齐、A2 §4 层级模型
export class RenderSystem {
  // 每渲染帧调用
  update(world: World, camera: Camera): void {
    const entities = world.query('Position', 'SpriteComp');
    for (const entity of entities) {
      const pos = world.getComponent<Position>(entity, 'Position')!;
      const sprite = this.spriteMap.get(entity);
      if (sprite) {
        const screenPos = camera.worldToScreen(pos.x, pos.y);
        sprite.x = Math.round(screenPos.x);  // 像素对齐
        sprite.y = Math.round(screenPos.y);
      }
    }
  }
}
```

**传送带系统 — 20 TPS**

export class BeltSystem {

    const belts = world.query('LogisticsComp', 'Position');
    for (const entity of belts) {
      const belt = world.getComponent<LogisticsComp>(entity, 'LogisticsComp')!;

      // 3. 清理已传输物品
    }
  }
}

### 5.5 仿真循环

详见 **[A5 — 仿真规范](doc/architecture/simulation-spec.md)**。核心设计：

```typescript
// GameLoop.ts
class GameLoop {
  speedMultiplier = 1;            // 0×, 1×, 2×, 4×, 8×
  private simAccumulator = 0;
  private readonly SIM_STEP = 50; // ms per tick @ 20 TPS

  // 每渲染帧调用一次
  update(frameDeltaMS: number): void {
    this.simAccumulator += frameDeltaMS * this.speedMultiplier;
    // 螺旋追赶保护: 累计超过 250ms 时截断
    while (this.simAccumulator >= this.SIM_STEP) {
      this.simAccumulator -= this.SIM_STEP;
      this.tick();  // 执行一个逻辑 Tick (50ms)
    }
  }

  private tick(): void {
      // 顺序执行（DD-010）:
      // 0. PowerSystem（Phase 3+ — 供电计算；Phase 1~2 此位为空，所有设备假定供电）
      // 1. 设备内部状态更新（MachineSystem 前半）
      // 2. 传送带移动（BeltSystem）
      // 3. 设备输出+输入处理（MachineSystem 后半）
      // 4. TurretSystem / EnemySystem / CleanupSystem
    }
}
```

## 六、SVG美术资源工作流

### 6.1 设计规范

- **风格**：黑白线稿，工业机械风
- **线条**：`stroke-width: 2`，无填充或浅灰填充
- **尺寸**：每个设备图标 64×64 或 128×128 像素
- **格式**：纯SVG，无外部依赖

### 6.2 导入流程

**方案：构建时转换（推荐）**

由于PixiJS运行时直接解析SVG会带来性能开销，推荐在**构建时**将SVG转换为PNG并打包为纹理图集。

```typescript
// vite-plugin-svg-to-spritesheet（自定义或使用现有插件）
// 构建时将 src/assets/svg/*.svg 转换为单个纹理图集
```

**手动流程：**

1. 在 `src/assets/svg/` 中存放所有SVG源文件
2. 使用工具（如 `svg2png`、`Sharp`）在构建时转换为PNG
3. 使用 `TexturePacker` 或 `PixiJS Spritesheet` 打包为图集
4. 在游戏中通过图集名称引用纹理

**运行时加载：**

```typescript
import spritesheetData from './assets/spritesheet.json';

// 加载图集
const texture = Texture.from('furnace.png');
const sprite = new Sprite(texture);
```

### 6.3 PixiJS v8 SVG新特性

PixiJS v8.18.0新增 `graphicsContextToSvg()`，可将Graphics对象导出为SVG，便于调试和资产导出。

```typescript
import { Graphics, graphicsContextToSvg } from 'pixi.js';

const g = new Graphics();
g.rect(0, 0, 64, 64).fill(0xffffff).stroke({ width: 2, color: 0x000000 });
const svgString = graphicsContextToSvg(g.context);
// 可用于导出或调试
```


## 七、性能优化方案

### 7.1 渲染优化

| 优化手段 | 实现方式 | 预期效果 |
|----------|----------|----------|
| **纹理图集** | 将所有设备纹理合并到一张图集 | Draw Call从N降至1 |
| **Sprite合批** | PixiJS自动合批相同纹理的Sprite | 显著减少DC |
| **视口剔除** | 只渲染屏幕内的实体 | 减少无效渲染 |
| **ParticleContainer** | 对大量相同纹理的精灵使用ParticleContainer | 极致的合批性能 |
| **Graphics优化** | 小型Graphics对象（<100点）性能与Sprite相当 | 灵活使用Graphics |

**ParticleContainer示例：**

```typescript
import { ParticleContainer } from 'pixi.js';

// 适用于大量相同纹理的实体（如资源掉落、粒子）
const container = new ParticleContainer(10000, {
  scale: true,
  position: true,
  rotation: true,
  uvs: true,
  alpha: true
});
app.stage.addChild(container);
```

### 7.2 逻辑优化

| 优化手段 | 实现方式 |
|----------|----------|
| **分帧处理** | 每帧只处理1/5的传送带/机器 |
| **对象池** | 复用子弹、敌人、粒子对象 |
| **空间分区** | 使用网格或四叉树加速碰撞检测 |
| **Rust后端** | 将寻路、存档等重型计算放在Rust侧 |

### 7.3 Tauri DPI适配

Tauri在不同屏幕（Retina、4K）上的DPI缩放需要特殊处理：

```typescript
import { getCurrentWindow } from '@tauri-apps/api/window';

async function getLogicalSize() {
  const win = getCurrentWindow();
  const physical = await win.outerSize();
  const scale = await win.scaleFactor();
  return {
    width: physical.width / scale,
    height: physical.height / scale
  };
}
```

### 7.4 初始化顺序保证

PixiJS渲染器初始化与Tauri WebView启动可能存在竞态条件，使用多重RAF确保就绪：

```typescript
function waitForPixiReady(app: Application, maxRetries = 10): Promise<void> {
  return new Promise((resolve) => {
    let retries = 0;
    const check = () => {
      if (app.renderer && app.stage) {
        resolve();
      } else if (retries++ < maxRetries) {
        requestAnimationFrame(check);
      }
    };
    check();
  });
}
```
