# T2.16 — 传送带终点对接辅助 · 实现笔记

> 任务卡: [implementation-phase-2.md](../implementation-phase-2.md) ｜ 状态: 2026-09-02 完成 ✅
> 背景: 2026-08-24 用户以玩家身份实测发现逻辑层全绿但"连不上设备"；2026-09-02 用户描述
> "第三个复杂问题"（多带喂精炼炉的先到先得/轮询补货规则 + 物品停在隔一格的 0,2），
> 对照确认其规则 1~5 均为已实现的 T2.6/T2.10 语义，"停在 0,2"的根源就是本任务卡的
> 终点对接缺口——带尾没接到输入口（供给格），物品堆在断头带尾。

## 问题回顾（接不上设备的四个坑，2026-08-24 实测结论）

1. 拖到设备格上 → 整条预览染红、点击无效（设备格 `canPlace` 不通过）；
2. 连接成立是隐式几何（末段须落在输入端口相邻格**且方向指向端口**），玩家无从得知；
3. 从侧面接近时末段方向"沿用上一格方向"指向侧面，物品到带尾默默停住；
4. 点击输入口想当起点 → 静默无效（起点只认输出口/断头末端）。

## 实现（五个文件 + 两个验收脚本）

- **BeltDockOps**（`src/game/systems/belt/BeltDockOps.ts`，纯几何，DD-011 先例）:
  - `dockTargetAt(cell, ports)`: cell 四邻格中的输入端口格 + 指向方向（供给格判定）；
  - `applyDockSnap(raw, mouseGrid, ports, startDir)`: 终点吸附核心——
    **mouse 在端口格上 → 路径截断到供给格（倒数第二格）+ 末段指向端口**（拖到设备上
    也能对接，不再整条染红——用户实测的主要卡点）；**mouse 在供给格上 → 末段方向
    覆盖为指向端口**（覆盖 computePathCells 的默认尾向）；吸附与进入方向 180° 折返
    （单格带从背离侧进入等）时放弃——传送带只有直段/90° 转角，U 形不是合法带型。
    路径仅 `[起点, 端口格]` 时供给格=起点格，无可落盘段，同样不吸附（染红提示）；
  - `applySnapToCells(cells, snap)`: 吸附方向重放到 PathCell 末格（末格与吸附格
    重合才写入）——previewPath 渲染与 commitCells 落盘共用，转角信息由
    computeTurnInfos 依 incoming/outgoing 自然得出；
  - `dockInfoOf(tail, tailDir, ports)`: 对接信息——targets=末格四邻全部输入端口格
    （候选"够得着"），confirmed=末段方向命中的端口格（"将连接"）。
- **IntakeOps.collectInputPortCells**（新增）: 全部设备输入端口格的世界索引。
  放在 IntakeOps 而非 belt/ 下——端口格的权威来源是 inputPortCells（与
  findFeederBelt 吸入判定同源），吸附几何才归 BeltDockOps。
- **BeltCreationSystem**（集成）: refreshPreview 在寻路后调 applyDockSnap
  （截断后的 raw 交给 checkPathValid，吸附决策存 `pendingSnap`），cells 末格重放
  吸附方向；commitCells 在 computePathCells 后重放 `pendingSnap`（重派生的默认
  尾向会覆盖预览吸附，落盘段组件以重放为准）。新增 `getDockInfo()`（预览有效才有，
  红色预览不亮端口防误导）与 `getStartHintCell()`（hover 态悬停输入端口格）。
- **PortHighlightRenderer**（视觉）: 创建模式输入端口新三级覆盖——起点反例红
  #E45050 > "将连接"绿 #37D067 > 候选紫 #C79BF2（箭头白色），优先级高于常态
  （连接黄/堵塞红）；落盘后常态即回到 T2.8 连接黄（"已连接"确认色）。起点反例
  另有单例 Text "输入端口不能作为起点"（白字深红描边，悬停端口上方，随格移动）。
- **接线**: Game → RenderSystem → PortHighlightRenderer 透传
  `getDockInfo`/`getStartHintCell` 两个回调（与既有 isCreateMode/getHoveredPortCell
  同模式）。可选项"断头带供给提示"无需新做——T2.8 连接黄本就是
  findFeederBelt 同源判定，对接成功的口常态即亮黄。

## 已知限制（有意不做，记录备忘）

- **已对接的断头带不能再延长**: 尾段方向指向设备，从它起带的首步被强制指向设备格
  （blocked）→ 预览恒红。要改线路需删段重铺或从源头重新起带。任务卡未要求，
  T2.14 设备移动落地后可一并审视。
- **同口第二供给带静默无效**: findFeederBelt 每口只认一条供给带，第二带指向同一
  端口只是断头（与旧版行为一致），"将连接"绿光仍会亮。多带喂设备应接**不同**输入口
  （A→左口、B→中口、C→右口），这是精炼炉说明的标准形态。
- **设备机身格（非端口格）拖带仍染红**: 只有输入端口格触发截断吸附；机身格无对接
  语义，红是正确反馈。

## 用户实测路径（本任务解决的原始痛点）

E 模式从源设备输出口起带 → **直接把鼠标拖到目标设备输入端口格上**（或紧邻供给格）
→ 输入口亮绿、末段自动指向端口 → 左键落盘 → 端口变黄（已连接）→ 物品沿带走进
供给格中心被预约吸入（T2.6），满载时停在供给格中心排队（不再"停在隔一格"）。
