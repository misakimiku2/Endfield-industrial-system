### 1.2 输入接线（关键纪律：System 不监听 DOM）

- `toCanvasPos(e)`：clientX/Y − canvas 原点 → canvas 屏幕坐标。
- **pointermove**：同步三方鼠标位置（`placement.setMouse` / `belt.setMouse` / `renderSystem.setBeltHoverMouse`）。
- **pointerdown**（优先级链）：
  1. 只处理左键(0)/右键(2)，中键留给相机拖拽；
  2. 命中工具栏包围盒直接 return（PixiJS `stopPropagation` 挡不住 canvas 原生 DOM 监听——两者是独立事件流）；
  3. `belt.isActive()` → 传送带创建优先；
  4. `placement.isPlacing()` → 左键放置 / 右键取消；
  5. 否则左键 → `selection.onPointerDown`（pointerdown 只记录时间戳，pointerup 提交短按判定）。
- **pointerup** 挂 window（指针可移出 canvas 才松开）。
- **键盘**：`E` 传送带创建模式；`Escape` 退出当前模式；`R` 旋转放置预览（裸按）；`Ctrl+R` 视图旋转（CameraController 拦截）；`Delete` 删除选中（带段逐个 `deleteSegment` → 设备 `deleteBuilding`）。

### 1.3 主循环与后台保活

- `app.ticker.add` 回调执行序见 [02-整体架构 §4](02-整体架构.md)。
- **双时钟兜底**（`src/main.ts:388`）：`setInterval(250ms)`，页面隐藏时按真实流逝时间 `tickSimulation(...)` 补 Tick——rAF 后台停转时仿真靠 accumulator 钳制（最多追 20 Tick）慢放而不冻结。
- **首帧对齐**：初始化末尾各 update(0) 立即跑一次，避免首帧错位。

## 2. ECS 核心 ECS.ts（166 行，零依赖）

### World 类 API

| 方法 | 签名 | 语义 |
|---|---|---|
| `createEntity()` | `(): EntityHandle` | 回收 index 优先，否则追加新槽位；以当前 generation 编码句柄 |
| `destroyEntity(h)` | `(handle): void` | **幂等**。清所有组件槽 → generation+1（旧句柄永久失效）→ index 入 freelist。不清理 PixiJS 对象（RenderSystem 负责） |
| `isAlive(h)` | `(handle): boolean` | 越界 / 存活位 false / **代数不匹配** → false |
| `entityCount()` | `(): number` | 存活实体数 |
| `addComponent(h, key, data)` | `<T>(handle, key: string, data: T): void` | 死实体抛错；同 key 重复 add = 覆盖 |
| `getComponent(h, key)` | `<T>(handle, key): T \| undefined` | 死实体返回 undefined；**返回组件对象引用**，直接 mutate 生效 |
| `hasComponent(h, key)` | `(handle, key): boolean` | |
| `removeComponent(h, key)` | `(handle, key): void` | 死实体静默 no-op |
| `query(...keys)` | `(...keys: string[]): EntityHandle[]` | 返回拥有全部 key 的存活实体数组；选最小 store 做基底遍历 |

句柄编码：`(generation << 20) | index`（index 20 bit、generation 12 bit，见 `src/game/ECS.ts:21`）。

## 3. Game.ts（110 行）——组合根

持有全部子系统（构造顺序 = 依赖顺序）：

```
new Game(scene, viewport, renderer):
  1. World                      (ECS)
  2. WorldData                  (含 createDefaultMap() 的 MapInstance，64×64)
  3. Camera(viewport, 世界边界)   ← 边界来自 MapInstance（非全局常量）
  4. RenderSystem(world, layers, camera, getTexture, renderer,
                  6 个回调 ← 全部转发 beltCreation 的查询:
                    isActive / getHoveredPortCell / getHoveredAnyPortCell /
                    getDockInfo / getStartHintCell / getHiddenTailCell)
  5. OccupancyMap(map)
  6. PlacementSystem(world, occupancy, camera, layers, getTexture)
  7. BeltCreationSystem(world, occupancy, camera, layers)
  8. BeltSystem
  9. GameLoop(world) → addSystem(beltSystem)      ★ BeltSystem 先注册（DD-010）
```

方法：

- `tickSimulation(deltaMS)` = `gameLoop.update(deltaMS)`。每渲染帧调用，**必须先于** `update()`（渲染读完整 Tick 快照）。
- `initProduction(recipes, items): MachineSystem`：**幂等**；创建 MachineSystem 并注册到 GameLoop（在 BeltSystem 之后）。由 main.ts 在 CSV 加载完后调用——这是 MachineSystem 延迟注册的原因（配方数据是异步导入的）。
- `update(deltaMS)`：计算插值系数 `alpha = accumulator / SIM_STEP_MS` 传给 RenderSystem。

## 4. GameLoop.ts（85 行）——固定步长仿真

```ts
interface SimulationSystem { update(world: World, dt: number): void }  // dt 恒 50ms
```

- `addSystem(sys)`：push，**注册顺序即执行顺序**。
- `update(frameDeltaMS)`：`simAccumulator += frameDeltaMS × speedMultiplier` → 钳制 1000ms → `while (>= 50ms)` 逐 Tick 调用全部系统。
- `get accumulator`：0~50ms，供渲染插值。
- `paused`：直接 return（暂停只停 Tick 不停渲染）；`speedMultiplier`：0/1/2/4/8 倍速。

常量（`render/constants.ts:80`）：`SIM_STEP_MS = 50`（20 TPS）、`SIM_ACCUMULATOR_MAX_MS = 1000`（后台 ~1Hz 节流下最多追 20 Tick）。

## 5. 世界层 world/

| 文件 | 职责 |
|---|---|
| `MapInstance.ts` | **地图尺寸唯一真相源**。`MapConfig {widthCells, heightCells}`；`widthPx = cells × CELL_SIZE` 构造时算好。`createDefaultMap()` = 64×64 Cell（4096×4096px）。相机边界与占用表边界都读它——为 Phase 3a 无限世界提前收口（不再有 WORLD_* 全局常量） |
| `World.ts` | `WorldData { map: MapInstance }`：当前地图静态数据容器。**注意：它不是 ECS 的 World**（ECS 的 World 在 ECS.ts） |
| `OccupancyMap.ts` | 格子占用表：`Map<"gx,gy", definitionId>`。**不进 ECS**（世界结构而非组件），一实例对应一张地图。API 见下表 |
| `Chunk.ts` | `class Chunk { // TODO }`：Phase 3a 无限世界分块占位 |

### OccupancyMap API

| 方法 | 语义 |
|---|---|
| `isOccupied(gx, gy)` / `getOccupant(gx, gy)` | 查询单格；value 为 definitionId |
| `occupy(gx, gy, defId)` | 占格（已占用则覆盖，调用方应先 canPlace） |
| `release(gx, gy)` | 释放（幂等） |
| `canPlace(gx, gy, w, h)` | footprint 左上角语义；先整体判边界（右下角在界内），再逐格查占用 |
| `occupyFootprint(gx, gy, def, direction)` | 按 `effectiveFootprint(def.footprint, direction)` 取有效占地整片占用；**方向影响占地**（90°/270° 宽高互换） |
| `releaseFootprint(gx, gy, def, direction)` | 对称释放，方向必须与放置时一致；幂等 |
| `snapshot()` | `{gx, gy, defId}[]`，验收"占位无泄漏"用 |

Phase 3a 演进注释：届时改为按 Chunk 存储，`occupy/isOccupied/canPlace/release` 对外接口不变。

对建筑 = footprint 左上角；对传送带段 = 该格左上角（`gx × CELL_SIZE`）。

### 6.2 BuildingComp（`BuildingComp.ts`，119 行）——已放置设备

类型：

- `Direction = 0 | 90 | 180 | 270`（世界相对；0°右 / 90°下 / 180°左 / 270°上）。
- `MachineState = 'idle' | 'working' | 'blocked'`（`no_power` 为 Phase 3+ 预留）。
- `LogoVisualState = 'normal' | 'paused' | 'blocked'`；`resolveLogoState(paused, state)`：**paused 优先于 blocked**（玩家主动操作优先于被动暂缓）。
- `BufferSlot { itemId: string | null; count: number }`：输入槽 `itemId === null` = 空/未锁定，非 null = **锁定该类型**（只进同类），count 降 0 解锁；输出槽一槽一物。容量上限 = `BuildingDefinition.bufferCapacity`（默认 50）。

字段全表：

| 字段 | 类型 | 初值 | 用途 |
|---|---|---|---|
| `definitionId` | `string` | 必填 | 对应 `BuildingDefinition.id` |
| `direction` | `Direction` | 放置时写入 | 世界朝向（落盘后不变） |
| `state` | `MachineState` | `'idle'` | 生产状态机（MachineSystem 迁移） |
| `paused` | `boolean` | `false` | 玩家手动暂停：生产/物流视同离线；**已预约(entering)物品仍放行** |
| `bufferInput` | `BufferSlot[]` | `createBufferSlots(def.inputSlotCount)` | 输入缓冲 |
| `bufferOutput` | `BufferSlot[]` | `createBufferSlots(def.outputSlotCount)` | 输出缓冲（液体产物不占槽） |
| `currentRecipeId` | `string \| null` | `null` | 当前配方（单设备单计时器） |
| `progress` / `elapsed` | `number` | 0 | 0~1 与已耗 ms |
| `inputPollIndex` | `number` | 0 | 输入轮询指针（在先到排名序中前进，满载冻结不重置） |
| `inputArrivalRank?` | `number[]` | 懒初始化 | 每输入口**首次**有物品到门口的 simTick 戳记（一次性；`Infinity`=未到货）。轮询走访序 = 升序（先到先得） |
| `outputPollQueue` | `number[]` | `createOutputPollQueue(def)` | 活跃输出端口轮询队列：出货成功移队尾、失败移出队列、恢复探测**追加队尾不插队**。堵塞集 = 全部端口 − 队列（派生值，不落盘 DD-012） |

### 6.3 BeltSegmentComp（`BeltSegmentComp.ts`，80 行）——传送带段（1 段 = 1 Entity = 1×1 Cell）

**BeltItem**（段内队列元素，物品不是独立实体）：

| 字段 | 语义 |
|---|---|
| `itemId` | 对应 items 图集 textureKey |
| `progress` | 段内归一化位置 0→1；每 Tick +0.025（0.5 格/秒）。**端口扩展区间 [-0.5, 1.5]**：设备输出注入从 -0.5 出发；预约进设备的物品推进到 1.5 后移除；断头/门口停走钳制在 0.5（格中心） |
| `delta` | 本 Tick 的 progress 增量（**渲染帧间插值用**；停走=0 不插值） |
| `entering?` | 端口预约标记：已在门口(0.5)通过 `tryAcceptItem` 预约（输入槽已 +1），放行推进到 1.5 由 MachineSystem 移除 |

**BeltSegmentComp** 字段全表：

| 字段 | 语义 |
|---|---|
| `chainId` | 同一次创建/延长的段共享（链的拓扑锚点之一） |
| `direction` | 直段 = 本段流向；转角段 = **出口方向** |
| `isCorner` / `entryDir?` / `mirrorH?` | 转角判定与渲染参数（CCW 转弯需水平镜像），由 `BeltPathGeometry` 落盘时计算 |
| `isTail` | 链末端（可继续延长）；也是"物品停在设备门口"的观察点 |
| `incomingDirection?` | 仅链首格：链首继承的进入方向（源端设备输出端口反向 / 断头段方向） |
| `segmentIndex` | 链内序号（0=链首），指针渲染/选中区间/断链重拆用 |
| `phaseOffset` | 落盘时随机 0~1，指针相位偏移（避免不同链同步流动） |
| `items` | `BeltItem[]` 本段物品队列（一格一物品约束下通常 ≤1） |
| `blocked?` | BeltSystem 每 Tick 重算的链级堵塞标记（渲染染红依据） |
