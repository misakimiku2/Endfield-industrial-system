## 一、问题时间线（用户报告 → 诊断 → 措施 → 结果）

### R0. 输出端口逻辑重定（会话起点，用户需求）
- 需求：输出按**传送带创建顺序**轮询；单带 1-1-1、两带各 1-0-1、三带各 1-0-0；
  动态接入 B 时 A 先出完密集段再转 A-B 交替（用户给了精确快照串）。
- 现状：旧版按端口定义序轮询、每端口每 Tick 1 件（多带=多倍吞吐）、同端口多带饿死、
  残留 beltPhase 相位闸门。
- **实施 T2.21**：`BuildingComp.outputPollQueue` 改存**接收传送带 handle**（创建序）；
  `pollOutputBelt`/`syncOutputBeltQueue`/`collectReceiverBelts` 纯函数；设备级节拍
  `outputNextEmitTick`（40 Tick）；移除 beltPhase 闸门。
- 结果：✅ 用户示例快照串逐字符复现（16/16 纯函数 + t210 39/39 + t27 43/43）。

### R1. 指针闪烁位移（用户实测：延长 B 传送带后 A、B 指针闪烁，队列似停顿/微退）
- 诊断：v11 指针相位（锁队首 + 空链哈希时钟）两处不连续——①模式切换（清空跳哈希、
  注入跳回）②领头插值外推在停走 Tick 边界回跳 ~0.025 格。
- **实施 T2.22**：渲染侧 `PointerPhaseClock`——每链连续相位载体 virt（跟随领头内插
  位移、空带无缝续流、注入不跳变 + ≤10% 带速微漂移收敛）。
- 结果：❌ 用户实测"空带越长箭头越快"。

### R2. 空带箭头速度随链长加快（用户实测）
- 诊断：**相位载体的推进被写进按段循环**——N 段链每帧推进 N 次 = 箭头 N 倍速。
  诊断脚本未抓到的原因：跳变容差 +0.03 太松，N=2~3 的倍速增量藏在容差内。
- **实施 T2.22a**：推进与取相位拆开，每链每帧恰好推进一次；诊断容差收紧到
  `sampleFlow×1.15+0.002`（合法上界），新增 S6 链长无关性断言。
- 结果：✅ 速度正确，但用户实测仍闪烁（现象变了）。

### R3. 队列前方箭头闪烁 + 物品格冒出指针 + 弯折带指针错位（用户实测，附截图）
- 诊断：T2.22 的"保持原位 + ≤10% 微漂移收敛"——漂移收敛任意偏移需数百帧（等效永不
  收敛），箭头相位与物品槽位周期**永久错开** → 箭头在物品旁边/格中央凭空出现消失。
- **实施 T2.22b**：放弃 hold+漂移，改为**逐帧硬锁领头内插位置**（保留停走零回跳的
  内插修复），空链从最后领头位置续流。
- 结果：⚠️ 用户实测仍闪烁（见 R4），**要求撤销到本轮** —— 但注意：撤销发生在 T2.23
  之后，最终停留状态 = T2.22b。

### R4. 撤销 T2.23，回到 T2.22b（用户指示"问题更多了，先撤销回上一轮修改"）
- 见下文"三、已撤销的 T2.23"。
- 结果：✅ 全量 node 验证恢复 T2.22b 数值（t210 39 / t27 43 / t212 53 / 纯函数 16 /
  诊断 0 非法跳变），tsc 干净。**注意：R3 报告的症状（箭头与物品错开、吸收时跳变）
  在 T2.22b 状态下依然存在**——这是用户知情的取舍。

## 三、已撤销的 T2.23（槽位时钟与出货对齐）

**动机**：R3 诊断确认——领头条件在**物品间距为整数格**时精确（全链共享格内相位），
T2.21 轮询发货产生非整数间距（截图实测 4.7/1.7 格）→ 箭头与物品错开随机量 + 吸收换
位跳 (间距 mod 1)。方案：让物品天生落在槽位网格上。

**实现过的内容（已全部撤销）**：
- `BeltSlotClock.ts`：仿真侧每链槽位相位（有物=队首 total mod 1；空链=带速自流；
  全局相位播种同步各链边界）；BeltSystem 末尾收集快照推进。
- 出货门控 `atHeadBoundary`：仅链首槽位边界 Tick 注入（MachineSystem/DepotOps），
  间距恒为整数格 → 指针锁永不跳变、箭头永远对齐（诊断 0 跳变，S7 精确对齐通过）。
- `pollOutputBelt` 三态（accept/skip/**wait**——wait 防止队首带饿死）。
- 浮点容差：吸收/释放判定 `±1e-6`（0.475+0.025=1.4999… 下欺导致门口滞留 1 Tick、
  后车多流 0.025 压缩间距 → 队首切换相位跳 +0.05）。
- 渲染器改读仿真时钟（单一事实来源），删除渲染侧时钟。

**撤销原因**：用户实测"问题更多了"。事后复盘的可疑点（未经验证，仅记录）：
1. 门控改变了发货节奏的手感（首件延迟 ≤40 Tick、边界等待期设备输出被暂缓）；
2. 'wait' 语义让轮询队首带阻塞后续带的服务，异常场景（停走链 skip、链间衔接）行为
   组合复杂，未经浏览器级实测就交付；
3. 改动面过大（时钟+门控+三态+容差一次上线），缺乏中间可回退点。

**若未来重拾此方向的注意点**：
- 吸收/释放浮点容差（±1e-6）是**独立、低风险**的修复，值得单独重做并单独验证；
- 门控的"未知链放行、已见链等边界"语义已在 t212 5a 验证过，可复用；
- `Array.from(iterator)` 预消费迭代器会静默清空后续 for-of（本回合 instrumentation
  事故，30 分钟排查）——诊断/插桩不得改变被测代码的迭代器消费。

## 四、当前状态下的已知遗留（T2.22b 语义的固有残差）

1. **箭头与物品不保证精确对齐**：物品间距非整数格（轮询节奏不均）时，箭头网格与各
   物品错开最多 ±0.5 格，微漂移以 ≤10% 带速缓慢收敛（实测收敛很慢，接近不收敛）。
   表现：箭头可能出现在物品紧邻位置（截图现象）。
2. **吸收瞬间的小幅网格移位**：队首被吸收时锁定切换，回退量 = 间距 (mod 1)，非整数
   间距时全链箭头跳 0~0.05 格（≈2.4px，每次吸收一次，即每 2 秒）。
3. 跨链衔接（A 链尾流入 B 链头）物品不对齐 B 链网格（瞬态）。
4. 调试钩子直接 push 的物品不在网格上（非玩家路径）。

上述 1/2 的根治方向即被撤销的 T2.23（间距整数化），见"三"。

## 五、通用教训

- **相位锚与速度锚必须同源**：相位取队首、速度取"任意物品最大位移"时，队首冻结而
  后方压缩的场景会每 Tick 回弹抖动。
- **帧增量断言的容差必须贴物理上界**：宽松容差（+0.03）会把"速度错了 N 倍"漏判成
  "无跳变"，给出虚假绿色。
- **渲染侧不要持有与仿真平行的时钟状态**：双时钟必然漂移；T2.23 的"仿真侧单一事实
  来源"方向正确，撤销的只是当时的门控交付方式。
- **浮点固定步长累加的边界判定必须带容差**：0.475+0.025 < 1.5（下欺 2e-16）这类
  门口滞留会引发连锁的间距压缩与相位跳变。
- **回归脚本也是代码**：三轮修复中测试脚本自身出过 4 类问题（ITEM/辅助函数被误删、
  跨 alpha 采样假阳性、S6 测量窗口混叠、CRLF 匹配失败），改断言前先跑基线。
