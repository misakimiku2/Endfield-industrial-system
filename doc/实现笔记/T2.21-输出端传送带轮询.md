# T2.21 — 输出端传送带轮询 · 实现笔记

> 任务卡: 用户 2026-09-05 需求（输出端重定语义）｜ 状态: 2026-09-05 完成 ✅
> 修订 A8 production-system-spec.md §4.2（输出轮询）、T2.7（输出对接节流）、T2.10（输出队列轮转）的输出侧语义。

## 需求（用户原话归纳）

生产设备输出端连接传送带后自动出货，输出数量为 0 时停止；输出轮询按**传送带创建顺序**
（此前按端口定义序，且同端口多带会饿死）：

| 接带数 | 各带物品模式（1=物品 0=空格，沿带流向） |
|---|---|
| 1 条 A | A: 1-1-1-1-1（密集） |
| 2 条 A,B | A: 1-0-1-0… / B: 0-1-0-1… |
| 3 条 A,B,C | 各 1-0-0… |
| 动态接入 | A 独跑中在另一端口接 B → 自动 A-B 轮询。快照: A: 0-1-0-1-0-1**\|**1-1-1-1-1（右段=接入前密集输出），B: 1-0-1-0-1-0**\|**0-0-0-0-0（右段=物品未到的空带） |

三组模式的共同推论 = **总输出速率恒为 1 件/40 Tick（=一格传送带时长），多带只分摊不提速**
（用户 2026-09-05 确认）；满带跳过语义沿用 §4.2（轮到的带满了→给下一条空带；用户确认）。

## 语义变更（旧 → 新）

| 维度 | T2.10/T2.7 旧 | T2.21 新 |
|---|---|---|
| 轮询单元 | 输出端口下标（定义序 左→中→右） | **接收传送带 handle**（chainId 创建序） |
| 同端口多带 | 固定方向序 [0°,90°,180°,270°] 取第一条，其余饿死 | 全部进入设备级轮询 |
| 节流 | 每端口每 Tick ≤1 件 + beltPhase ≤ STOP_MAX 相位窗口 | **设备级**: 每 40 Tick 至多成功 1 件（`outputNextEmitTick` 计时器） |
| 相位窗口 | 闸门残留在 emitBeltOutputs（与注释"已退役"矛盾、与仓库口路径不对称） | 移除（节拍由计时器承担） |
| 堵塞 | 堵塞移出队列 + 每 Tick 下标序探测 + 恢复追加队尾 | 语义等价实现: 失败移出 → 下一 Tick 队列同步按创建序重新追加队尾 |

## 实现

- **OutputOps（纯逻辑，DD-011 先例）** 新增:
  - `beltCreationKey(seg)`: 解析 chainId `"chain-${Date.now()}-${序号}"` → `[时间戳, 序号, segmentIndex]`
    元组（链创建后 chainId 永不改写，是稳定键；main.ts 演示随机后缀同样可解析）。
    **几何事实**: 接收段的入口侧是端口格（被设备占据，链不可能穿过设备）→ 接收段必为
    链首 segmentIndex 0 → "传送带创建顺序"="链创建顺序"，segmentIndex 仅作确定性防御。
  - `collectReceiverBelts(world, beltAt, cells)`: 全部输出端口 4 邻格收集"入口背离设备"的段，
    跨端口/方向按 handle 去重（先到端口记 portIndex，事件文案用），返回创建序升序。
  - `syncOutputBeltQueue(queue, candidates)` 纯函数: 失效 handle 过滤 + 新带按创建序追加队尾。
  - `pollOutputBelt(queue, candidates, canAccept)` 纯函数: 同步后从队头走访最多一轮，首条可写带
    选定并移队尾；不可写带移出（本 Tick 不回队）。节拍计时器由 MachineSystem 管理。
- **MachineSystem.emitBeltOutputs 重写**: 早退（空输出槽零维护）→ 候选发现+队列同步 →
  节拍闸门（`simTick < outputNextEmitTick` 只同步不出货——等待期新接入的带也要登记）→
  `pollOutputBelt` 选带 → `tryEmitToBelt`（注入段首 progress=0 不变）→ 成功后
  `outputNextEmitTick = simTick + 40`；无可写带不重置节拍（带腾位即恢复）。
  `OUTPUT_EMIT_INTERVAL_TICKS = Math.round(1/ITEM_PROGRESS_PER_TICK) = 40`（BeltSystem 导出常量）。
- **BuildingComp**: `outputPollQueue: number[]` 语义改为"按轮询序的活跃接收带 handle"（放置时
  初始化 `[]`，首件出货时按创建序发现填入；项目无存档系统，零迁移成本）；新增可选
  `outputNextEmitTick?: number`。`createOutputPollQueue` 删除（`outputPortCount` 保留）。
- **事件/调试**: `ProductionEvent.portIndex`（output）= 发现该带的端口下标（首占端口）；
  `portStatus()` 输出轮询队列行改为"带#N"（全场创建序排名，`compareBeltCreation` 排序），
  供"按创建顺序轮询"肉眼校验。
- **一键测试 t210 场景B/C 适配**: 场景B 断言不变（带创建序=端口序，轮转 1→2→3 每 2s 一件，
  节拍语义反而更干净）；场景C 步骤8 重置队列改为带 handle（`beltHandleAtCell`）+ 计时器清零，
  预期序 左→右→中 不变（中带由队列同步重新追加队尾）。

## 设计要点备忘

- **为什么是"出队-成功-队尾"而不是"从上次出过的带之后走"**: 动态接入示例的相位要求
  "B 接入后下一件仍先给 A"——队头是"等待最久的带"，A 独跑时 A 的轮次永远 pending，
  B 追加后 A 仍在队首 ✓（test-output-polling ③ 快照逐字符验证）。
- **为什么需要设备级计时器而不是"目标带腾位即出"**: 2 条带时 B 全空，若只看目标带可写
  会在 A 出货后 1 Tick 就给 B（两带全密集 1-1-1），而非 1-0-1-0 分摊。计时器保证相邻成功
  出货间隔 ≥ 40 Tick = 单带吞吐上限。
- **队列同步在节拍闸门之前**: 等待节拍的 Tick 里新接入的带也要登记进轮询序，否则接入
  后首件会晚一个节拍才看到新带。
- **堵塞语义等价性**: 旧"移出+探测+恢复追加"与新"移出+下 Tick 同步按创建序追加"在
  效果上一致（恢复的带排在队尾等待轮转），且不需要独立的堵塞集状态（派生 = 候选 − 队列）。
