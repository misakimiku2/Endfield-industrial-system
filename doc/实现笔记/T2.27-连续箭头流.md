## 根因（视频逐帧 + 日志差分定位）

**旧模型"每格一枚精灵、相位 = (virt − segIdx) mod 1"在每个整点回卷**——全体箭头
同时向下瞬移 ~1 格（0.975 格 ≈ 47px）。满载带上回卷点被物品盖住（无缝，这也是
v11 以来一直没暴露的原因）；**T2.21 稀疏出货后，物品之间空格的箭头回卷裸露**:

- 1.mp4（新建带首件骑行）: 物品前方一格的箭头随领队相位爬到格顶，物品跨格进入
  该格瞬间箭头"隐身"（该格有物品）——60fps 帧列可见箭头在物品跨格帧消失。
- 2.mp4（连接两条带后）: 物品尾部 0.975 相位处的箭头贴着物品后缘，随回卷消失/
  重现——读作"物品分裂/闪烁"。
- 诊断脚本旧检测器对 mod 1 盲视（相位差 (0.975→0.0) mod 1 = 0.025 = 合法帧流动量）
  ——**世界坐标连续性检测器**（新增）才会命中: 旧模型 47 次回卷瞬移。

## 修复: 连续箭头流（旧项目/真 Endfield 的模型）

**箭头不再是"每格一枚、相位取模"，而是链坐标系上的连续等距点列**:
`d_m = virt − m（m ∈ ℤ）∩ 窗口[−0.125, chainLen+0.125]`，随 virt 以带速连续滑动，
滑出链尾/链首即被窗口裁掉、在对端补入（两端被设备 sprite/端点遮挡）——
**链中段任意位置箭头位置帧间连续（Δ = 帧流动量），结构性无回卷、无闪烁**。

- **virt（流动锚）语义不变**: 领队锁定（队列停→箭头停）、空带按带速续流、
  播种 = globalPhase + chainId 哈希（与仿真侧空链注入同源）。
- **积分改回不钳位**: 吸收/换领头的负增量 = 箭头槽位集合 {virt+j} 整体平移恰好
  整数格——集合不变（精灵不可区分）+ 改用 **Tick 总量差**积分（新领头 tick −
  旧领头 tick = 精确整数格）→ **箭头相对物品网格零漂移**（T2.22 时代的 max(0,·)
  钳位在连续流下每次吸收丢失一份帧流动量，900 Tick 漂移 0.13 格——已实测复现并消除）。
- **换领头校准**: 负增量帧将 virt 分数部分对齐新领头 Tick 位置（校准量 ≈0.016 格
  不可见）——消除新旧领头内插相位差（采样 α 差 × 0.025）的 mod 1 断裂。
- **"有物品隐藏箭头"规则退役**: 指针层移入 layer2Building zIndex 0.4（带身 0 之上、
  物品 belowItems 0.5 之下、设备 1 之下）——箭头从物品/设备下方连续滑过，
  物品吸入/注入的显隐硬切不再存在（这正是 2.mp4"物品上的闪烁"的根源）。
- **空链注入落自流箭头相位**: slotPlacement 空链分支 = frac(beltPhase +
  chainPhaseOf(chainId))（与渲染侧播种同一公式，chainPhaseOf 移交 OutputOps
  单一来源）——空链首件恰好落在自流箭头上，**消除 ▴ 再对齐闪跳**（1.mp4 2-6s）。
  downMin 防御钳对两条分支一致生效（空链分支此前漏钳，已修——注入相位越过
  下游钳位时钳到 downMin，物品停在钳位上、delta=0 静止）。

## 实现结构

- `BeltArrowStream.ts`（新，纯逻辑）: `computeArrowPositions(chainLen, virt)` —
  槽位集合 ∩ 窗口，升序；node 诊断可直接驱动。
- `BeltPointerPhase.ts`: `computeChainVirts()` 替代 `computePhases()`（返回每链
  virt；领队 {interp, tick} 双量；换领头校准）。
- `BeltPointerRenderer.ts` 重写: 每链箭头池（Map<m, ArrowEntry>，按槽位序号键控
  ——键控错误会 reintroduce 索引平移瞬移）；链几何行走（段游标缓存，直段匀速
  线性/转角圆弧，端点扩展 moveRange 移除——它会破坏流的匀速性）；保留堵塞 tint、
  选中白箭头（按段内进度渐变）、延长预览隐藏；per-cell 单元蒙版退役。
- `RenderSystem.ts`: pointerLayer（layer2Building, zIndex 0.4）。

## 补记 T2.27-a — 浏览器复测暴露致命回归：链运行时未持久化（2026-09-06 同日）

用户编译运行后报告: 指针动画消失、箭头糊成一条实心黄带、帧率极低
（几条带 + 一个精炼炉只有 ~48 FPS）。浏览器实测（3 带 + 炉 + 取货口）复现:
FPS 48、`beltPointers` 容器 **147,390 个精灵**（应为 ~36）。

- **根因**: `BeltPointerRenderer.update()` 重写时把每帧分组结果建在**局部**
  `grouped` Map 上（全新空箭头池），但**从未 `this.chains.set(chainId, rt)`
  存回持久字段**——`this.chains` 只剩 delete/clear。于是:
  ① 池同步每帧全量 `createArrow()`（新池恒空 → 恒创建），窗口滑出分支永不命中
  → **每帧泄漏 (链长+1)×2 个精灵、永不回收**（16 段 × ~55fps × 75s ≈ 14.7 万）；
  ② 上一帧的箭头仍挂在层上但无人更新——历史帧箭头以"每帧带速位移"（60fps 下
  ~0.5px）的间距铺满整条带 → **离散箭头视觉上糊成连续实心带**（这正是用户
  看到的"指针被链接成一条线"）;
  ③ 14.7 万子节点每帧被 sortableChildren 容器重排 + 重写位置/tint → 帧率崩塌;
  ④ 渲染帧耗时拉长到跨 1.6 Tick → T2.25 物品跳动检测器每帧命中 → 日志刷屏
  （运行日志 570 行 ❗ 物品跳动，帧增量 0.04 > 合法 0.025）。**四个症状同源。**
- **修复（一行语义）**: 分组循环改从 `this.chains` 取运行时、缺失才新建并立即
  `set` 存回；`rt.segs` 每帧清空重填（段列表逐帧刷新），箭头池/blockedBlend
  跨帧存活。附带修正: blocked tint 渐变此前因运行时每帧重建被永久卡在 0。
- **教训**: "每帧重建的局部分组" 与 "跨帧池化字段" 必须是同一批对象——池化
  结构只 delete 不 set 等于没有池；node 侧纯逻辑回归（箭头池逻辑独立测试）
  测不到渲染器装配层的这种装配性丢失，浏览器复测不可省。
- **验证（浏览器实测）**: 精灵数 147,390 → 56（三条链 (13+5+11)×2，精确吻合、
  稳定不涨）；FPS 48 → 144；箭头恢复离散"三角+圆点"、随带速连续流动
  （0.8s 帧对位移 ~0.4 格，无回跳）；物品与箭头同格对齐（T2.24 语义）；
 堵塞带红显 + 箭头停走语义正常。tsc 干净；test-output-polling / t210 39 /
  t27 43 / diagnose-pointer-flicker S1~S10 全绿（89 次瞬移为文内已知 v1 残留）。

## 补记 T2.27-b — 修复引入的次生回归：段列表被逐实体清空（2026-09-06 同日）

T2.27-a 修复后用户复测新症状: **L/U 形弯折带上箭头不跟随弯转**，而是沿弯前
方向排成一条直线穿出到空地（直带完全正常——所以首轮直带验证没暴露）。

- **根因**: T2.27-a 把链运行时改为 `this.chains` 持久复用后，`rt.segs.length = 0`
  仍留在**逐实体**循环体内——rt 跨帧共享，处理第 2 个段实体时把第 1 个刚 push
  的段清掉 → 每帧结束时 `rt.segs` 只剩链的**最后一个段**。segmentAt 把全部箭头
  映射到末段、沿末段方向匀速延伸（progress = d − 末段idx 可为任意大/负）→
  箭头排成穿过末段中心的直线；直带恰好与真实路径重合（视觉无误、潜伏），
  **首个弯折处即穿出带外**。chainLen = max(idx)+1 不受影响 → 箭头数量正确、
  只有位置错——症状"指针动画消失/连成一条线"。
- **定位方法**: 临时把 `{virt, chainLen, segs, pool}` 挂 `__ptrDbg` 供浏览器读取
  ——`rt.segs` 只剩 1 条而 chainLen=21，一眼定位。真实拖拽链（E 模式合成
  pointer 事件驱动）复现；验证段数据 idx 连续、转角数据正常，排除创建系统。
- **修复**: `rt.segs.length = 0` 提到逐实体循环**外**（每帧对全部已知链先清一次，
  循环内只 push）。
- **验证（真实拖拽 U 形链，21 段）**: 可见箭头 21 支**全部**落在带身格上
  （带外 0 支，程序化逐格比对）；弯折处箭头沿圆弧跟随；FPS 144；
  tsc 干净 + test-output-polling / t210 39 / t27 43 / diagnose 全绿。
- **教训**: 把"每帧局部对象"改成"跨帧持久对象"时，原初始化代码（清空/重置）
  的**执行频率语义**会跟着变——循环内清空 = 每实体清空，必须逐处重审。
  直带验证对箭头映射是盲的（任何单方向映射都通过），**弯折链必须进验收**。

## 补记 T2.27-c — 端口出现感 + 一格一物品 + 端点淡出（2026-09-07，用户实测三连）

用户复测三点: ①物品不从输出端口中出现、中途刷新在前面一格；②指针与物品同格
（"传送带和物品在同一格只能出现一个"——A9 §5.2.2 重申）；③带尾箭头穿出带身。

- **①空链注入回归段首 0**（OutputOps.slotPlacement 空链分支）: T2.27 的"落在
  自流箭头相位"让物品中途凭空刷新。回归 T2.6 原语义（段首 0 立即注入，物品
  从端口边缘滑出、进入侧半格被设备 sprite 覆盖）。**曾实现"等自流相位走到带首
  再注入（≤40 Tick）"，回归 t210 11 败**——相位等待拖慢设备出货节奏（最长压
  2s/件），破坏 T2.10 用户拍板的节拍语义 → 放弃等待、立即注入。
- **②同格互斥（渲染）**: 物品所在格的箭头隐藏，**按格 floor(d) 判定**——
  首版用 |d−t|<0.5 距离判定在链首泄漏（首格物品 progress 0~0.37 时同格箭头
  距离可 >0.5 漏藏，S7 检查暴露）。按格后切换发生在换格边界、不可见。
- **③端点淡出**: 窗口余量箭头（±0.125）在死端侧淡出（尾: 1 @ d ≤ len−0.375 →
  0 @ d ≥ len−0.125；头对称），端点外邻格有设备/带时不淡出（从设备下方滑过）。
  外邻占用用世界查询等价判定（渲染器不持有 OccupancyMap）。
- **相位解耦（本补记的核心设计转变）**: 同格互斥成立后，**箭头与物品的相位
  对齐不再必要**——箭头只跟随领头的**速度**（停走同步，v11 语义保留），
  恒定相位差被同格隐藏完全遮蔽。因此删除 PointerPhaseClock 的"空链首件
  校准"（`virt = leader.tick + round(...)`）——它就是 T2.21~T2.26 时代 ▴
  再对齐闪跳的根源；slotPlacement 的自流相位注入（T2.27）随之失去意义。
  T2.24 非空链网格注入**保留**（保证物品间恒整数间距，S10 间距恒 1.0 依旧
  全绿——它防的是物品间重叠，不是箭头对齐）。
- **诊断脚本口径更新**（diagnose-pointer-flicker）: 旧 ②"物品与箭头 mod1 对齐"
  断言废弃 → 改"一格一箭头"（每带身格 ≤1 支，捕获窗口/池化缺陷）；新增跨段
  重建帧跳过（领队跨段对象重建 + T2.26 落点余量 → 渲染时钟内插基线单帧
  +0.025 断裂，1.6px、每 2s 一次——T2.26 时代潜伏的身份交换类误报，与吸收帧
  同 philosophy 跳过）。S1~S10 全绿、累计 0。
- **回归**: tsc 干净；test-output-polling / t210 39 / t27 43 / t212 53 /
  t23 40 全绿；verify-intake-cadence 3/5 与 verify-belt-blocked 18/20 的失败
  **经 git stash 基线对照确认与本次改动无关**（HEAD 同样失败，且不在上轮
  验证清单）。浏览器实测: 物品格零箭头外露（含首格）、死端带两端无穿出、
  弯折跟随、FPS 144~145。
- **教训**: ①"对齐"从来只是手段，用户要的是"格内二选一"的视觉规则——互斥
  隐藏比相位锁定便宜且无闪跳，架构反转后一串补偿机制（自流相位注入、首件
  校准）整体退役；②节拍/吞吐语义是用户拍板的验收红线，任何"等一下"的设计
  都必须先过 t210 的节拍断言。
