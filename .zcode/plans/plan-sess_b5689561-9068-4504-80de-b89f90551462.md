## 对比分析结论

参考旧 Flutter 项目（`C:\Users\Misaki\Desktop\git\Endfield\lib\canvas\canvas_editor.dart`）后，找到了"对味"的关键。旧项目 `_handleScroll` + `_onTick` 的算法与我现在实现有三个本质差异：

| 维度 | 旧 Flutter（对味） | 我当前（不对味） |
|---|---|---|
| **滚轮力度** | `targetScale × (1 - scrollDelta/200)` —— 用 deltaY **线性比例**，滚得快=缩放快，触控板丝滑 | 固定 `direction ±1`，**丢弃 deltaY 大小**，每次机械 ×1.25 |
| **目标更新** | target 累乘 + display 持续追（不重置） | 即时位移 + 速度衰减 |
| **动画方式** | display 向 target 每帧 lerp（指数趋近，连滚不冻结） | 速度惯性 |

**最根本问题是 #1**：我把 WheelEvent.deltaY 简化成 `±1`，丢失了"滚多快=缩多快"的连贯感，触控板体验尤其差。旧项目用 deltaY 线性比例是地图类应用的标准做法。

## 新方案：移植旧 Flutter 的 target lerp 模型

**display 向 target 指数趋近**（帧率无关版），target 由滚轮的 deltaY 累乘。已端到端数值验证：
- 连滚5次：target 持续累乘（1.5→4），display 平滑追赶，**滚时画面就在动不冻结** ✓
- 停手：display 指数追上 target，无猛冲 ✓
- 锚点漂移 0 ✓
- deltaY 线性比例：触控板丝滑 ✓

### 改动 1：`src/game/render/constants.ts`

删除速度模型参数，换成 target lerp 模型参数：
```ts
/** 删除: CAMERA_ZOOM_WHEEL_LN_STEP, CAMERA_ZOOM_INERTIA_KICK, CAMERA_ZOOM_INERTIA_TAU */

/**
 * 滚轮缩放（target lerp 模型，移植自旧 Flutter 项目）。
 * display 向 target 指数趋近，target 由滚轮 deltaY 累乘。
 */
/** 滚轮缩放: deltaY 归一化分母。newZoom = targetZoom × (1 − deltaY/此值)。
 *  200 = 每格滚轮(|dy|≈100)缩放 ×1.5。值越大单次缩放越温和。 */
export const CAMERA_ZOOM_WHEEL_DELTA_DIVISOR = 200;
/** display 向 target 趋近的时间常数(秒)。越小越跟手；0.08≈80ms衰减到1/e，较快跟手。 */
export const CAMERA_ZOOM_SMOOTH_TAU = 0.08;
/** 锚点屏幕漂移容差，display 与 target 差距小于此值时吸附结束动画。 */
export const CAMERA_ZOOM_SNAP_EPSILON = 0.0005;
```
保留 `CAMERA_ZOOM_WHEEL_STEP`（不再用于缩放，但... 实际会清理，因为 deltaY 比例取代了它）。

### 改动 2：`src/game/render/Camera.ts`

**删除** 速度模型字段 `_zoomVel`，**替换为** target lerp 字段：
```ts
private _targetZoom = CAMERA_ZOOM_DEFAULT;     // 滚轮累乘的目标 zoom
private _zoomAnchor: {x,y} | null = null;       // 滚轮期间固定的世界锚点(无漂移)
```

**`update(deltaMS)`** 替换速度积分为 target lerp：
```ts
if (this._zoomAnchor) {
  // display 向 target 指数趋近(帧率无关): k = 1 - exp(-dt/TAU)
  const k = 1 - Math.exp(-(deltaMS/1000) / CAMERA_ZOOM_SMOOTH_TAU);
  let newZoom = this.zoom + (this._targetZoom - this.zoom) * k;
  newZoom = clamp(newZoom, MIN, MAX);
  this.applyZoomAtAnchor(newZoom);  // 固定锚点反解相机中心
  if (Math.abs(this.zoom - this._targetZoom) < CAMERA_ZOOM_SNAP_EPSILON) {
    this.applyZoomAtAnchor(this._targetZoom);  // 吸附结束
    this._zoomAnchor = null;
  }
}
```

**新增 `zoomByWheel(screenAnchor, deltaY)`**（替代当前的 direction 版本，恢复 deltaY 力度）：
```ts
zoomByWheel(screenAnchor, deltaY): void {
  const oldScale = this._targetZoom;
  const newTarget = clamp(this._targetZoom * (1 - deltaY / CAMERA_ZOOM_WHEEL_DELTA_DIVISOR), MIN, MAX);
  if (Math.abs(newTarget - oldScale) < 0.0001) return;
  // 锚点用当前显示 zoom 求世界坐标(鼠标此刻指向的地方)，连滚时刷新
  this._zoomAnchor = this.screenToWorld(screenAnchor.x, screenAnchor.y);
  this._targetZoom = newTarget;
}
```

**保留** `applyZoomAtAnchor`（已实现，数学不变）、`zoomAt`/`setZoom` 瞬时（verify 脚本依赖）。

**`isZooming`** 改为 `this._zoomAnchor !== null`。

### 改动 3：`src/game/render/CameraController.ts`

onWheel 传 deltaY 而非 direction：
```ts
private onWheel = (e: WheelEvent): void => {
  e.preventDefault();
  this.camera.zoomByWheel({ x: this.mouseX, y: this.mouseY }, e.deltaY);
};
```

### 不改动
- `zoomAt`/`setZoom` 瞬时语义（verify-t1.2/t1.5 依赖）。
- 旋转过渡（独立，不受影响）。
- 锚点数学（与原瞬时 zoomAt 同式 ratio=zoomOld/zoomNew，漂移=0 已验证）。

### 帧率无关性修正（相对旧项目的改进）
旧项目 `lerpFactor=0.2` 是"每帧固定"，60fps 和 144fps 手感不同。我用 `k = 1 - exp(-dt/TAU)` 做帧率无关的指数趋近，等效于"每帧 lerp %"但与帧率无关——这是对旧项目的改进，手感更稳定。

### 验证
- `tsc --noEmit`
- verify-t1.2（13项）/ verify-t1.5（63项）应全过（zoomAt/setZoom 瞬时未变）
- 端到端推演（已做）：连滚不冻结、停手平滑追上、锚点漂移0、deltaY线性比例

### 风险
- 极低。锚点数学不变，zoomAt/setZoom 瞬时不变。
- deltaY 线性比例下，触控板/惯性滚动 deltaY 可能很大（±500），单次缩放幅度大——这正是想要的丝滑感。若太敏感可调大 DELTA_DIVISOR。
- 回退：参数都在 constants.ts 单点调整。
